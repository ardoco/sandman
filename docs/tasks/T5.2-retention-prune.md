# T5.2 Retention: prune skills and scheduled workflow

Milestone M5 · Effort M · Depends on: M2 · Risk: RK-11 (graph growth)

Status: in progress (2026-10-18)

## Context

Every ingestion adds artifact versions, elements, links and runs. Nothing removes them. Stage 1 §4.2 asks for a retention rule and names the prune order. Read first:
- `docs/stage-1-analysis-architecture.md` §4.2 (retention), §8 (schedule workflow)
- `contracts/skills.schema.json` (`PruneTraceLinks*`, `PruneArtifactData*`) and the two Agent Cards (`plannedSkills`)
- `docs/tasks/T1.13-review-follow-ups-semantics.md` (R-006, R-019)

## Goal

A scheduled workflow removes old, unreferenced graph data per project. A dry run shows the counts first. Data that a user, an experiment or an inconsistency refers to stays.

## Scope

1. Skill `prune-trace-links` in the tlr-agent and skill `prune-artifact-data` in the extraction-agent.
2. Additive contract changes, version 0.9.0.
3. Retention config in `config/orchestrator/rules.yaml`, per project, safe defaults.
4. Orchestrator: workflow type `prune` and a periodic scheduler.
5. Unit tests and Memgraph integration tests.
6. A short section in `docs/user/operations.md`.

Out: Artifact node removal for deleted artifacts, blob removal in the artifact store, orphan elements without `HAS_ELEMENT`, ingestions that changed nothing.

## Rules

Each artifact keeps these versions:

| Keep | Reason |
|---|---|
| The newest `keepVersionsPerArtifact` versions (default 20) | Order by the highest `seq` of the activating ingestion. |
| `CURRENT_VERSION` | Always current. |
| Versions with a content hash in `protectedContentHashes` | The orchestrator reads the hashes from `experiments/*/experiment.yaml`. |
| Versions with an element that is an `INVOLVES` target of an inconsistency, or an endpoint of a link that is such a target | Inconsistencies stay explainable. |
| Versions with an element on a link that is not `rejected` and (active or `confirmed`) | A confirmed decision survives. |

Only versions that no rule keeps are removed.

## Skill contract

Both skills take `{projectId, keepVersionsPerArtifact, dryRun, protectedContentHashes?}`. `dryRun` defaults to `true`. The output is `{runId, removedCount, keptCount, dryRun, removed{...}, warnings?}`. `removedCount` is the sum of `removed`.

| Skill | Agent | Deletes |
|---|---|---|
| `prune-trace-links` | tlr-agent | Links (not `explicit-reference`) that are inactive, not `confirmed`, not `INVOLVES` targets and have an endpoint in a removable version. Orphan links without `SOURCE` or `TARGET`. Own `Run` nodes whose facts are all gone. |
| `prune-artifact-data` | extraction-agent | Explicit-reference links, elements and versions of removable versions. Concepts and ingestions left without references. Own `Run` nodes whose facts are all gone, and own prune runs older than 90 days. |

Each skill publishes the event `sandman.retention.pruned` (`projectId`, `scope`, `runId`, `dryRun`, `keepVersionsPerArtifact`, `removedCount`). `scope` is `trace-links` or `artifact-data`.

## Scheduling

- The orchestrator rule: `retention.pruned` with scope `trace-links` creates the step `prune-artifact-data`. The tlr-agent prunes first, the extraction-agent second.
- Manual workflow type `prune`: `POST /v1/workflows` with `{"type": "prune", "projectId": ...}`. It starts with `prune-trace-links`.
- The scheduler checks once per tick. For each project with retention enabled, it starts a `prune` workflow if the last scheduled one is older than `interval`.
- Config (`retention` in `rules.yaml`): `enabled`, `interval`, `keepVersionsPerArtifact`, `dryRun`, `experimentsDir`, `projects.<id>.{enabled,keepVersionsPerArtifact,dryRun}`.

## Safety

- Default config: retention enabled with `dryRun: true`. Nothing is deleted until an operator sets `dryRun: false`.
- A dry run runs the real delete in one transaction and rolls it back. The counts are exact.
- Every query filters by `projectId`. Another project is never read or changed.
- Each service deletes only its own node types (single-writer rule).
- Audit: each call writes a `Run` (`tool = retention`) with policy, counts and `dryRun` in `params`.
- A second run finds nothing to remove.

## Tests

- Unit: the orchestrator rule, the scheduler interval, config validation.
- Memgraph integration (both services): protected versions survive (manifest hash, `INVOLVES`, non-rejected current link), old unreferenced versions go, dry run deletes nothing, another project stays, a second run removes nothing.

## Decisions taken

1. Window by activating `seq`, not by creation time.
2. `dryRun` defaults to `true` (schema default changed; the skills were planned only).
3. Experiment protection travels as content hashes in the input. Services never read `experiments/`.
4. Counts go into `Run.params`. The KG schema stays unchanged.
5. A confirmed inactive link still protects its versions.
6. New event type `sandman.retention.pruned`. The orchestrator marks the step done on this event.
7. Contract version 0.9.0.
