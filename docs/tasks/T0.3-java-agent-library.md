# T0.3 Java agent library (`agent-lib`, `agent-lib-a2a`)

Milestone M0 · Effort M · Depends on: T0.1; `agent-lib-a2a` waits for the Java runtime decision of T0.4 (D-6) · Blocks: T0.6, T0.7

Status: done (2026-10-07). Libraries and tests are on `develop`; the walking-skeleton e2e passes.

## Context

The Java agents (tlr-agent, inconsistency-agent) run on Quarkus because the `a2a-java` server integration is CDI-based — provisionally: T0.4 decides between `a2a-java` on Quarkus and a hand-written JSON-RPC endpoint (ADR-0002 amendment). Java agents call LLMs only inside reused code (LangChain4j in LiSSA/ArDoCo), so this library has no LLM client, record/replay or tool loop (D-3, D-7). They must behave exactly like the Python library (T0.2) at the contract level. Read first:
- `docs/stage-1-analysis-architecture.md` §9 (Java API sketch), §3.3
- `docs/stage-2-contracts-repository.md` §1.2–1.4, §1.7
- `adr/0010-minimal-agent-library.md`, `adr/0002-use-a2a-for-agent-commands.md`
- `contracts/*.schema.json`, `contracts/conformance/vectors.json`, `contracts/agent-cards/*.json`
- `docs/tasks/T0.2-python-agent-library.md` (the module table defines the shared behavior)

## Goal

Implement `libs/java/agent-lib` (plain Java 21, no CDI) and `libs/java/agent-lib-a2a` (Quarkus/CDI glue around `a2a-java`) with behavior identical to the Python library.

## Scope

`agent-lib` (artifact `io.github.ardoco:sandman-agent-lib`, package `edu.kit.kastel.mcse.ardoco.sandman.agent`):
- `Settings` (env + `*_FILE`), `Ids` (`stableId`, `sectionLocalKey`, `sentenceLocalKey`, `fingerprint`, ids; byte-wise UTF-8 sorting, not `String.compareTo`), `Contracts` (networknt validator, schemas loaded from `SANDMAN_CONTRACTS_DIR`, `$id`-based resolution without network), `Jcs` (RFC 8785 via `java-json-canonicalization`, for `configHash`).
- `LlmAccess.forPolicy(settings, llmPolicy)`: base URL (`SANDMAN_LLM_BASE_URL`, the `llm-replay` proxy), the cloud or `-local` key (`SANDMAN_LLM_KEY_FILE` / `SANDMAN_LLM_LOCAL_KEY_FILE`) and routes from `models.yaml`; used by approach/detector adapters to configure LangChain4j.
- `EventPublisher`, `EventConsumer`, `Streams.ensure()` (`jnats` JetStream; same envelope, dedup header, retries).
- `KgClient` (`neo4j-java-driver`, `executeRead`/`executeWrite`), `RunRecorder` (incl. `cleanupStale`).
- `ArtifactStore`, `HttpPluginClient` (detector plugins, `contracts/openapi/plugin-http.yaml`, presenting the plugin's inbound token; A2A variant cut until needed, D-7), `ServiceAuth` (own token from `SANDMAN_SERVICE_TOKEN_FILE`, verification against the hash file `SANDMAN_SERVICE_VERIFY_FILE`, trusted forwarders: `query-service` for `X-Sandman-Actor`, `orchestrator` for `sandman.actor`; `plugin:<id>` callers rejected), JSON logging (Logback/JSON encoder or JBoss logging JSON in Quarkus) with the same fields.
- `testing`: `ConformanceRunner`.

`agent-lib-a2a`:
- `Skill` interface (Stage 1 §9.2; `run` returns `SkillResult` = output + completion event), `SkillContext` (cancellation flag, progress), an `AgentExecutor` implementation that applies the SANDMAN invocation convention (REJECTED/FAILED rules; on valid output publish the completion event with `causationid` = `messageId` of the A2A request, await the ack, then complete with the result artifact; `sandman.error`), serving the Agent Card from a classpath/file path, bearer-token filter.
- `A2aClient` (submit with `returnImmediately`, get, cancel, card) using the `a2a-java` client.

Out: approach/detector SPIs (they live in the agents), service logic.

## Acceptance criteria

- `ConformanceTest` passes the `stableId`, `sectionKey`, `sentenceKey`, `fingerprint`, `eventEnvelope` and `skillInvocation` vectors (same file as Python), the latter served by a test skill in a `@QuarkusTest`.
- Cross-language interop test (in `tests/conformance/`, may be added in T0.11): Python `A2aClient` → Java test agent and Java `A2aClient` → Python test agent both complete a skill call. In this task, at least the Java client ↔ Java server round trip runs; document the cross-language command in the module README.
- Testcontainers tests for KG (read-only transaction rejects writes) and NATS (publish/consume, dedup).
- `mvn -B verify` green incl. Spotless and enforcer (no LangChain4j).
- Record any deviations from the assumed A2A JSON shapes (V-19) in `docs/notes/a2a-java.md`. Implement `agent-lib-a2a` on the runtime chosen in T0.4; if T0.4 chose the fallback, implement the hand-written JSON-RPC endpoint (`SendMessage`, `GetTask`, `CancelTask`, static card) without Quarkus instead.

## Constraints

Java 21, Quarkus 3.x LTS only in `agent-lib-a2a` (if chosen in T0.4). No agent frameworks. Synchronous API on virtual threads.
