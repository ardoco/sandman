# T4.4 Security test suite for the query path

Milestone M4 · Effort S · Depends on: T4.1 (done) · Blocks: M4 exit · Mitigates RK-10, R-032

Status: done (2026-10-17). Finding F-3 stays open (strict xfail tests).

## Context

The query-service is the only place where one project's data can reach a user who may not see it. All strategies (ADR-0018) end in Cypher or in LLM text, so one suite must test them together. Read first:
- `docs/stage-3-implementation-plan.md` (row T4.4, risk RK-10), `docs/stage-4-review.md` (R-032)
- `adr/0009-nl-to-cypher.md` (amendment D-2: parse-tree scope guard), `adr/0018-query-strategies.md`
- `docs/tasks/T0.9-query-service.md` (guard, `Runner`, bypass corpus of T0.9), `docs/tasks/T4.1-nl-to-cypher-strategy.md`, `docs/tasks/T4.3-answer-synthesis-citations.md`
- Code: `services/query-service/src/sandman_query/` (`guard.py`, `query.py`, `reader.py`, `nl.py`, `auth.py`) and the tests `tests/test_guard.py`, `tests/test_memgraph.py`, `tests/test_authz.py`.

## Goal

A versioned bypass corpus and a parametrized test suite that prove one invariant for every strategy: **a caller with access to project A never receives data of project B through the query path.** The suite runs with the scope guard on and with the guard off. With the guard off, the read transaction, the limits and the result post-check must still hold, and every gap is reported as a finding.

## Threats

| ID | Threat | Control under test |
|---|---|---|
| TH-1 | Cross-project read through Cypher constructs: `CALL` and procedures, `UNION`, subqueries (`EXISTS`, `COUNT`, `CALL {}`), pattern comprehensions and predicates, `WITH` rebinding, `UNWIND` | Guard allowlist and anchoring |
| TH-2 | Anchor tricks: label-only anchor, `{id: $projectId}` on a non-Project node, `$projectId` in `WHERE`, literal project id, duplicate map keys, expressions around the parameter | Guard anchoring |
| TH-3 | Parameter tricks: other parameter names, case variants, user-supplied reserved names, `$` forms, `LIMIT $x` | Guard, `RESERVED_PARAMS`, driver binding |
| TH-4 | Obfuscation: comments inside keywords, case, backticks, Unicode homoglyphs, full-width letters, Unicode digits, control characters, no-break space, line separators, `;`-chained statements | Tokenizer; statement rebuilt from tokens |
| TH-5 | Path expansion across projects: unbounded `[*]`, `shortestPath`, Memgraph `*bfs`, `*wShortest`; a writer that breaks the no-cross-project-edge invariant | Anchoring, result post-check |
| TH-6 | Vector or embedding search without a `projectId` filter (`vector_search.search` returns nodes of all projects) | `CALL` is rejected; future `graphrag` must filter by project inside the service |
| TH-7 | Write and admin attempts: `CREATE`, `MERGE`, `SET`, `DELETE`, `LOAD CSV`, `SHOW`, `DROP`, `USE`, `GRANT` and all other Memgraph statements | Guard allowlist; read transaction (checked with the guard off) |
| TH-8 | Resource exhaustion: unbounded paths, cartesian products, huge `range`, huge `LIMIT`, deep nesting, oversized query, endless repair loop of the LLM | Timeout, `QUERY MEMORY LIMIT`, row cap, `MAX_DEPTH`, `MAX_LENGTH`, `maxRepairs` |
| TH-9 | Prompt injection through the question: the question asks the LLM to ignore rules, to use another project, to emit `CALL` or write clauses, to cite foreign ids | Guard on every LLM Cypher; question only in the user message; post-check |
| TH-10 | Prompt injection through KG content (element text, evidence) into the LLM: rows with instructions, `</rows>`, foreign ids | Rows are data; answer cites only ids in the rows (R-032, T4.3) |
| TH-11 | Result leak: rows of other projects in the result, at any depth (node, relationship, map, list, path) | `check_scope` post-check (422, `event=scope_violation`) |
| TH-12 | Error-message leakage: foreign values, database addresses or stack traces in problem responses; LLM errors with internal detail | `Runner` error mapping, generic 503 texts |
| TH-13 | Authorization: a role, token or plugin that has no access to the project; role check must run before strategy availability | `authorize`, strategy dispatch order |
| TH-14 | Console rendering of LLM rationale and plugin evidence: script injection, missing CSP | Autoescape, CSP `default-src 'self'` (existing console tests; Ask page by T4.3) |

## Scope

1. **Corpus** `services/query-service/tests/security/corpus.yaml`, versioned (`version: 1`; bump it and keep ids stable when entries change). Sections: `reject` (queries the guard must refuse, with the expected message), `bounded` (queries the guard accepts that the runtime must bound), `obfuscation` (mutation names), `injection` (questions and KG texts with the Cypher a compliant LLM would emit). Every entry has an `id`, a `threat` (TH-n) and a one-line `why`.
2. **Guard corpus tests** (`test_guard_corpus.py`): every `reject` entry is refused with a `GuardError` and never with another exception. Every entry is refused again after each mutation [upper case, lower case, comment between all tokens, newline for space, leading comment, `;` suffix].
3. **Strategy-parametrized dispatch tests** (`test_query_path.py`): fixture `strategy` over `cypher`, `graphrag`, `explore`. A hostile fake LLM answers every call with an out-of-scope query, a foreign-id citation or an error. A strategy that is not implemented yet is skipped with the reason "strategy X not implemented (T4.5/T4.6)"; the tests start to run when it appears. Fixture `validation` over `on` and `off` (`off` replaces `check` by a pass-through in `query` and `nl`).
   - Hostile Cypher never reaches the reader (`on`), and forged foreign rows never reach the caller (`on` and `off`).
   - Injection fixtures measure the effect on the output: number of reader queries, status code, foreign markers in the body, `cypher` unchanged.
   - Authorization per role before strategy availability; errors without leakage; bounded repairs; budget exhaustion answers 503.
4. **Memgraph test** (`test_memgraph_isolation.py`, Testcontainers, skipped without Docker): two projects with marker values, all `reject` entries and all `bounded` entries run through `/v1/query/cypher` and through `/v1/query/nl` with the hostile LLM. Assert zero foreign markers in every response and no change of the graph. Repeat with the guard off for the post-check cases.
5. **Findings.** A gap that cannot be closed in this task is a `xfail(strict=True)` test with the finding id in the reason. Fixes are small, in `guard.py`, `query.py` or `reader.py`, and come with a test.

Out: new strategies (T4.5, T4.6, T4.7), the Ask page and the synthesis (T4.3; the suite only checks their invariants when they exist), per-project deployments, a Cypher grammar change.

## Acceptance criteria

- `corpus.yaml` has at least [80] guard entries across TH-1 to TH-8 and at least [8] injection entries; ids are unique (a test checks this).
- Guard corpus: all entries refused, also after each mutation; no entry raises a non-`GuardError`.
- Dispatch tests pass for `cypher` with guard on and off; `graphrag` and `explore` are reported as skipped with the reason above.
- Memgraph test: zero foreign markers for every corpus entry and every injection, guard on and off; the graph is unchanged after write attempts.
- With the guard off, node, relationship, map, list and path results that carry a foreign `projectId` (or are a foreign `Project`) give 422 and no marker in the body. Scalar projections cannot be checked and are reported as finding F-3 (`xfail`).
- The findings section of this file lists each finding with severity and status.
- `uv run ruff check`, `ruff format --check`, `uv run pytest services/query-service` green.
