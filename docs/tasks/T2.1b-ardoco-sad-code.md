## Goal

The approach `ardocode` writes ArDoCo SAD↔code links to file `CodeUnit`s. On TeaStore and MediaStore, the link set equals the set of the standalone `Ardocode` runner on the same ACM. Incremental runs give the same current links as one batch run.

## Decisions

1. **ACM source: the tlr-agent calls the plugin skill** `sandman.plugin.code-model` through `A2aClient` (submit, poll, cancel on `ctx.cancelled()` or timeout). Input: `projectId` and `currentArtifacts` = all current `code` versions (`path`, `storagePath` = `ArtifactStore.pathFor(storageUri)`; both services mount the artifact store at `/artifacts`). Both services are on `internal`; no network change. Token: mount the existing inbound secret `plugin_in_code-extractor-ardoco` into `tlr-agent` as a second owner. The token only allows plugin calls, and the plugin only reads `/artifacts`, which the tlr-agent already reads. Rejected: an ACM artifact written by the extraction step (extraction-agent change, new store object, KG pointer, staleness); building the ACM in the tlr-agent (JDT).
2. **Approach** `ardocode`, version `2.1.0+a1`, in module `approach-ardoco` (shares `CorenlpClient`, `SentenceRendering` and the JVM `LOCK` with `ardoco`). `supports` = {architecture-doc → code}, `scopeMode` = `whole-project`, `usesLlm` = false, `paramKeys` empty. A separate id keeps its own Runs, `configHash` and retirement scope. Enable it in `config/tlr/approaches.yaml`.
3. **Orchestrator:** add `{ source: architecture-doc, target: code }` to `kindPairs`, without an `approaches` list (T2.1 deviation: equal inputs keep steps mergeable). Without the pair, a change of code alone never starts `ardocode`.
4. **Mapping:** one `CandidateLink` per distinct (sentence number, compilation unit). Source = sentence `TextUnit` at that line. Target = the `CodeUnit` with kind `file` and `localKey` = decoded path, decoded with the rule of `ElementMapping.pathOf` (Java: decode all; shell: decode directories only). `linkType` = `documents` (as `ardoco`); `confidence` 1.0; no `rationale`. An unknown path or sentence fails the run. Types and methods get no links, because ArDoCo links only files. Package links arrive already expanded to files.
5. **Text:** as `ardoco` (render, hash check, gateway, 1:1 check). A bounded in-JVM cache of annotated `Text` keyed by sha256(rendered text) + provider identity [4 entries] serves both approaches, so a doc version is annotated once per tlr-agent call.
6. **Run:** write the ACM to a temp dir, `new CodeConfiguration(acmFile, ACM_FILE)`, `Ardocode.setUp(...)`, inject `PreprocessingData`, `runWithoutSaving()`, under `LOCK`. One run per doc version; the ACM is fetched once per `recover` call. Delete temp dirs.
7. **configHash:** `environment()` = CoreNLP provider identity + plugin `name` and `version` from its Agent Card. The ACM hash does not enter it: the ACM is a function of the current code versions (in `Run` USED) and the plugin version, and `environment()` runs before the input is known. Log the ACM sha256 and size on every run.
8. **Failures:** plugin unreachable, `DEPENDENCY_UNAVAILABLE` or retryable `INTERNAL` → `ApproachUnavailableException` (skill fails retryable after the other approaches). `INVALID_INPUT` (plugin caps) and an unmappable link → Run failed, not retryable. Plugin timeout `SANDMAN_CODE_MODEL_TIMEOUT` [10m]; URL `SANDMAN_CODE_MODEL_URL` [`http://code-extractor-ardoco:8000`]; token `SANDMAN_CODE_MODEL_TOKEN_FILE`.

## Acceptance criteria

- **Equivalence** (`BenchmarkEquivalenceTest`, profile `benchmark`, provider container on both sides): for TeaStore and MediaStore, the adapter set equals the standalone set as (1-based sentence, decoded path). Standalone: `Ardocode.setUp(rawText, CodeConfiguration(acm, ACM_FILE), {}, outDir)` + `run()`, parsed from its SAD↔code CSV. The adapter gets the same ACM through a fake `CodeModelClient` and a `TlrInput` with one file element per compilation unit.
- **Incremental equals batch** (tlr-agent, Testcontainers, profile `benchmark`, TeaStore): doc v1 (first 30 sentences) + code without the image service; doc v2 (all); full code; code without the image service again; a merged step. After the last step, the current `ardocode` link ids equal a batch run on a fresh KG. After each step, no active `ardocode` link has an endpoint outside the current versions.
- Two runs on the same input give the same link ids, `configHash` and ACM sha256.
- Plugin stopped: the Run fails and the skill fails with `DEPENDENCY_UNAVAILABLE`, `retryable: true`; `ardoco` and `stub-name-match` links are written.
- TEAMMATES in the tlr-agent container (`mem_limit: 5g`): no OOM; the notes record ACM size, plugin call time, peak heap and run time. The plugin call fits its timeout.
- `make e2e` and CI green, e2e < 15 min, `replay-twice` identical. The golden diff contains only `ardocode` Runs and links, plus the Run of the extra manual doc→code step of `stub-name-match` (open question 3); the notes list each changed node.
