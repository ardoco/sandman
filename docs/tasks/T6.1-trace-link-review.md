## Context

Users can triage inconsistencies, but they cannot validate trace links. The contract has the operation `reviewLink` (`POST /v1/links/{linkId}/review` in `contracts/openapi/tlr-agent.yaml`). It is marked `x-sandman-status: planned` and answers 501. Stage 1 §6 and A-11 prepare link review but do not build it.

The paper review asks for this task: the user validates results (paper Fig. 1, p. 489) and feedback goes back into the system (paper §4, challenge 5, p. 490). See `docs/notes/paper-review-3774748.3795871.md` §3.1.

Facts from the code:
- Detectors already ignore rejected links (`KgInput.links` in `detector-ardoco`, and `stub-untraced`). A rejection changes the next detection result without detector changes.
- `PruneTraceLinks` keeps confirmed links. Retention does not delete reviewed links.
- A `TraceLink` id contains the element ids. Element ids belong to one artifact version. If an artifact is unchanged, its version id and element ids stay the same, so the link id and the review stay the same. If an artifact changes, all its elements get new ids, also the unchanged elements. Then the links are new and the review is lost. This task adds the carry-over for this case.

## Goal

A triager confirms or rejects a trace link in the console. The review applies to the element pair. The review survives a new artifact version if both elements are unchanged. A review starts a new detection on the affected artifacts.

## Behavior

### Review request

1. The query-service checks the session role (`triager` or higher, ADR-0013).
2. The query-service checks that the link belongs to `projectId`. If not, it answers 404.
3. The query-service forwards the request with `X-Sandman-Actor` to the tlr-agent.
4. The tlr-agent loads the link. If the link does not exist, it answers 404.
5. If the link is not active, the tlr-agent answers 409. Inactive links belong to old versions.
6. If the link has the approach `explicit-reference`, the tlr-agent answers 409. The extraction-agent owns these links.
7. If `status` is `rejected` and `reason` is empty, the tlr-agent answers 422.
8. The tlr-agent finds all active links with the same source element and the same target element, over all approaches, except `explicit-reference`. This set is the element pair set.
9. In one write transaction, the tlr-agent sets `status`, `reviewedBy`, `reviewedAt`, `reviewReason` and `reviewOrigin = user` on each link of the set.
10. If `status` is `candidate`, the tlr-agent removes the review properties. This is the reset.
11. After the commit, the tlr-agent publishes `sandman.tracelink.reviewed`.
12. The response lists the changed link ids.

### Carry-over at activation

Put the carry-over into one shared method of `LinkStore`. Call it from `finish` and from `finishWholeProject`, inside the same transaction, after the activation.

For each link that the run activates:
1. Find the source element and the target element.
2. Find earlier reviewed links (`reviewedAt` is set) with the same `projectId`, the same `linkType`, a source element with the same `key` and `contentHash`, and a target element with the same `key` and `contentHash`.
3. If such links exist, take the one with the latest `reviewedAt`.
4. Copy `status`, `reviewedBy`, `reviewedAt` and `reviewReason`. Set `reviewOrigin = carried-over`.
5. If an endpoint `contentHash` differs, copy nothing. The link stays `candidate`.

The carry-over does not depend on the approach. A review of one approach carries over to links of all approaches for the same element pair. This matches the review per element pair.

### Orchestrator rule

Add a rule to `rules.py`:
- Trigger: `sandman.tracelink.reviewed`.
- Step: `detect-inconsistencies` for the artifacts of `sourceVersionIds` and `targetVersionIds`.
- The normal debounce (`debounceSeconds`, 10 s) merges many reviews into one step.

### Console Links page

Add a page `links.html` to the query-service console. Use the style of `inconsistencies.html`.
- Filters: artifact, approach, status, minimum confidence.
- One row per element pair: source excerpt, target excerpt, approaches, highest confidence, number of approaches that agree, status, reviewer.
- A detail view shows the rationale of each approach. Escape rationale text (R-032, T4.4).
- Buttons: Confirm, Reject, Reset. Reject requires a reason.
- Viewers see the page without buttons.

## Decisions taken

| Id | Question | Decision |
|---|---|---|
| D-1 | Review one link or the element pair? | Element pair (PR-D4). Users judge a relation between two elements, not one approach output. |
| D-2 | Carry-over rule | Same key, same `contentHash` on both ends, same `linkType` (PR-D5). |
| D-3 | Review `explicit-reference` links? | No. Answer 409. Users change the reference text in the artifact instead. |
| D-4 | Reject without reason? | No. Answer 422. Confirm and reset have an optional reason. |
| D-5 | New event or reuse `sandman.tracelinks.updated`? | New event. `TracelinksUpdated` is one event per `recover-trace-links` task and requires `runs`. |
| D-6 | Who checks the project? | The query-service. The tlr-agent trusts only the service token and the actor header. |

## Acceptance criteria

1. Contract PR merged first. Conformance vectors and both libraries are green.
2. Unit tests for the carry-over:
   - same key and hashes: review copied, `reviewOrigin = carried-over`
   - changed `contentHash` on one end: no copy
   - two earlier reviews: the latest wins
   - different `linkType`: no copy
3. Memgraph integration test: review of one link changes all active links of the element pair, across two approaches.
4. Integration test: 404 for a link of another project, 409 for an inactive link, 409 for `explicit-reference`, 422 for reject without reason, 403 for a viewer.
5. End-to-end test: a requirement has one link. A triager rejects it. The next detection creates an OPEN `untraced-requirement` inconsistency.
6. End-to-end test: change one sentence of a document and ingest again. The review of a link of an unchanged sentence survives. The review of the changed sentence does not.
7. The export contains the review columns in the default format and no new columns in the benchmark formats.
8. The replay determinism test (T1.6) stays green.
