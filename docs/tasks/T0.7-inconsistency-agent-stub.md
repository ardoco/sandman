# T0.7 Inconsistency-agent stub (with real lifecycle)

Milestone M0 · Effort L · Depends on: T0.3 · Blocks: T0.11, M3

## Context

The inconsistency-agent (Java, Quarkus) owns `Inconsistency` and `StatusChange` nodes. Only the detector is a stub in M0. Fingerprinting, re-detection, the lifecycle state machine, the triage API and notifications are final behavior from day one, because they define the contract semantics. Read first:
- `docs/stage-1-analysis-architecture.md` §4.3 (lifecycle, re-detection algorithm), §4.4 (transition Cypher), §5.4, §10 (notifications)
- `adr/0007-inconsistency-lifecycle.md`, `adr/0012-pluggable-approaches-and-detectors.md`, `adr/0013-users-and-roles.md`
- `docs/stage-2-contracts-repository.md` §1.5, §1.6 (`config/inconsistency/plugins.yaml`), §4.4
- `contracts/openapi/inconsistency-agent.yaml`, `contracts/agent-cards/inconsistency-agent.json`, `contracts/skills.schema.json` (`DetectInconsistencies*`, `ListDetectorsOutput`, `PluginDetect*`, `Finding`), `contracts/events.schema.json`, `contracts/conformance/vectors.json` (`fingerprint`)

## Goal

`services/inconsistency-agent`: Quarkus app with the A2A skill `detect-inconsistencies`, REST `GET /v1/detectors`, triage endpoints, health, the detector SPI, plugin support (HTTP), the stub detector `stub-untraced`, and the complete lifecycle.

## Scope

1. SPI `InconsistencyDetector { id(); version(); types(); List<Finding> detect(DetectionScope, DetectorContext); }` via `ServiceLoader`; `config/inconsistency/plugins.yaml` enables detectors and registers plugins (`transport: http` implemented; `a2a` rejected at startup until needed, D-7). Detectors read only **active** links (of all approaches, Q-20) with current endpoints.
2. `stub-untraced` (Stage 2 §4.4).
3. Detection run (Stage 1 §4.3, ADR-0007 amendment): resolve scope (`scopeArtifactIds` or all artifacts with a current version); run detectors and plugins (HTTP, plugin inbound token, input incl. `llmPolicy`) and collect `Finding`s (validated); compute fingerprint (type, detector id **without** version, involved keys sorted byte-wise; links as `sourceKey->targetKey`) and id (`inc_` = stableId(projectId, fingerprint)) and `evidenceHash`; apply the re-detection algorithm: artifact-based scope, auto-resolve only for detectors that completed in this run, auto-resolvable states `OPEN`/`REOPENED`/`DEFERRED`/`RESOLVED(pending)`, `artifact-deleted` resolution independent of scope, system transitions conditional on the observed status; write everything plus `StatusChange`s (reasons `re-detected`, `not-redetected`, `artifact-deleted`) in one transaction; log one `notification` event per new/reopened inconsistency; return `SkillResult` with `DetectInconsistenciesOutput` and the `sandman.inconsistencies.updated` event.
4. Lifecycle state machine as a pure class with the allowed user transitions (ADR-0007), the reason requirement (`ACCEPTED`, `REJECTED`, `DEFERRED`), and the system transitions.
5. REST: list with filters, `counts` and `changedSince`; detail with involved elements (artifact path, lines, excerpt), links, history and `allowedTransitions`; `POST …/transitions` with optimistic concurrency (409), 422 for disallowed transitions or a missing reason, 403 if `X-Sandman-Actor` comes from a caller other than `query-service` (callers verified against `SANDMAN_SERVICE_VERIFY_FILE`); publish `sandman.inconsistency.status.changed`.
6. `GET /v1/detectors`.

Out: ArDoCo detectors (M3), A2A plugin transport (until needed).

## Acceptance criteria

- State machine unit tests: every pair (from, to) is tested as allowed or forbidden for user and system actors.
- Scenario test (Testcontainers): detect → two OPEN; user DEFER one; change data so the other is no longer found → `RESOLVED` with `verification=confirmed`; deferred one re-detected → stays `DEFERRED` with a new `lastRunId`; accept one, then change the evidence content hash → `REOPENED`; the detector throws → no auto-resolution of its items and the run is `partial`; a run with `detectors` = another detector leaves the first detector's items untouched; an item whose involved artifacts are partly outside `scopeArtifactIds` is untouched; deleting an involved artifact resolves the item with reason `artifact-deleted` in the next run of any scope; bumping the detector version keeps all fingerprints and statuses; a user transition between the run's read and write wins (system transition skipped).
- Fingerprint and id computation matches `vectors.json`.
- Triage API passes Schemathesis against `contracts/openapi/inconsistency-agent.yaml`; 409/422/403 paths covered; events validate.
- Plugin calls via HTTP are tested with an in-test fake plugin that checks the inbound token; invalid plugin output → detector run `failed`, not a crash.

## Constraints

Java 21, `agent-lib` + `agent-lib-a2a`, no agent frameworks, all Cypher parameterized.
