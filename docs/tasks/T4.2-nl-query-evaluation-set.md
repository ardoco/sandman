# T4.2 NL query evaluation set

Status: tooling and AI-drafted seed set done. Human-written test split open.

## Goal

Measure the NL query service on a fixed set of question items.
The set follows PROTOCOL section 7. Items split by template and by project.
Each item carries a `strategy` label. The labels feed a classifier confusion matrix for `auto`.

## Targets and actual counts

| Target | Value [default] | Actual |
| --- | --- | --- |
| Question-Cypher pairs and content items in total | at least 150 | 181 items, 126 with gold Cypher |
| Content and multi-hop items (`graphrag`, `explore`) | at least 50 | 55 (25 graphrag, 30 explore) |
| Items written by independent human authors (test split) | all test items | 0 |

Warning: The target is not met. Every item is `author: ai-draft`.
PROTOCOL section 7 requires independent human authors for the held-out test set.
The AI-drafted items are dev and seed items only. Do not report them as test results.
The validator keeps `met` false until at least one human-written test item exists.

## Dataset

- File: `experiments/nlquery/dataset.yaml`. Format: YAML with a list `items`.
- Fields, strategy rules and the item template are in `experiments/nlquery/AUTHORING.md`.
- Gold results: `experiments/nlquery/gold-results.json`. The seed KG produces them.
- Dev projects: `mediastore`, `teastore`, `bigbluebutton`. Test projects [default]: `teammates`, `jabref`.
- Test authors write questions without access to prompts or intents.

## Seed KG

`experiments/nlquery/seed_kg.py` builds the KG for five benchmark projects in a Memgraph testcontainer.

- Elements and relations come from the extraction goldens.
- Trace links come from the ArDoCo SAD-SAM results in `experiments/nlquery/seed/`.
- Confidence, link status, inconsistencies, concepts and ingestions are synthetic. Fixed rules generate them.
- The `gold` command checks the scope guard, runs each gold Cypher and rejects empty results.
- The `gold` command checks that gold keys exist and that explore keys equal the reference query.

Caution: Synthetic data limits what the numbers mean. Re-validate the gold Cypher against a real pipeline KG.

## Commands

All commands run from the repository root. They are offline and need no stack, except `classify`.

| Command | Purpose |
| --- | --- |
| `sandman eval nlquery validate --dataset D [--allow-shared-projects]` | Check the format, the split and the counts. Exit code 1 on an error or on leakage. |
| `sandman eval nlquery baseline --dataset D --intents I --out P` | Match each question with the regex intents. Write predictions. |
| `sandman eval nlquery exec --dataset D --gold G --predictions P [--split S]` | Execution accuracy. |
| `sandman eval nlquery retrieval --dataset D --predictions P` | Gold-element recall and precision for `graphrag` and `explore`. |
| `sandman eval nlquery classifier --dataset D --predictions P` | Confusion matrix for `auto`. |
| `sandman eval nlquery classify --dataset D --out P [--split S] [--limit N] [--pause SEC] [--token-file F]` | Post each question to `POST /v1/query/nl` with `strategy: auto` and `execute: false`. Write `{id: classification.strategy}` to P. |

`classify` needs a running stack and the seeded KG (`experiments/nlquery/seed_kg.py`). It uses `$SANDMAN_URL` and `$SANDMAN_TOKEN`.
It sends the project of each item. If a request fails, it writes `null` for the item, prints the reason to stderr and continues.
`null` counts as `none` in `classifier`. The pick of the model is measured, not the threshold fallback.

Baseline run order: `baseline`, then `seed_kg.py run`, then `exec`.

## Metrics

- Execution accuracy: the result of the predicted query equals the gold result as a multiset.
  The comparison ignores row order, column names and column order. It does not truncate and does not use `LIMIT`.
  An error, a truncated result or a missing prediction counts as wrong.
- Validity rate: the share of predictions that run without error.
- Recall and precision: per item, then the macro average, for `graphrag` and `explore`.
- Confusion matrix: gold strategy against predicted strategy. A missing prediction counts as `none`.
- Baseline: the intent stub of `config/query/intents.yaml`. It is the reference for every strategy.

## Split and leakage rules

- A template is the gold Cypher with literals replaced by `?`, white space collapsed and lower case.
- Dev and test items must not share a template.
- Dev and test items must not share a project. Use `--allow-shared-projects` to relax this check.
- A test question must not be a near-duplicate of a dev question. Token Jaccard 0.8 or higher is a duplicate.
- A test item must have `author: human:<id>`.
