# T3.2 ArDoCo Artemis inconsistency detection adapter (`artemis-id`)

Milestone M3 · Effort M · Depends on: T3.1 (done) · Blocks: T3.5 · Extends the module `detector-ardoco` (R-030 package rule of T3.1); implements ADR-0015 L2 and V-29 for the LLM variant

Status: in progress (spec 2026-10-17) · open questions decided 2026-10-17

## Context

ArDoCo has a second inconsistency pipeline, `ArtemisInconsistencyDetection`, on the pinned branch `0d1f22b` (ADR-0015 B1). It finds named components in the text with an LLM (library NAER), links them to model components, and reports the unlinked ones in both directions. T3.1 delivered the non-LLM variant `ardoco-id`. Read first:
- `docs/tasks/T3.1-ardoco-inconsistency-detection.md` (module, text rendering, mapping, lifecycle)
- `adr/0015-ardoco-integration.md` (V-29: Artemis reads its LLM settings from the process environment only)
- `docs/notes/spike-T0.12.md` §2 and §4
- Code: `services/inconsistency-agent/detector-ardoco/`, `libs/java/agent-lib` (`LlmAccess`, `LlmClient`), `libs/java/ardoco-text`

The ArDoCo LLM client has three properties that conflict with the Sandman rules:
- The enum `LargeLanguageModel` reads `OPENAI_API_KEY`, `OLLAMA_*` and a `.env` file from the process. The key is global and not per project.
- It writes a response cache to `.cache-llm/` or `LLM_CACHE_DIR`.
- `ArtemisConnectionInformant` calls `api.openai.com` directly for embeddings with `OPENAI_API_KEY` and has no base URL.

## Goal

The detector `artemis-id` writes Artemis findings to the KG. All LLM traffic goes through the llm-gateway (or llm-replay) with the virtual key of the agent. The agent holds no provider credential. The detector is disabled by default.

## Scope

1. **LLM adapter.** A LangChain4j `ChatModel` that sends each request through `LlmClient.chat(...)`. The key, the base URL and the routes come from `LlmAccess.forPolicy(Settings.fromEnv(), llmPolicy)`. A `local-only` project uses the local key and the `-local` routes.
2. **Custom stages.** `definePipeline` of the runner takes an enum `LargeLanguageModel`. Build the stages from public classes, as T3.1 does:
   - `ArtemisPreprocessing` (simple text provider, model provider with metamodel `ARCHITECTURE_WITH_COMPONENTS`)
   - NER stage: a copy of `ArtemisNerInformant.process()` that builds `NamedEntityRecognizer` with the adapter of item 1
   - connection stage: a subclass of `ComponentArtemisConnectionInformant` that overrides `getModelEndpointEmbeddings` and `getNamedArchitectureEntityEmbeddings` to call `LlmClient.embed(access.embedRoute(), text)`
   - `ArtemisPostprocessing` and `ArtemisInconsistencyChecker` unchanged
3. **Text.** One sentence per line from the KG (T3.1 rendering). NAER rejects lines without a final `.`, `!` or `?`, so the adapter appends `.` to such lines. The hash assertion of T3.1 stays.
4. **Result.** Read `ArtemisInconsistencyStates` from the `DataRepository` (`ArdocoResult` does not expose it). Reuse `IdRunner.extract` and `Mapping` of T3.1.
5. **Detector `artemis-id`.** Version `0.1.0+0d1f22b`. Types `undocumented-model-element` and `missing-model-element`. `usesLlm` = true. `scopeMode` = `WHOLE_PROJECT`. Params: `textKinds`, `modelKinds`. No `linkApproaches` (Artemis does its own linking).
6. **Module rules.** The classes live in the package of T3.1, so the R-030 enforcer and `ModuleRulesTest` need no change.
7. **Config.** Add `artemis-id` with `enabled: false` to `config/inconsistency/plugins.yaml`.
8. **Docs.** Update `docs/plugins.md` and the plan row.

Out: strategies for classes and data files, code models, an upstream change to ArDoCo, e2e replay of the LLM path (the cassette needs a live recording, see decision 3).

## Acceptance criteria

- No class in the Artemis path reads `OPENAI_API_KEY`, `OLLAMA_*` or `.env`, and the run creates no `.cache-llm/` directory.
- A test with a stub gateway (JDK `HttpServer`) shows: chat and embedding requests arrive at the stub with the virtual key as Bearer token and with the routes of `models.yaml`.
- With canned NER answers, the detector reports the expected `undocumented-model-element` and `missing-model-element` findings with correct sentence keys.
- Embedding requests go to the gateway `/embeddings`, not to `api.openai.com`.
- A `local-only` policy uses the local key and the `-local` routes. A missing local key fails the run.
- A gateway error fails the detector. The run is `partial`, and no `artemis-id` item auto-resolves (T0.7).
- Two runs with the same stub answers give the same fingerprints.
- `artemis-id` is listed in `plugins.yaml` with `enabled: false`. The e2e does not change.

## Test plan

Unit (`detector-ardoco`, no live LLM): the NAER occurrence line base (0 or 1) against the 1-based `Mapping`; the chat adapter message conversion; the embedding override with the stub; the end-to-end detector on a small in-memory text and a PCM model fixture with a stub gateway; the guard tests of the acceptance criteria. `mvn verify` of `detector-ardoco` and `inconsistency-agent`. No live LLM call in CI. Keep a handoff note `.work/T3.2-impl.md`.

## Constraints

Java 21. No new dependency. Do not change the `LargeLanguageModel` enum or any ArDoCo class. Do not set `LLM_CACHE_DIR`. Keep `.env` out of the working dir.

## Decisions

1. **Own module or same module.** [Same module `detector-ardoco`, same package, class names `Artemis*`.] Pro: reuse of the package-private `Mapping`, `KgInput`, `IdRunner`; one enforcer override; one `pipeline-id` dependency (it already brings `artemis`). Con: the Artemis code ships in the same jar. A separate module would need to copy or publish these classes.
2. **Own LLM adapter or env route.** [Own adapter.] The env route needs a global key and an `.env` or process variables, and it cannot select a key per project policy. It also cannot reroute the embedding call. Option "one env gateway key for the whole agent": rejected, because the key is then process-global and the local-only policy does not work.
3. **Enabled by default.** [No, `enabled: false`.] The e2e replay has no cassette for the Artemis prompts and the output of the LLM changes with the model. Enable after a recorded cassette exists (T3.5).
4. **Embeddings.** [Gateway route `embed-default` or `embed-local`.] Artemis hard-codes `text-embedding-3-large`. The gateway model of the route replaces it. The cosine threshold 0.6 stays. Quality of other embedding models is not verified.
5. **Line base.** [Verified by a test, then mapped to the 1-based `Mapping`.]
6. **Sampling.** [Temperature 0 and a fixed seed.] The repair call of NAER uses the same settings.
7. **Findings.** [Same types and severities as `ardoco-id` (T3.1 decision 4).] The detector id differs, so the fingerprints differ. `usesLlm` marks the run in the run record.
