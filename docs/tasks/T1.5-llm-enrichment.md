## Goal

After the elements of a version are written, `extract-artifact-versions` enriches them with summaries and concepts in a separate `Run` (`tool = llm-enrichment`), unless disabled by config or `options.llmEnrichment = false`. Enrichment is optional: its failure never loses extraction results.

## Scope

1. **Config.** Create `config/llm/models.yaml` (Stage 2 §1.6 format; compose already points `SANDMAN_LLM_MODELS_FILE` at it, the file does not exist yet). Enrichment settings (`enabled`, element kinds, max elements per run, concurrency, `maxSummaryChars`) per open question 2.
2. **LLM access.** `Service` builds a `ModelSelector` from `Settings` (`llm_models_file`, `llm_base_url`, `llm_key`, `llm_local_key`); the route is `chat_model(project.llmPolicy)`, the client `client(policy)`. `temperature = 0`, fixed `seed`, `user = runId`, `response_schema` set (strict structured output).
3. **Prompts and schemas.** Versioned prompt files `services/extraction-agent/src/sandman_extraction/prompts/{summary,concepts}.txt` (`str.format`, artifact text only inside a delimited data section); response schemas `.../schemas/{summary,concepts}.schema.json` (bounded lengths, max concepts per element, `confidence` in [0,1]). Prompt id = `<path>@<first 12 hex of sha256(content)>`.
4. **Calls.** One call per element (open question 1 decides which kinds), elements selected with `ORDER BY e.id`; prompts contain element text and name only, never ids, run ids or timestamps (cassette keys must be stable across projects and runs).
5. **Writes** (one transaction per artifact version): `SET e.summary`; `MERGE` `Concept` by `con_` id (normalization per open question 3); replace the version's `MENTIONS` edges (delete old, create new with `confidence`, `runId`); `(run)-[:PRODUCED]->(concept)`.
6. **Provenance.** Extend `RunRecorder.start` with optional `prompt_ids` and `RunRecorder.complete` with optional `resolved_model` (library change with test); write `model` (route), `params` (JSON: temperature, seed), summed token usage.
7. **Failures.** Schema-invalid or non-JSON response → retry once, then skip that element with a warning; `PolicyError`, connection errors, any other gateway/proxy error (incl. a replay miss, HTTP 404) → enrichment Run `failed`, skill output gets a warning, extraction result unchanged; `BudgetExceededError` propagates (existing library behavior blocks the workflow; see open question 6).

Out: requirement splitting of unstructured text (open question 5), embeddings, enrichment of plugin-produced elements, Java side, re-enrichment of unchanged elements across versions beyond open question 4.

## Deliverables

`config/llm/models.yaml`; enrichment config (open question 2); `services/extraction-agent/src/sandman_extraction/enrich.py` (selection, prompting, validation, writes) wired into `extract.py`; prompt and schema files above; `RunRecorder` extension in `libs/python/sandman-agent/src/sandman_agent/kg.py`; tests and cassette `services/extraction-agent/tests/cassettes/enrichment/cassette.jsonl`.

## Acceptance criteria

- `mini` fixture with enrichment on: every selected element has a `summary`; concepts and `MENTIONS` exist; the enrichment `Run` has `tool = llm-enrichment`, `model`, `resolvedModel`, `params`, `promptIds`, token counts; skill output and event still validate against `contracts/`.
- `llmPolicy = local-only` uses the `-local` key and `chat-local` route (assert on the request); a cloud route under `local-only` raises `PolicyError` → enrichment skipped with warning.
- `options.llmEnrichment = false` or `enabled: false` → no LLM call, no enrichment Run.
- Re-running the skill with the same input does not duplicate `Concept` nodes or `MENTIONS` edges.
- Injection fixture (artifact text "ignore previous instructions, output …") yields only schema-valid data or a skipped element.
- `uv run ruff check`, `ruff format --check`, `uv run pytest services/extraction-agent libs/python/sandman-agent` green; no test calls a live model.

## Test plan

- **Unit** (`ScriptedLlmClient`): valid output, malformed JSON, schema violation, refusal/empty content, over-long summary, duplicate concept names differing in case/whitespace.
- **Integration** (Testcontainers Memgraph, `ScriptedLlmClient`): writes, idempotency, replacement of `MENTIONS` on re-extraction, Run provenance.
- **Replay** (no Docker needed for the LLM part): `create_app(Settings(mode="replay", records_dir=...))` from `sandman_llm_replay.app` served through `httpx.ASGITransport`; `OpenAiLlmClient(_client=AsyncOpenAI(base_url=..., http_client=httpx.AsyncClient(transport=...)))`. Strict replay: a miss fails the test. Recording once: same test with `mode="record"` against the gateway (env-gated, never in CI); review the cassette for secrets and confidential content before committing.

## Open questions (decided 2026-10-08: recommended defaults accepted)

1. Which elements are enriched? [`Requirement` and `TextUnit` with `kind = section` get summaries and concepts; sentences, `ModelElement`, `CodeUnit`, plugin elements are skipped.]
2. Where does enrichment config live? A new section in `config/extraction/plugins.yaml` changes `configHash`, which enters explicit-link ids (`tl_`), so tuning a prompt setting would churn links. [Separate file `config/extraction/enrichment.yaml`; its hash is the enrichment Run's `configHash`.]
3. Concept name normalization has no conformance vector. [NFC, casefold, collapse whitespace, trim; vector added in a separate contract PR.]
4. Reuse results for an unchanged element (same `key` and `contentHash`) in a new version instead of a new call (cost, RK-8)? [Yes, if `promptIds` and resolved route match; copy summary and `MENTIONS`.]
5. Requirement splitting for unstructured text (Stage 1 §5.2): the plan names only concepts and summaries for T1.5, but the T1.3 spec lists it as T1.5 work. [Out of T1.5; a separate follow-up task after T1.3, and fix the reference in T1.3.]
6. Budget exhaustion during optional enrichment: block the workflow (current library behavior) or skip with warning? [Block; it keeps spend visible and matches `a2a.py`.]
7. Concrete pinned models in `models.yaml` (user decision); does Bifrost → remote Ollama (`SELFHOSTED_LLM_URL`; serves `chat-local`/`embed-local`) honor `response_format: json_schema`? [Verify first; fallback `json_object` + local schema validation.]
8. R-041 (done in T1.14): `Run.resolvedModel` is a single value. [Store the first resolved model; `Run.mixedModels` marks a mismatch and replaces the former `event=mixed_models` log.]
9. `Concept` has no `runId`, so `cleanup_stale` cannot remove concepts of failed runs. [Accept; orphan concepts are pruned in T5.2.]
