## Goal

The detector `ardoco-id` writes ArDoCo ID findings to the KG as inconsistencies with stable fingerprints. It uses the active trace links of all configured approaches (Q-20). With `linkApproaches: [ardoco]`, its findings equal the findings of the standalone ArDoCo runner on the benchmark inputs (the T3.3 test uses the hooks of this task). The standard ID path makes no LLM call.

## Scope

Step 1, SPI and registry (internal, no contract change):
1. **SPI module.** Move the SPI types (`InconsistencyDetector`, `DetectorContext`, `DetectionScope`, `Finding`) to a new module `services/inconsistency-agent/detector-spi`. Keep the package name. Reason: `detector-ardoco` must not depend on the Quarkus app (same split as T2.1 step 4).
2. **Detector params.** `DetectorRegistry` reads `detectors.<id>.params` from `config/inconsistency/plugins.yaml` and passes them to the detector. Add `InconsistencyDetector.paramKeys()` (default empty). Unknown param names fail at startup.
3. **DetectorContext.** Add `params` (map), `artifacts` (the agent-lib `ArtifactStore`) and `cancelled` (`BooleanSupplier`). Keep `kg`, `llmPolicy` and `queryServiceUrl`.
4. **Whole-project detectors.** Add `InconsistencyDetector.scopeMode()` with default `PAIRWISE`. A `WHOLE_PROJECT` detector ignores the scope subset and runs over all current versions. In `DetectionService.write` step 3, a completed whole-project detector resolves its own items even if their artifacts are not in the scope (open question 6).
5. **Run identity.** `Run.inputKey` gets a `configHash` per detector: sha256(JCS(effective params)) plus the CoreNLP provider identity of T2.5. A change of `linkApproaches` then gives a new run key.

Step 2, module and detector:
6. **Module `services/inconsistency-agent/detector-ardoco`** (listed in the root `pom.xml`, `ServiceLoader` registration in the module). Package `edu.kit.kastel.mcse.ardoco.sandman.inconsistency.ardoco`, package-private classes. Dependency: `io.github.ardoco.id:pipeline-id` of the pinned branch (version `2.1.0-SNAPSHOT`, to verify after the bootstrap build). Exclude magika, onnxruntime and Eclipse JDT, as `approach-ardoco` does (to verify that the ID path does not load them). Exclude the CoreNLP models jar; the remote CoreNLP provider annotates the text (T2.5).
7. **R-030.** Allow `dev.langchain4j` in the enforcer of `detector-ardoco` and `inconsistency-agent` only. LangChain4j 1.18.1 comes in through `model-provider` even on the non-LLM path (spike §6). Add `ModuleRulesTest` to `inconsistency-agent` (copy of the tlr-agent rule): no class outside `..sandman.inconsistency.ardoco..` imports `dev.langchain4j..`. Add a rule fixture that the test must reject.
8. **Detector `ardoco-id`.** Id `ardoco-id`. Version `0.1.0+0d1f22b`; raise the first part when the mapping changes. Types `undocumented-model-element` and `missing-model-element`. `usesLlm` = false. `scopeMode` = `WHOLE_PROJECT`. `paramKeys` = `textKinds` (default `[architecture-doc]`), `modelKinds` (default `[architecture-model]`), `linkApproaches` (default `all`, else a list of approach ids).
9. **Runs.** One ArDoCo run per (current doc version of `textKinds` × current model version of `modelKinds`) with model format PCM or UML. Decide the format by `Artifact.format`, else by file suffix (`.repository` PCM, `.uml`/`.xmi` UML), as T2.1 does. Skip other formats with a warning. Serialize all runs in the JVM with one lock (ArDoCo singletons, spike "Not verified"). Check `ctx.cancelled()` between runs. Delete temp dirs.
10. **Text (ADR-0015 S3).** Read the sentence `TextUnit`s of the doc version from the KG, ordered by `sentenceIndex`. Render one sentence per line (line breaks inside a sentence become one space, T2.1 note). Annotate the lines with the CoreNLP gateway in `eolonly` mode (T2.5 client). Inject the result as `PreprocessingData`; `CoreNLPProvider` then skips its own NLP (spike §4). Assert per line: the hash of the normalized line equals the hash part of the sentence key. A mismatch fails the detector. ArDoCo sentence *i* (1-based) = line *i* = the `TextUnit` at `sentenceIndex` *i* − 1.
11. **Model.** Stage the original model file from the artifact store (`storageUri`) into a temp dir. ArDoCo model id = PCM `id` / UML `xmi:id` = `ModelElement.localKey` (spike §4). Derive `localKey` from `Element.key` (text after the first `#`), as T2.1 does. Interfaces are model elements too (ArDoCo maps, for example, "download" to `IDownload`). An unknown model id in a finding fails the detector.
12. **Pipeline.** `definePipeline` is private, so build the pipeline from the public `get(config, repo)` factories, as `Spike.runExternal` does: `TextPreprocessingAgent` → `ModelProviderAgent` → `TextExtraction` → `RecommendationGenerator` → `ConnectionGenerator` → **`ExternalLinksStep`** → `InconsistencyChecker`. Metamodel `ARCHITECTURE_WITH_COMPONENTS_AND_INTERFACES`. Run with `runWithoutSaving()`; read `new ArdocoResult(repo).getAllInconsistencies()`. Factory names come from spike §2; verify them against the pinned commit.
13. **Link feed (`ExternalLinksStep`, Q-20 workaround, spike §5).**
    - Read the active, non-rejected `TraceLink`s between sentence `TextUnit`s of the doc version and `ModelElement`s of the model version. Both ends must be current. Use the `StubUntracedDetector` pattern. Filter by `TraceLink.approach` if `linkApproaches` is a list.
    - Map each link to (line index, `localKey`).
    - Build a new state with `ConnectionStatesImpl.build(...)`. Add `addToLinks(ri, entity, claimant, p)` for every RecommendedInstance with a word in a linked sentence that passes the rule `internal+similar`: ArDoCo already has an instance link from this RI to the element, or the RI name is similar to the element name.
    - Replace the entry with `repo.addData(ConnectionStates.ID, fresh)`.
    - Do not drop `ConnectionGenerator`; it also adds RecommendedInstances that the text detector uses.
    - Record the counts (input links, mapped RI links, unmapped links) as detector warnings or log fields.
14. **Findings.**
    - `ModelEntityAbsentFromTextInconsistency` → type `undocumented-model-element`, severity `warning` (open question 4). Involved: the `ModelElement` with `localKey` = `getModelInstanceUid()`, role `subject`. Evidence: model id, element name, ArDoCo element type, doc version id.
    - `TextEntityAbsentFromModelInconsistency` → type `missing-model-element`, severity `info` (open question 4). Involved: the sentence `TextUnit`, role `subject`. ArDoCo reports one finding per word, and duplicates can differ only in confidence (spike §3: S1 "Media" 0.63 and 0.65). Deduplicate by (sentence, word) and keep the maximum confidence. Then merge all words of one sentence into one finding (open question 1): `confidence` = maximum, `evidence.words` = sorted list of `{word, confidence}`, title names the words.
    - Multiple runs (several docs or models): combine as in open question 5.
    - Fingerprint and lifecycle stay the T0.7 rules: sha256(type, detector id without version, sorted involved keys). The detector version is not in the fingerprint, so triage survives T3.5. `evidenceHash` comes from the involved elements' `contentHash`.
15. **Failures.** CoreNLP unavailable, a hash mismatch, an unknown model id or an ArDoCo exception throw a `RuntimeException` from `detect`. `DetectionService` then marks the run `partial`, and nothing of this detector auto-resolves (T0.7).
16. **Equivalence hooks for T3.3.** Package-private entry points in `detector-ardoco`, usable from tests:
    - `run(Text preprocessed, Path model, ModelFormat, List<ExternalLink> linksOrNull)` returns the raw ArDoCo inconsistencies before mapping. `null` = no `ExternalLinksStep` (pure ArDoCo pipeline).
    - `standalone(Path rawText, Path model, ModelFormat, Path outDir)` calls `InconsistencyDetection.setUp(...)` + `run()` and parses `inconsistencyDetection_<name>.txt` (format to verify).
    - A normal form for comparison: model findings as the set of model ids, text findings as the set of (1-based sentence, word) pairs.
    - Publish the test helpers as a test-jar, as `approach-ardoco` does for `CorenlpProvider`.

Step 3, build, deploy and config:
17. **Branch build (B1).** Move `spikes/T0.12/bootstrap.sh` to `scripts/ardoco-id-bootstrap.sh`. It must run on Linux (no `/usr/libexec/java_home`) and install into a given Maven repo. Add `make ardoco` (named in ADR-0015). The inconsistency-agent `Dockerfile` runs the script in its build stage with a Maven cache mount. CI caches the result by commit sha.
18. **Compose.** `inconsistency-agent` joins the `corenlp` network and gets `SANDMAN_CORENLP_URL`, `SANDMAN_CORENLP_TOKEN_FILE` and the secret `corenlp_client_token_inconsistency-agent`. The gateway, the Caddyfile entry and `gen-secrets.sh` already know this caller (T2.5). Keep the working dir free of `.env`. Check `mem_limit: 5g` with the TEAMMATES run.
19. **Config.** Add `ardoco-id` to `config/inconsistency/plugins.yaml` with the Stage 2 params; `enabled` per open question 9. Update the e2e golden if e2e runs the detector.
20. **Licences.** `services/inconsistency-agent/THIRD-PARTY.md` (ArDoCo MIT, CoreNLP GPL-3.0-or-later, LangChain4j Apache-2.0), as `services/tlr-agent/THIRD-PARTY.md`.

Out: Artemis variant and any LLM use (T3.2); the standalone equivalence test itself (T3.3, this task gives the hooks and a MediaStore smoke check); console evidence view (T3.4); switch to the released ArDoCo (T3.5); labeling study (T3.6); the upstream extension for sentence-level links (spike §5); per-project doc/model globs (R-025); code models (ACM) as ArDoCo input; HTTP plugin packaging (open question 2).

## Acceptance criteria

- `detector-spi` split done; T0.7 tests (`DetectionScenarioTest`, `LifecycleTest`, `FingerprintTest`, `TransitionTableTest`, `PluginTest`, `AgentTest`, `SmokeTest`) stay green without changes to their expectations.
- **MediaStore (PCM and UML), `linkApproaches: [ardoco]`, links from the `ardoco` approach:** the raw ArDoCo output of the adapter equals the standalone run: 6 `ModelEntityAbsentFromText` + 36 `TextEntityAbsentFromModel` = 42 (spike §3). After mapping: 6 `undocumented-model-element` findings and one `missing-model-element` finding per affected sentence (17 sentences: 1, 9, 12, 13, 20, 22–25, 27–29, 31–35).
- Without `ExternalLinksStep` (hook `linksOrNull = null`), the adapter equals the standalone runner on MediaStore and TeaStore (PCM and UML).
- Every finding involves a current element; no finding is lost by fingerprint collision (one finding per fingerprint by construction).
- Two runs on the same KG give the same fingerprints, ids and `evidenceHash` values (determinism). A second detection run gives no new or reopened items.
- **Lifecycle on real data (M3 exit, part):** on MediaStore in Testcontainers Memgraph, remove the "Cache" component from the PCM model; the related `undocumented-model-element` item auto-resolves. Add one sentence at the start of the doc; no status changes (R-001 scenario). A doc-only change auto-resolves model findings that the doc change fixes (whole-project rule).
- `linkApproaches` filters: with `[]`, ArDoCo gets no links, so every model element of the default types is reported; with `[ardoco]`, the 42 result holds.
- CoreNLP gateway down: the run is `partial`, the detector entry is `failed`, and no `ardoco-id` item auto-resolves.
- The enforcer still fails if another module adds LangChain4j. `ModuleRulesTest` rejects the fixture.
- TEAMMATES runs in a container with `mem_limit: 5g` without OOM; the log records peak heap and duration per run.
- `make e2e` and CI stay green; e2e < 15 min; image size before and after is recorded.

## Open questions

1. **One text finding per sentence or per word.** The fingerprint is (type, detector id, involved keys). Two words of one sentence have the same involved key, so `DetectionService.prepare` keeps only the first (`putIfAbsent`).
   - A: one finding per sentence; words in `evidence.words`. Pro: no contract change, stable fingerprint, one triage item per sentence. Con: accepting a sentence accepts all its words; a new word in an accepted sentence reopens it only if the sentence text changes.
   - B: one finding per (sentence, word); add an optional `Finding.discriminator` (here the lower-case word) to the fingerprint. Pro: exact ArDoCo granularity, per-word triage. Con: contract minor bump, new vectors case, change in `Ids.fingerprint` for all languages.
   - [A. Revisit with B after the T3.6 labeling study if per-word triage is needed.]
2. **In-process detector or HTTP plugin (`POST /v1/detect`, T0.10).** In-process pro: ADR-0012 and ADR-0015 prescribe it, direct KG and artifact access, R-030 module rule. Con: +570 MB image, ArDoCo dependencies on the Quarkus classpath (RK-22). HTTP plugin pro: own classpath, no Quarkus BOM conflict, own memory limit. Con: the plugin needs KG read access or a large input payload, a new service, and ADR changes. [In-process. Switch to a plugin only if the Quarkus classpath breaks CoreNLP or ArDoCo (T3.3).]
3. **Reuse of `SentenceRendering` and `CorenlpClient` from `approach-ardoco`.** They are package-private, and `CorenlpClient` throws the tlr `ApproachUnavailableException` and uses ArDoCo `text-provider-json` classes. The release (TLR) and the branch (ID) have the same class names.
   - A: new shared module `libs/java/ardoco-text` with the ArDoCo dependencies in scope `provided` (compiled against the release). Pro: one implementation, one parity test. Con: binary compatibility with the branch must hold (`git diff v2.1.0 0d1f22b` for `text-provider-json` and `core/api`, to verify).
   - B: copy both classes into `detector-ardoco`. Pro: no cross-version risk. Con: two copies to keep in sync.
   - [A if the diff check is empty, else B with a test that compares both renderings on the benchmark texts.]
4. **Severities.** [`undocumented-model-element` = `warning`, `missing-model-element` = `info`. Text findings have a lower precision (MediaStore: words like "it", "component", "data").]
5. **Several doc or model versions.** ArDoCo reads one text and one model per run. The same model element can be documented in doc A and not in doc B. [Intersection: report `undocumented-model-element` only if every run with that model reports it; report `missing-model-element` for a sentence only if every run with that doc reports it. Per-project pairing globs come with R-025.]
6. **Scope handling.** The orchestrator sends `scopeArtifactIds` (for example, only the changed doc). A model finding involves only the model element, so step 3 of `DetectionService.write` never resolves it on a doc-only scope. [Whole-project detector (Scope item 4): the detector always runs all pairs, and a completed run resolves its own items regardless of the scope. Alternative: involve the doc as evidence, which changes the fingerprint.]
7. **Exact model findings.** The `internal+similar` rule gives 7 model findings with gold links on MediaStore, the `sentence` rule gives exactly the 4 gold UME but 0 text findings (spike §5). "Run the checker twice" (model findings from `sentence`, text findings from `internal+similar`) was not tried. [Ship `internal+similar` only; try the double run as a measured experiment in T3.3 and switch if it reaches the gold UME on MediaStore and keeps the 42 = 42 equivalence for `[ardoco]`. Contribute the upstream extension (spike §5) in parallel.]
8. **Branch build in the reactor.** `pipeline-id:2.1.0-SNAPSHOT` is not on Maven Central, so a root `mvn` build fails without the bootstrap. [Module in the default reactor; `make ardoco` and the Dockerfile run the bootstrap first; CI caches it. Alternative: a Maven profile `ardoco-id`, off by default, which hides build breaks.]
9. **Enabled by default.** Stage 2 plans `enabled: false`. [Enabled in `config/inconsistency/plugins.yaml`, as `ardoco` in T2.1; e2e runs it on the mini fixture and the golden records the findings.]
10. **Default element types for model findings.** ArDoCo reports only `Component`, `BasicComponent`, `CompositeComponent` (spike §2) and uses `minimumNeededTraceLinks` = 1 and a whitelist. [Keep ArDoCo's defaults; no params for them until a project needs it.]
