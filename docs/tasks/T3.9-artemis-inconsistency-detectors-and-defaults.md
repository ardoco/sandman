# T3.9 ArTEMiS inconsistency detectors and ArTEMiS as the default

Milestone M3 · Effort L · Depends on: T3.5 (step B), T3.8 · Checks RK-22

Status: partial, steps 1-6, 8 and 9 done; defaults flipped to ArTEMiS on 2026-11-12 (user decision, evidence on two projects); step 7 (new benchmark projects in experiments) not done

## Context

ArDoCo PR #186 (merge `21ef682`) extends the inconsistency detection:

* ArTEMiS ID works per strategy (component, class, datafile). It finds text entities that the model misses (TEAM). For components it also finds model entities that the text misses (MEAT).
* New inconsistency kinds: programming-language statements in the text and architectural style or pattern statements in the text. Each is checked against the code by an LLM agent with read-only tools. `ProgrammingLanguageInconsistencyDetection` and `ArchitecturalStylePatternInconsistencyDetection` run the checks. They record a statement and an `explanation`, not a model element.
* The `InconsistencyState` types are new. Gold standards exist for all kinds in the benchmark projects.
* The programming-language and style checks take `LargeLanguageModel` (enum). There is no `ChatModel` injection (same gap as T3.8 finding 4).

Today SANDMAN has the detector `artemis-id` (components only, disabled by default) and `ardoco-id` (default). The TLR approaches `transarc` and `ardocode` are default or optional. The user decision of 2026-11-12: ArTEMiS becomes the default.

## Goal

SANDMAN detects the new inconsistency kinds. ArTEMiS detectors and approaches are the default when an LLM route exists. The classic ones stay as fallback.

## Decisions (defaults taken 2026-11-12)

| # | Question | Decision |
|---|----------|----------|
| 1 | Finding types for class and datafile gaps | Reuse `undocumented-model-element` and `missing-model-element`. Add `target` to the evidence. |
| 2 | Finding types for the new kinds | New types `programming-language-mismatch` and `architectural-style-mismatch`. Evidence: sentence and `explanation`. Severity `warning` (the contract enum has `info`, `warning`, `error`; decided 2026-11-13). |
| 3 | LLM injection for the checks | Build the stages from the public classes with the gateway `ChatModel`. Ask upstream for injection. |
| 4 | Code input for the checks | Decide in the spike (step 1): ACM from `code-extractor-ardoco`, or a directory built from the artifact store. |
| 5 | Default order | `artemis-id` and `artemis-transarc` first. `ardoco-id` and `transarc` run only when no LLM route exists (`local-only` without a model). |
| 6 | Flip condition | Only after the evaluation (step 8) matches or beats the classic detectors on the benchmark projects. |

## Steps

Each step ends with its check. Keep the handoff note `.work/T3.9.md` up to date. Implementation agents: Sonnet, medium effort.

1. Spike: run the two new detections from the pinned sources on `sandman-example` with the gateway `ChatModel`. Test the read-only tools on a directory and on an ACM.
   Check: `docs/notes/spike-T3.9.md` records which input works (decision 4), cost and time.
2. Extend `artemis-id` (`services/inconsistency-agent/detector-ardoco`): param `strategies: [component, class, datafile]`, MEAT for components, new states in `Mapping`, new `VERSION`.
   Check: `MappingTest` covers each state. `ArtemisIdDetectionTest` counts are recorded.
3. Add the detectors `programming-language-id` and `architectural-style-id` (decisions 2 to 4). Evidence holds the statement, the sentence and the explanation. The detector needs the code through the chosen input.
   Check: detector tests with a stubbed gateway. Golden KG update.
4. Contracts and KG: add the two finding types to `contracts/kg/schema.yaml`. Add `target` to the evidence schema.
   Check: contract and KG tests pass.
5. Console and triage: labels, filters and causes for the new types. Update `experiments/labeling/GUIDELINES.md` and `docs/user/trace-links-and-findings.md`.
   Check: console tests pass. A label example exists for each new type.
6. Config: add the new detectors to `config/inconsistency/plugins.yaml`. Add the fallback rule of decision 5 (the workflow picks the classic detector when no LLM route exists).
   Check: workflow tests cover both routes.
7. Cassettes and goldens: `make record-cassettes`. Add the new benchmark projects and gold standards from upstream to `experiments`.
   Check: `make e2e` and `make replay-twice` pass.
8. Evaluate: `sandman eval` on the benchmark projects for classic against ArTEMiS (inconsistencies and TLR). Record precision, recall, cost and time in `docs/notes/eval-T3.9.md`.
   Check: the note states the result against decision 6.
9. Flip the defaults in `config/inconsistency/plugins.yaml` and `config/tlr/approaches.yaml` only if decision 6 holds. Update ADR-0015, the user docs and `site/src/components.yaml`.
   Check: `make e2e` passes with the new defaults. Release notes mention the cost change.

## Acceptance criteria

1. The new finding types appear in the KG, the console and the docs.
2. `artemis-id` covers components, classes and datafiles.
3. The evaluation note exists. The defaults follow decision 6.
4. With no LLM route, the classic detector and approach run and the user sees why.
5. `mvn -B verify`, `make e2e` and `make replay-twice` pass.

## Rollback

Revert the default flip (step 9) alone to return to the classic defaults. Revert the other steps together if needed.

## Risks

* LLM cost and runtime become the default. Mitigation: policy routes, budget check in T5.4, fallback.
* Statement-level findings have no model element. Console and fingerprint code may assume one. Mitigation: step 4 and 5 tests.
* Upstream renames before the release. Mitigation: re-diff at the T3.5 trigger.
