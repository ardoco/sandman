## Goal

`requirements` artifacts in Markdown or CSV yield one `Requirement` per requirement with its id as `localKey`; explicit references resolve only to requirements, run from requirement to referring element, and never link a definition to itself.

## Scope

1. `services/extraction-agent/src/sandman_extraction/requirements.py`, registered in `builtin.py` for `kind=requirements`:
   - Markdown: a heading of any level whose first token is a requirement id (current `REQ_HEADING` id rule) starts a requirement; `name` = rest of the heading, `text` = heading + body up to the next heading (≤ 4000 chars), lines, `parent` = `file`; move `REQ_HEADING` and the logic out of `stub_elements` (the stub keeps only file-level elements);
   - CSV: UTF-8 (BOM tolerated), header row, columns per open question 2; one `Requirement` per row, `startLine`/`endLine` = physical lines of the record; rows without id or with a duplicate id → skipped + warning;
   - `kind` = CSV `type` column if present, else `requirement` (as in M0);
   - requirements files get no section/sentence `TextUnit`s (open question 4);
   - with `builtin.enabled: false` or after an extractor fallback the stub yields only the file-level element (no `Requirement` nodes) — intended.
2. Explicit references (`extract.py`), per R-013's recommendation (open question 1):
   - targets: `Requirement` elements only (current versions plus this run), matched by `localKey`;
   - direction unchanged: source = requirement, target = referring element; no link from an element to itself (definition site);
   - the built-in matcher runs only on non-plugin artifacts (as now); plugin `explicitReferences` are resolved the same way.
3. Golden files for `mini/requirements/requirements.md`, a CSV fixture `tests/fixtures/requirements/requirements.csv`, and a requirements set from a LiSSA dataset once V-24 names one (open question 3).

Out: LLM requirement splitting of unstructured text (not planned in M1; possible follow-up task), re-resolving links when the referenced artifact changes (R-014, open question 5), per-project reference patterns (open question 6), changes under `contracts/`.

## Acceptance criteria

- `mini` still yields exactly REQ-1..3 with the M0 names, and the walking-skeleton e2e test stays green (link REQ-1 → `MediaCacheTest`, two untraced requirements).
- CSV fixture: one `Requirement` per valid row; missing/duplicate ids reported in `warnings`; quoted multi-line cells keep correct line ranges.
- Matcher: a requirements file mentioning REQ-1 inside REQ-1 creates no link; REQ-2's body mentioning REQ-1 creates REQ-1 → REQ-2; a doc sentence mentioning REQ-1 creates REQ-1 → that sentence (with T1.1); a reference text equal to a non-requirement `localKey` creates no link; unknown ids create nothing.
- Link ids recomputed in the test with `stable_id`; running the skill twice creates no duplicates.
- Golden files committed and green; `make lint` and `uv run pytest services/extraction-agent` green.
