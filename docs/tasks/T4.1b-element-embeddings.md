## V-43 findings (Memgraph 3.13.1, verified with Testcontainers)

- Syntax: `CREATE VECTOR INDEX element_embedding ON :Element(embedding) WITH CONFIG {"dimension": 768, "capacity": 100000, "metric": "cos"}`. A second run does not fail and changes nothing.
- The dimension is fixed per index. Writing a vector of another length fails the write.
- Search: `CALL vector_search.search("element_embedding", k, $vector) YIELD node, similarity`. There is no property filter. Filtering by `projectId` is a post-filter on `node`, so `k` must exceed the wanted count (T4.5 over-fetches and cuts).
- `REMOVE e.embedding` or `SET e.embedding = null` removes the node from the index.
- `SHOW VECTOR INDEX INFO` lists the index (`dimension`, `size`, `capacity`).
- Not verified here: memory per 100 k elements and persistence across snapshots. Estimate: 768 float32 = 3 KB per vector, about 300 MB plus graph structure per 100 k elements. Measure at T4.5.

## Decisions (defaults in brackets)

1. **Schema (additive, KG schema 0.5.0; the contract version 0.8.0 stays, the KG schema carries its own version).** `Element.embedding` (list of float, optional) and `Element.embeddingModel` (string, optional: the gateway model id, e.g. `openai/text-embedding-3-small`). Both are marked `internal: true`: they are for retrieval, not for answers or prompts. Readers ignore elements without them. [no `embeddedAt`; the Run records time and route]
2. **One dimension, one index.** The index has dimension [768] and metric [cos]. `embed-local` (`nomic-embed-text:v1.5`) gives 768 natively. `embed-default` (`text-embedding-3-small`, 1536) is cut to its first 768 values and re-normalized (valid for Matryoshka-trained models). A shorter vector is a failure of that batch. [the dimension lives in `init.cypher` and in `embedding.yaml`; a test keeps both equal]
3. **Which elements.** Labels and kinds in `config/extraction/embedding.yaml`: [`Requirement`, `TextUnit` kind `section`, `ModelElement`, `CodeUnit` kind `type`]. Sentences, methods, files and tests get none (volume, little signal).
4. **Which text.** `name` + blank line + `text` (empty text: `name` only), control characters removed, cut to [6000] chars. The summary is not used, so embeddings do not depend on the LLM enrichment.
5. **When.** After enrichment, in its own Run (`tool: element-embedding`, `model` = route), for the elements of the extracted versions. Default [`enabled: false`] until cassettes exist; the request option `options.embedding = false` also turns it off.
6. **Re-embedding.** Elements are created per version. An element takes the vector of an earlier element with the same `key`, `contentHash`, `name` and `embeddingModel` (copy, no gateway call). Otherwise it is embedded. A changed content hash or a changed model id therefore causes a new embedding. Old versions keep their vectors.
7. **Policy.** Route = `ModelSelector.embed_model(llmPolicy)`: `embed-default` for `cloud-allowed`, `embed-local` for `local-only`. A local-only client refuses non-local routes (`PolicyError`). If no LLM access is configured, the route is unknown, or the gateway denies the route, the step ends with a warning and the extraction result stays untouched.
8. **Batching and cost cap.** [32] texts per `embed` call, [2] batches in parallel, at most [500] elements per run (`maxElementsPerRun`), the rest is skipped with a warning. `BudgetExceededError` fails the embedding Run and propagates (same rule as enrichment). Other gateway errors give a warning.
9. **Progress.** `ctx.progress("embedding elements (n/m)")`, throttled by the existing 2 s rule.
10. **Index maintenance.** `init.cypher` creates the index (`capacity` [100000]; Memgraph raises it on demand). The write is one transaction per version: `SET e.embedding, e.embeddingModel`.

## Acceptance criteria

- Unit (scripted LLM, no graph): selection by label and kind, text rule, truncation to 768 with re-normalization, short vector rejected, batching by 32, element cap warning, policy picks `embed-local` / `embed-default`.
- Memgraph integration (Testcontainers, `memgraph/memgraph:3.13.1`): `init.cypher` twice changes nothing (index count, `SchemaVersion`); the vector index exists with dimension 768; embeddings are written with the model id; a second ingestion of unchanged content makes no `embed` call and copies the vector; changed text embeds only the changed element; a changed model id embeds again; `vector_search.search` returns the written nodes and the `projectId` post-filter works; local-only project uses only `embed-local`; disabled, no LLM, gateway error and `BudgetExceededError` behave as in decision 7 and 8; elements without embedding stay readable.
- Record/replay: the strict replay test over a cassette (`tests/cassettes/embedding/`) is added when the cassette is recorded (see Rollout). Until then, the test is skipped when the cassette is missing; the e2e config keeps `enabled: false`.
- `scripts/validate_contracts.py`, `uv run ruff check`, `ruff format --check`, `uv run mypy` for the touched packages, `uv run pytest services/extraction-agent` green. The existing e2e golden path is unchanged (embedding off, no new cassette entries).

## Rollout

- **Migration:** `kg-migrate` (`python -m sandman_agent.kg`) runs `init.cypher`. It is idempotent and additive: it creates the vector index and raises `SchemaVersion.version` to 2. Existing data stays valid; no backfill is needed to start.
- **Backward compatible:** readers ignore the new properties. Elements without a vector are skipped by search. `Element.embedding` is `internal`: NL-prompt generators must not list it (note for T4.2/T4.3).
- **Backfill:** a new ingestion embeds the elements of its versions. Elements of unchanged versions are not re-visited (no re-extraction) [out of scope; re-ingest the project, or run the skill again, to fill them].
- **Enable:** set `enabled: true` in `config/extraction/embedding.yaml` once the gateway allows `embed-default` / `embed-local` for the virtual keys (`deploy/gateway/config.json`) and, for local-only projects, the Ollama model `nomic-embed-text:v1.5` is pulled (`make models`).
- **Cassettes:** the e2e walking skeleton does not embed. To add embedding to it: set `enabled: true` in the e2e config, run `make record-cassettes` (records against the remote Ollama, regenerates the golden KG export; strip `embedding` in `scripts/kg_canonical_export.py` first, because vectors are not stable text), review the cassette for secrets, commit. Do not re-record live cassettes as part of this task.
