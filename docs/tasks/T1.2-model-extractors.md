## Context

ArDoCo reports model results by PCM `id` / UML `xmi:id`, and links text to components **and interfaces**; benchmark UML ids equal PCM ids (spike T0.12 §4b). The KG must therefore hold one `ModelElement` per component and interface with `localKey` = that id. Read first:

- `docs/stage-1-analysis-architecture.md` §5.2 (built-in extractors), §5.4 (ArDoCo detector mapping); `docs/stage-4-review.md` R-029 (XXE, billion laughs)
- `adr/0015-ardoco-integration.md` (S3, "the model extractor must also produce interfaces"), `docs/notes/spike-T0.12.md` §2, §4 (`PcmExtractor`, `UmlElement`, 23 MediaStore endpoints)
- Code: `services/extraction-agent/src/sandman_extraction/extract.py` (`RELATIONS`, `RELATION_QUERIES`, relation resolution in `_extract` via `version_of[path]`, `_write_links`), `builtin.py` (T1.1); fixture `services/extraction-agent/tests/fixtures/mini/model/mini.repository`.

## Goal

Built-in extractors for PCM repository XML (`pcm-repository`, `*.repository`) and UML XMI (`uml`, `*.uml`, `*.xmi`) that emit components and interfaces with preserved ids and `PROVIDES`/`REQUIRES` relations, identical in id set to what ArDoCo reads.

## Scope

1. `services/extraction-agent/src/sandman_extraction/models.py`, registered in `builtin.py`:
   - parse with `defusedxml.ElementTree` (no DTDs, no entity expansion); reject files above a size limit (open question 4) → file-level fallback + warning;
   - PCM: `components__Repository` → `kind=component`, `interfaces__Repository` → `kind=interface`; `localKey` = `id`, `name` = `entityName`; provided/required roles → `PROVIDES` / `REQUIRES` from the component to the referenced interface;
   - UML: `packagedElement` with `xmi:type` `uml:Component` / `uml:Interface` (`localKey` = `xmi:id`, `name` = `name`); `interfaceRealization` → `PROVIDES`, `uml:Usage` (client component, supplier interface) → `REQUIRES`;
   - follow ArDoCo's model reading (`PcmExtractor`, UML classes `UmlElement`/`PackagedElement`; pinned commit of `scripts/ardoco-id-bootstrap.sh`) for which XML constructs count; document deviations in the module docstring;
   - keep the `file` element as root (`CONTAINS` file → component/interface); `qualifiedName` = name; `text` = name plus provided/required interface names (bounded);
   - relations in the plugin shape (`{path, localKey}` endpoints, same path), so `_extract` resolves and writes them unchanged.
2. Golden files for `mini/model/mini.repository` and the vendored benchmark models (MediaStore and TeaStore `pcm/*.repository` and `uml/*.uml`, see T1.1 open question 5).
3. Dependency `defusedxml` in `services/extraction-agent/pyproject.toml` (approval needed).

Out: PCM system/assembly/allocation models and connectors (`DEPENDS_ON`), operation signatures, other metamodels (ArDoCo `COMPONENT_LISTING`, `ACM`), code models (plugins), ArDoCo itself (T2.1, T3.1).

## Acceptance criteria

- For MediaStore PCM and UML, the set of non-file `ModelElement` `localKey`s equals the 23 endpoint ids ArDoCo reports (expected list produced once with the spike harness in `spikes/T0.12`, committed as test data); PCM and UML yield the same id set and the same `PROVIDES`/`REQUIRES` pairs.
- Every non-file `localKey` occurs as `id="…"` / `xmi:id="…"` in the source file (the spike's check, run on all vendored models).
- Golden files committed and green; `mini.repository` still yields `MediaCache` and `UserDB`.
- XML with a DTD, an external entity or entity expansion is rejected → file-level fallback + warning, no network or file access.
- Integration (Testcontainers): extracting a model version writes `PROVIDES`/`REQUIRES` between current elements; re-extraction of a changed model drops removed components from the current set; T0.5 acceptance tests and the walking-skeleton e2e test stay green.
- `make lint` and `uv run pytest services/extraction-agent` green.

## Test plan

Unit: PCM and UML snippets (component without roles, interface only, role to a missing interface → warning and no relation, duplicate ids → first wins + warning, foreign namespaces/versions), XXE and billion-laughs payloads. Golden: benchmark models. Integration: one skill run with a model and one revision.

## Open questions (decided 2026-10-08: recommended defaults accepted)

1. Interface operations/signatures as elements? ArDoCo's metamodel `ARCHITECTURE_WITH_COMPONENTS_AND_INTERFACES` uses only components and interfaces. [No; add when a TLR approach needs them.]
2. Connectors (`DEPENDS_ON`, Stage 1 schema) need PCM `.system` / UML dependency parsing; the ArDoCo benchmarks ship repository models only (verify). [Out of T1.2; follow-up when a detector uses them.]
3. Which UML dialect variants must parse (Papyrus vs. Eclipse UML2 `xmi:type` prefixes, nested packages). [Exactly those in the ArDoCo benchmark set; others fall back with a warning.]
4. XML size limit. [10 MiB per model file, configurable via `builtin.maxXmlBytes`.]
5. Element `kind` for PCM `BasicComponent` vs. `CompositeComponent`. [`component` for both; the PCM type goes into `text`.]

## Constraints

Python 3.13, uv only, `sandman_agent`; stdlib `xml.etree` API through `defusedxml` (no `lxml`); deterministic output order (document order); all Cypher parameterized. Do not change `contracts/`. Ask before adding dependencies. Keep a handoff note `.work/T1.2.md`.
