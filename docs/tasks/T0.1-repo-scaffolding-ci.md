# T0.1 Repository scaffolding, build tooling and CI

Milestone M0 · Effort M · Depends on: – · Blocks: all other tasks

## Context

SANDMAN is a multi-agent system (Python + Java) in a monorepo. The repository already has `adr/`, `docs/`, `contracts/` and `deploy/`. Read first:
- `docs/stage-2-contracts-repository.md` §2 (layout, tooling, CI outline), §1.8 (contract validation)
- `adr/0008-monorepo-layout.md`, `adr/0010-minimal-agent-library.md`

## Goal

Create the empty but buildable skeleton for all modules, plus CI that validates contracts and builds/tests both languages.

## Scope

In:
1. Python uv workspace at the repository root: `pyproject.toml` with members `libs/python/sandman-agent`, `services/orchestrator`, `services/extraction-agent`, `services/query-service`, `services/llm-replay`, `tools/cli`, `tests/plugin-stubs`. Each member has a minimal `pyproject.toml`, an importable package (`sandman_agent`, `sandman_orchestrator`, `sandman_extraction`, `sandman_query`, `sandman_llm_replay`, `sandman_cli`, `sandman_plugin_stubs`) and one trivial test. Python 3.13. Dev tools: ruff, mypy, pytest. Commit `uv.lock`.
2. Maven aggregator `pom.xml` (Java 21) with modules `libs/java/agent-lib`, `libs/java/agent-lib-a2a`, `services/tlr-agent`, `services/inconsistency-agent`. Define `dependencyManagement` with properties for `a2a-java` (latest 1.x Final), Quarkus platform BOM (current 3.x LTS), `neo4j-java-driver`, `jnats`, `json-schema-validator`, `java-json-canonicalization`, JUnit 5, Testcontainers. Add Spotless (check in `verify`) and `maven-enforcer-plugin` with `bannedDependencies` for agent frameworks (`dev.langchain4j:*` banned in `libs/` and service code; it will be allowed later only as a transitive dependency of the ArDoCo/LiSSA adapter packages). Each module has one trivial test.
3. `Makefile` targets: `secrets`, `infra`, `up`, `down`, `logs`, `test`, `test-py`, `test-java`, `contracts`, `e2e` (placeholder that fails with "not implemented"), `backup` (placeholder).
4. `scripts/validate_contracts.py`: validates JSON Schemas against the 2020-12 meta-schema; validates the `eventEnvelope` and `skillInvocation` cases in `contracts/conformance/vectors.json` against the schemas; recomputes the `stableId`, `sectionKey`, `sentenceKey` and `fingerprint` cases and checks the cassette keys against the `rfc8785` package; checks that every Agent Card extension schema reference resolves; validates all `contracts/openapi/*.yaml` with `openapi-spec-validator`. Run it with `uv run --with ... python scripts/validate_contracts.py`, or add a dev dependency group.
5. GitHub Actions `.github/workflows/ci.yml` with jobs `contracts`, `python` (ruff, mypy on `libs/`, pytest), `java` (`mvn -B verify`), `compose` (`deploy/gen-secrets.sh` in a temp copy + `docker compose config -q`), each with path filters as in Stage 2 §2.3. Also add the framework guard for Python: fail if `langchain`, `langgraph`, `deepagents`, `llama_index`, `crewai` or `autogen` is imported under `libs/` or `services/`.
6. `.dockerignore` (exclude `data/`, `deploy/secrets/`, `**/target`, `**/.venv`, `.git`).

Out: any service logic, Dockerfiles (T0.11), the e2e job (T0.11).

## Acceptance criteria

- `uv sync` and `uv run pytest` succeed from the repository root; `uv run ruff check .` and `uv run mypy libs/python` pass.
- `mvn -B verify` succeeds; adding `dev.langchain4j:langchain4j` to `services/tlr-agent/pom.xml` makes the enforcer fail (verify manually, do not commit).
- `make contracts` passes on the current `contracts/` and fails if a schema is broken (e.g., an invalid `type` value).
- The CI workflow runs green on a PR; its jobs are skipped when their paths are unchanged.
- No changes under `contracts/`, `adr/` or `docs/` except documentation of new Make targets in `README.md`.

## Constraints

Conventional Commits, small commits, no AI attribution. Pin tool versions (uv, Python, Java, Maven plugins).
