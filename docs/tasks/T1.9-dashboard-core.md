It must keep working when the services it monitors are down, so it depends only on Memgraph and NATS at startup. ## Goal

`services/dashboard` (package `sandman_dashboard`): FastAPI + Jinja2 (autoescape) + vendored htmx and Cytoscape.js, no build chain, with admin login, the **Services** start page, the **Knowledge graph** page and the **LLM gateway** page.

## Scope

1. **Login and sessions.** One account `admin`; password = content of `SANDMAN_DASHBOARD_ADMIN_PASSWORD_FILE` (constant-time compare). Server-side sessions in SQLite at `SANDMAN_STATE_DB` (`PRAGMA user_version` + plain SQL migrations, same scheme as query-service `store.py`): random session id, only its sha256 stored, absolute 12 h / idle 2 h expiry. Cookie `sandman_dashboard_session` (distinct name: cookies are not port-isolated, the console on `127.0.0.1:8080` uses `sandman_session`), `HttpOnly`, `SameSite=Strict`, `Secure` when `SANDMAN_COOKIE_SECURE=true`. CSRF token on every POST (403 without). Logout revokes. Login rate limit 5 failures per 15 min per username and client address → 429. Every page and JSON endpoint except `/login`, `/healthz`, `/readyz`, `/static/*` requires a session.
2. **Poller.** Background task every `SANDMAN_POLL_INTERVAL` s (default 5) over `SANDMAN_TARGETS`: `GET /readyz` (no auth) and `GET /v1/status` (bearer `svc_token_dashboard`), 2 s timeout each, concurrently. Health: `up` = readyz 200 and status 200; `degraded` = readyz 200 but status failed or invalid; `down` = readyz non-200, timeout or connection error. Infrastructure: Memgraph `RETURN 1` (read) and `SHOW STORAGE INFO` (fixed query via `KgClient.run_autocommit`, the read path blocks it); NATS `SANDMAN_NATS_MONITOR_URL` `/healthz?js-enabled-only=true` and `/jsz?streams=true&consumers=true` (stream `SANDMAN` messages/bytes, consumer `orchestrator` pending/ack-pending/redelivered); gateway `GET /health`. Results are kept in memory with `checkedAt`; pages read only this cache (T1.10 alerts and T1.11 samples reuse it).
3. **Services page** (start page, htmx refresh every 5 s): per service health, state `working`/`idle`, `activeTasks`, `lastActivityAt`, `version`, `details` as escaped key/value list; Memgraph nodes/edges/memory, NATS stream size and consumer lag, gateway health; time since last successful check.
4. **Knowledge graph page.** Project selector (from `MATCH (p:Project)`) or "all projects". Start from a label, a search by `key`/`name`/`id`, or the Cypher box; expand neighbors on click; filters by label and relationship type (allowed values from `contracts/kg/schema.yaml`, never interpolated from input); properties panel; at most 500 nodes per response with a `truncated` flag; path between two nodes (Memgraph BFS, max hops default 6, syntax per V-38); export of the visible subgraph as PNG and JSON client-side (`cy.png()`, `cy.json()`). Session-authenticated JSON endpoints return Cytoscape elements; element ids are driver element ids (dashboard-internal), the schema `id` is shown as a property.
5. **Read-only Cypher box.** Statement passes the query-service guard's clause allowlist in unscoped mode (admin, no anchoring; see open question 1), then runs via a read transaction with 10 s timeout, `QUERY MEMORY LIMIT 100 MB` appended and a row limit (500, `LIMIT` appended when missing). Result as table; returned nodes can be added to the graph. Guard rejections, timeouts and memory-limit errors show a message, never a 500.
6. **LLM gateway page.** `GET {SANDMAN_GATEWAY_URL}/metrics` with Basic auth `admin:<gateway_admin_password>`: requests, input/output tokens, cost, errors and latency (p50/p95 from the histograms) per virtual key, model and provider since gateway start, plus rates since the previous poll. Budget usage per virtual key from the Bifrost management API (endpoint to verify, V-36); budget ≥ 80 % highlighted. Charts over time come in T1.11.
7. **Page layout.** Shared `base.html` with navigation (later pages added by T1.10/T1.11), banner slot (T1.10), `Content-Security-Policy: default-src 'self'; frame-ancestors 'none'; form-action 'self'; base-uri 'none'` and `X-Frame-Options: DENY` on all responses. All JavaScript in vendored or own files under `static/` (no inline scripts or handlers, CSP forbids them); htmx copied from the query-service with the same pinned version; Cytoscape.js 3.34.x (MIT) with license file (V-39).
8. **Service plumbing.** `/healthz`; `/readyz` (SQLite and Memgraph reachable; monitored services are not checked). JSON logs via `sandman_agent.telemetry`. `Dockerfile` following `services/orchestrator/Dockerfile` (port 8000, non-root, `/data`). Add the package to the root `pyproject.toml` workspace and dependencies, `uv.lock`, the CI `python` and `compose` path filters, and `--profile dashboard --profile resources` to the CI `docker compose config` loop. Adjust the existing Compose `dashboard` entry only where the image needs it.

Out: workflows, events, alerts, experiments (T1.10); projects, history, resources (T1.11); users other than `admin`, OIDC.

## Acceptance criteria

- **Auth:** every protected route returns a redirect to `/login` (HTML) or 401 (JSON) without a session; cookie flags and name asserted; CSRF missing/wrong → 403; logout revokes the session; 6th failed login → 429; session expiry honored.
- **Read-only KG:** with Testcontainers Memgraph 3.13.1, the Cypher box rejects `CREATE`, `MERGE`, `SET`, `DELETE`, `REMOVE`, `CALL`, `DUMP DATABASE`, `SHOW …`, `LOAD CSV`, `;`-chained statements and a caller-written `QUERY MEMORY LIMIT`; with the guard bypassed (test seam), a write still fails in the read transaction and the node count is unchanged; a cartesian product hits the memory limit and shows a message. Graph and path endpoints use only parameterized queries.
- **No secrets leaked:** a test renders every page and JSON endpoint, triggers upstream errors (gateway 401/500, unreachable targets) and asserts that none of the secret values (admin password, session secret, service token, Memgraph and gateway passwords) appears in responses or captured logs; upstream error bodies and request headers are never shown.
- **Poller:** with fake ASGI targets, a target that stops answering is shown `down` within one polling interval; readyz 200 + status 401 → `degraded`; one slow target does not delay the others beyond its timeout.
- **Gateway:** parsing a recorded Bifrost `/metrics` fixture yields the expected per-key/model totals (tokens, cost, errors); a metric absent from the scrape shows "n/a", not an error.
- **XSS:** a node property and a `details` value containing `<script>` are rendered escaped; CSP header present; no inline `<script>` in templates.
- **Compose / e2e:** `docker compose --profile stubs --profile dashboard up --wait` is healthy; `tests/e2e/test_dashboard.py` logs in, sees all six `SANDMAN_TARGETS` plus Memgraph, NATS and gateway `up`, loads the graph of the e2e project, gets a write rejected, and shows `tlr-agent` as `down` after `docker compose stop tlr-agent` (then restarts it and waits until healthy).
- `uv run ruff check`, `ruff format --check`, `uv run pytest services/dashboard` green.

## Test plan

- Integration: `test_memgraph.py` with Testcontainers Memgraph 3.13.1 (skip without Docker): Cypher box corpus, graph/path queries, `SHOW STORAGE INFO`.
- E2E: `make e2e` starts profile `dashboard` as well and runs `tests/e2e/test_dashboard.py` in a second pytest call after the walking-skeleton test (it needs its data); CI e2e job unchanged otherwise.

## Constraints

Python 3.13, uv, `sandman_agent`, FastAPI, Jinja2, `httpx`, `python-multipart`, uvicorn; no new dependency without asking (see open question 3). All Cypher parameterized; labels and relationship types from the schema enum. The dashboard writes nothing to Memgraph and holds no tokens except its own. Keep a handoff note `.work/T1.9.md`.
