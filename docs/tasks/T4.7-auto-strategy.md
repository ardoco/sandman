# T4.7 Strategy `auto`: classifier routes a question

Milestone M4 · Effort S · Depends on: T4.1 (done), T4.5 (done), T4.6 (done) · Blocks: none

## Context

ADR-0018 defines `auto` as the default strategy. One cheap classifier call picks `cypher`, `graphrag` or `explore`. Read first:
- `adr/0018-query-strategies.md` (rows `auto`, "Visible choice", "Availability"), `adr/0009-nl-to-cypher.md` (amendment D-2)
- `docs/tasks/T4.1-nl-to-cypher-strategy.md` (dispatch), `T4.2-nl-query-evaluation-set.md` (`strategy` labels, `sandman eval nlquery classifier`), `T4.4-query-security-suite.md`
- `contracts/openapi/query-service.yaml` (`classification`), `contracts/config/query-strategies.schema.json` (`classifierThreshold`)
- Code: `services/query-service/src/sandman_query/nl.py`, `strategies/`, `templates/ask.html`.

## Goal

A question with `strategy: auto` runs on the strategy that fits it. The response names the resolved strategy and the classification. A weak or invalid classification never leaves the set of enabled strategies.

## Scope

1. **Candidates.** The enabled and registered strategies of `cypher`, `graphrag`, `explore`. `auto` is available if at least one is. Otherwise it answers 501.
2. **No classifier call** (no cost) in these cases. The classification is still returned, with `confidence` 1 and a `reason`:
   - Only one candidate exists.
   - `cypher` is enabled with `intentsFirst` and a fixed intent matches the question.
3. **Classifier.** One chat call on the project route (`ModelSelector.chat_model(llmPolicy)`: a `local-only` project uses `chat-local`), temperature 0, structured output `{strategy, confidence, reason}`.
   - The system prompt lists only the candidates with one line on what each fits.
   - The user message is the question and nothing else. The question is untrusted: the prompt says it is data. No KG content, no schema.
   - The `strategy` enum of the schema holds the candidates only.
4. **Validation.** The output counts only if `strategy` is a candidate (checked in code, not only by the schema), `confidence` is a number (not a boolean) in [0, 1], and the JSON parses. `reason` is cut to [200] characters. The console escapes it.
5. **Fallback.** The safe default is `cypher`: it is guarded, cheapest and deterministic, and a wrong answer is visible. If `cypher` is disabled, the first enabled candidate in the order `cypher`, `graphrag`, `explore`. The fallback applies when:
   - the confidence is below `classifierThreshold` [0.6] (equal passes); the classification keeps the pick of the model and the reason says the fallback was used,
   - the output is invalid (`confidence` 0, strategy = fallback),
   - the classifier call fails or no LLM is configured (`confidence` 0). The error text is not returned.

   Ask-for-clarification is not used: it needs a new response shape and a second round trip. The user can re-run with another strategy in the console.
6. **Response.** `strategy` is the resolved one. `classification` (`strategy`, `confidence`, `reason`) is present for `auto` only (existing contract fields, no change). The console Ask page already shows both. `mode` and `execute` pass to the resolved strategy unchanged.
7. **Wiring.** `strategies/auto.py` (`classify`, `auto`, `register`); `NlService` registers it, reads `classifierThreshold`, and `enabled("auto")` is true if a candidate is enabled. The classifier uses the project `llmPolicy` through `NlService.llm`. No cascade (ADR-0018): if the resolved strategy fails, the response reports it.

Out: few-shot examples in the classifier prompt, classifier token budget, caching of classifications, cascade between strategies, a `clarify` outcome.

## Acceptance criteria

- Scripted-LLM tests: dispatch to each of the three strategies, with the classification in the response and the OpenAPI schema valid; classifier input is the question only; route `chat-local` for a local-only project; the enum and prompt list only enabled strategies.
- Fallback tests: below threshold (and the equal case) gives `cypher` with the model pick visible; invalid output (strategy outside the allowlist, `auto`, `run_cypher`, confidence out of range, boolean, text, wrong JSON type) gives `cypher`; classifier error gives `cypher` without leaking the error; `cypher` disabled gives the first enabled candidate; no candidate gives 501.
- No-classifier-call tests: one candidate; matching intent; no LLM configured.
- Injection test: a question that asks for another strategy cannot leave the allowlist and only appears in the user message.
- T4.4 suite: the `auto` cases run next to `cypher`, `graphrag`, `explore` (forged foreign rows with guard on and off, role check before availability).
- Console test: the classification badge shows; the reason is escaped.
- `uv run ruff check`, `ruff format --check`, `uv run pytest services/query-service` green.

## Findings and open points

- Evaluation gap: `sandman eval nlquery classifier --dataset D --predictions P` takes `{id: strategy}`. That fits `classification.strategy` of a response, but no endpoint runs only the classifier. A dataset run through `POST /v1/query/nl` with `execute: false` runs the classifier and the model call of `cypher`, but no graph tool. `sandman eval nlquery classify --dataset D --out P` closes the gap (see T4.2, Commands). Use the pick of the model (`classification.strategy`), not the fallback, to measure the classifier.
- The threshold [0.6] is not tuned. Tune it on the `strategy`-labelled items of the T4.2 set after the first run.
- A classifier call is not counted in the token budget of `explore`.
