## Goal

Markdown and plain-text artifacts produce a `file` element, one `TextUnit` per section (`kind=section`) and one `TextUnit` per sentence (`kind=sentence`) with content-based keys and a 0-based, document-wide `sentenceIndex`, nested by `CONTAINS`.

## Scope

1. **Dispatch** (`services/extraction-agent/src/sandman_extraction/builtin.py`): `extract(path, kind, fmt, content) -> (elements, relations)` choosing an extractor by `Artifact.format`, else by file extension (formats are optional in kind rules; the e2e fixture sets none). Element dicts keep the shape `stub_elements` returns (`localKey`, `label`, `kind`, `name`, `qualifiedName`, `text`, `startLine`, `endLine`, `parent`) plus optional `sentenceIndex`; relations use the plugin shape (`type`, `source`/`target` = `{path, localKey}`) so `_extract` resolves them unchanged. Unsupported format → `stub_elements` (current behavior); extractor exception → `stub_elements` + warning in the skill output (see open question 4). `stub()` in `_extract` calls `builtin.extract` and puts relations into `relations[vid]`.
2. **Text extractor** (`sandman_extraction/text.py`, `extract(path, content)`) for `markdown` and `text`, all kinds except `requirements` (T1.3):
   - keep the `file` element (`localKey=file`) as root; section keys via `section_local_key` (ATX and setext headings; text before the first heading = `sec:`; plain text has only `sec:`); `name` = heading text, `text` = section excerpt ≤ 4000 chars, `startLine`/`endLine`;
   - paragraphs = blank-line-separated blocks; each list item is its own paragraph; inline markup removed (link text kept); fenced/indented code, HTML blocks and tables excluded from sentences (open question 2);
   - sentence keys via `sentence_local_key` with the occurrence counter per section; `text` = normalized sentence (as in the vector rule, so the key hash is recomputable from `text`); `startLine`/`endLine` of the sentence so `match_references` attributes references to sentences.
3. `render_sentences(elements) -> str` in `text.py`: sentence texts ordered by `sentenceIndex`, one per line, no blank lines (the ArDoCo input of ADR-0015 S3; see open question 1).
4. KG write: add `n.sentenceIndex = e.sentenceIndex` to `_element_query` and pass it in `_write_elements`; set `TOOL`, `TOOL_VERSION` to the built-in extractor identity (open question 3).
5. Switch: `builtin.enabled` (default `true`) in `config/extraction/plugins.yaml`; `false` restores the M0 stub (plan §2).
6. Golden-file harness reused by T1.2–T1.4: `services/extraction-agent/tests/test_golden.py` runs `builtin.extract` on every file under `tests/fixtures/{mini,benchmark}/` and compares canonical JSON (sorted keys, emission order) with `tests/golden/<fixture>/<path>.json`; `SANDMAN_UPDATE_GOLDEN=1` rewrites them. Benchmark texts are vendored per open question 5.

Out: requirements (T1.3), models (T1.2), PDF/DOCX (T1.4), LLM enrichment (T1.5), ArDoCo `PreprocessingData` annotation (T3.1), changes under `contracts/`.

## Acceptance criteria

- Golden files for `mini/docs/*.md`, `spikes/T0.12/fixtures/wrapped.md` (copied into fixtures) and the vendored benchmark texts are committed and green; a vector-style unit test recomputes every sentence key from its `text`.
- Sentence-alignment rate against the benchmark `.txt` lines (one sentence per line) is printed per project; MediaStore = 37/37 (MediaStore text vendored in `tests/fixtures/benchmark/mediastore/`, checked by default).
- Inserting a sentence into a section changes no other element key; `sentenceIndex` of later sentences shifts; identical sentences in one section get `~2`, `~3`.
- `render_sentences` of `wrapped.md` has as many lines as sentence elements and line *i* hashes to the key of `sentenceIndex` *i*.
- Integration (Testcontainers): extracting `mini` writes sections and sentences with `CONTAINS` file → section → sentence; re-extraction of a changed version drops removed sentences from the current set; T0.5 acceptance tests and `tests/e2e/test_walking_skeleton.py` stay green; `builtin.enabled: false` reproduces M0 output.
- `make lint` and `uv run pytest services/extraction-agent` green.

## Test plan

Unit: headings/setext, nested sections and duplicate sibling slugs, preamble, lists, code/table exclusion, abbreviations ("e.g.", "i.e."), hard-wrapped paragraphs, CRLF, empty file, non-UTF-8 bytes. Golden: fixtures above. Integration: one skill run on `mini` plus one revision.

## Open questions (decided 2026-10-08: recommended defaults accepted)

1. Plan T1.1 says the one-sentence-per-line rendering is "stored per version"; the spike recommends that T3.1 owns it; R-025 asks for one canonical rendering per doc version. [No stored blob, no contract change: T3.1 renders from the KG (`text` ordered by `sentenceIndex`); `render_sentences` is the reference implementation and test oracle.]
2. Headings, tables and code blocks as sentences? [No; headings only as section names, tables/code only in section `text`. ArDoCo benchmark texts contain none of them.]
3. Run identity of built-in extraction. [One `Run` per skill call as today, `tool=builtin-extractor`, `toolVersion` bumped whenever a golden file changes.]
4. Parser error status: Stage 1 says "fallback + warning" but not the run status. [Run status `partial`, like plugin failures; unsupported format stays `completed`.]
5. Benchmark data source (A3-2): vendor files from the pinned ArDoCo commit or fetch in CI. [Vendor MediaStore and TeaStore texts under `tests/fixtures/benchmark/` with a `SOURCES.txt` (commit, path, license) after a license check; other projects opt-in via a pytest marker.]
6. Sentence splitter and Markdown parser (new dependencies, approval needed). [`markdown-it-py` (token line maps) and `pysbd` (rule-based, deterministic), both MIT; plain regex splitting fails on abbreviations.]
7. Sentence `name` (required). [First 80 characters of the normalized text.]
8. Owner of the Stage 2 §4.2 criterion "incremental ingestion of 1 000 files < 60 s". [T1.1 adds a timed integration test with 1 000 small Markdown files, marked `slow`.]
