# T1.11 Dashboard insights (projects, history, resources)

Milestone M1 · Effort M · Depends on: T1.9 · Blocks: M1 exit

## Context

T1.9 delivers the `dashboard` service (admin login, poller cache with service health/activity, Memgraph `SHOW STORAGE INFO`, NATS `/jsz`, gateway `/metrics`, SQLite state DB with migrations). This task adds the pages that look at content and trends: per-project KG statistics, history charts from the dashboard's own SQLite samples, and container resource usage via cAdvisor in the opt-in Compose profile `resources` (already defined: `gcr.io/cadvisor/cadvisor:v0.60.6`, read-only host mounts, network `internal`; `SANDMAN_CADVISOR_URL=http://cadvisor:8080` is already set on the dashboard). Read first:
- `docs/tasks/T1.9-dashboard-core.md` and its code in `services/dashboard`
- `adr/0016-system-overview-dashboard.md`, `docs/stage-1-analysis-architecture.md` §10.1 (Projects, Resources, History), §4 (current versions, active links)
- `contracts/kg/schema.yaml` (labels, `TraceLink.active`/`approach`, `Inconsistency.status`/`type`, `Ingestion.seq`, `CURRENT_VERSION`), `deploy/docker-compose.yml` (`mem_limit` per service, Memgraph `--memory-limit=8192`)
- `docs/stage-3-implementation-plan.md` V-37 (cAdvisor registry, mounts, metrics on Docker Desktop and Linux), V-39 (uPlot)

## Goal

Pages **Projects**, **History** and **Resources** in `services/dashboard`, with a sampler writing to the dashboard SQLite every 30 s and a 14-day retention.

## Scope

1. **Projects page:** one row per project, detail per project, all from read transactions (10 s timeout, `QUERY MEMORY LIMIT 100 MB`, parameterized): artifacts (current / deleted) and versions; elements of current versions by label; active trace links per approach (`active = true` and both endpoints current, the Stage 1 "current link" rule); inconsistencies by status and by type; last ingestion (`seq`, `createdAt`, `sourceRevision`, counts of its `ACTIVATED`/`DELETED` edges). Results cached for 60 s per project; a slow or failing query shows "n/a" for that figure only.
2. **Sampler** (background task, interval `SANDMAN_SAMPLE_INTERVAL`, default 30 s) reading only the T1.9 poller cache, never the targets directly. Migration `002_samples.sql`: `samples(ts INTEGER, series TEXT, key TEXT, value REAL)` with an index on `(series, key, ts)`. Series: `health` (0 = down, 1 = degraded, 2 = up) and `active_tasks` per service and infrastructure component; `llm_requests`, `llm_tokens_in`, `llm_tokens_out`, `llm_cost`, `llm_errors` as cumulative gateway counters per virtual key; `memgraph_memory`. Hourly prune of samples older than 14 days (`SANDMAN_HISTORY_DAYS`, default 14).
3. **History page:** uPlot 1.6.x (MIT, vendored with license, V-39) charts for health, activity and LLM usage; ranges 1 h, 24 h, 14 d; server-side downsampling to at most 1 000 points per series; LLM charts show per-interval deltas computed from the counters, treating a counter decrease (gateway restart) as a reset, not a negative value. Chart data from a session-authenticated JSON endpoint; glue in a static JS file (CSP, no inline scripts).
4. **Resources page:** cAdvisor API (endpoint and version to verify, V-37): memory working set and CPU rate per container of the Compose project, mapped by the label `com.docker.compose.service`, against the container's memory limit; Memgraph memory from `SHOW STORAGE INFO` against `--memory-limit`; ≥ 80 % highlighted. Without the profile (URL unreachable) the page shows "profile `resources` not active" and the navigation entry stays; nothing else fails.
5. **Compose / docs:** verify and, if needed, fix the `cadvisor` mounts and image for Docker Desktop (macOS) and Linux; record the V-37 result in `docs/notes/cadvisor.md`. cAdvisor stays on `internal` only, no published port.

Out: alerts (T1.10), resource history (only health, activity and LLM usage are sampled), per-project LLM cost (gateway metrics are per virtual key, not per project), Grafana dashboards (T1.7).

## Acceptance criteria

- **Project statistics:** with Testcontainers Memgraph 3.13.1 and a seeded two-project fixture (deleted artifact, reactivated version, inactive link, link with a non-current endpoint, inconsistencies in several states), every figure matches hand-computed values and no figure of project A counts nodes of project B.
- **Sampler and retention:** with a fake clock and fake poller cache, one sample row set per interval; a target that goes down is recorded as 0 in the next sample; prune removes exactly the rows older than 14 days; the sampler keeps running when the cache has missing entries.
- **History:** downsampling keeps at most 1 000 points and preserves min/max per bucket for health; a counter reset yields a non-negative delta; the JSON endpoint requires a session.
- **Resources:** against a recorded cAdvisor response fixture, memory/CPU per Compose service and the percentage of `mem_limit` are computed correctly; cAdvisor unreachable → page renders with the "not active" message; the dashboard healthcheck stays green without the profile.
- **Compose:** `docker compose --profile dashboard --profile resources up --wait` is healthy on Linux (CI) and the Resources page shows every running SANDMAN container; Docker Desktop result recorded in `docs/notes/cadvisor.md`.
- **Security:** pages and JSON endpoints require a session; project names and labels are escaped; KG access only through read transactions (reuse the T1.9 read path); no secrets in pages or logs (extend the T1.9 leak test).
- **E2E** (extend `tests/e2e/test_dashboard.py`): the Projects page shows the walking-skeleton project with non-zero artifacts, elements, links and inconsistencies; the History page returns at least one sample per service after one interval.
- `uv run ruff check`, `ruff format --check`, `uv run pytest services/dashboard` green.

## Test plan

Unit tests with fake clock, fake cache and recorded cAdvisor/metrics fixtures (`test_sampler.py`, `test_history.py`, `test_resources.py`); integration test with Testcontainers Memgraph (`test_projects.py`, skip without Docker); Compose run with profile `resources` in CI (`compose` job) and once manually on Docker Desktop; e2e as above.

## Constraints

Same stack as T1.9; stdlib `sqlite3`; no time-series database, no new dependency without asking. Keep a handoff note `.work/T1.11.md`.

## Open questions (recommended default in bold)

1. Sampling interval and retention: **30 s, 14 days (≈ 40 000 rows per series, small SQLite)**, as in ADR-0016; configurable via env only.
2. If cAdvisor does not work on Docker Desktop (V-37): **support Linux only, show "not available on this host" on macOS and document it**, or drop the Resources page there in favor of `docker stats` by hand.
3. Project statistics cost on large projects (≤ 200 000 nodes, A-6): **compute on page view with a 60 s cache**, or compute in the sampler and store snapshots (adds per-project series).
4. CI coverage of the `resources` profile: **start it in the existing `compose` job (adds cAdvisor startup time)**, or only validate `docker compose config` and test against fixtures.
