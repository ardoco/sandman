## Context

Thus it cannot work on element subsets, and R-022 asks for a `scopeMode`. The 2.1.0 TLR release is on Maven Central since 2026-10-07. Its SWATTR stages (text-preprocessing, text-extraction, recommendation-generator, connection-generator) are identical to the pinned branch commit `0d1f22b` (`git diff v2.1.0 0d1f22b` is empty for them). SAD↔code is not in this task (open question 1). Read first:

## Goal

The approach `ardoco` writes ArDoCo SAD↔SAM links to the KG. On the benchmark projects, this link set is identical to the link set of the standalone ArDoCo runner. Whole-project approaches give the same current links after incremental runs as after one batch run.

## Scope

Step 1, contract PR (additive, `contracts/` only, validated by `scripts/validate_contracts.py`):
1. `ListApproachesOutput.approaches[].scopeMode`: enum `pairwise | whole-project`, optional, absent = `pairwise`. Bump the contract minor version.
2. Semantics text in `skills.schema.json` (`RecoverTraceLinksInput` description) and Stage 2 §1.6 / §4.3. A `whole-project` approach ignores the version subset of the input. It runs over all current versions of the artifact kinds it supports. It retires its own active links of these kinds that the run did not produce. A `pairwise` approach keeps the T0.6 semantics.
3. ADR-0015 dated amendment: TLR uses the released `io.github.ardoco.tlr:*:2.1.0`. B1 (pinned commit) applies to the inconsistency branch only (T3.1). R-022 status in Stage 4.

Step 2, code:
4. **SPI** (internal, not a contract): `TraceLinkApproach.scopeMode()` with default `PAIRWISE`. `TlrInput.Element` gets `versionId`, `localKey` and `sentenceIndex` (nullable). `TlrInput` gets `versions` (id, artifactId, path, kind, format, storageUri). Move the SPI types to a new module `services/tlr-agent/approach-spi`, so approach modules do not depend on the Quarkus app.
5. **Whole-project runs** in `RecoverTraceLinks`/`LinkStore`: for a whole-project approach, load all current versions of the supported kinds in the project. `finish` deactivates the approach's active links whose endpoint artifact kinds match a supported pair and that the run did not produce. Record all used versions on the `Run`. Event and output keep the input version ids. `GET /v1/approaches` returns `scopeMode`.
6. **Module `services/tlr-agent/approach-ardoco`** (listed in the root `pom.xml`, `ServiceLoader` registration). Dependency: `io.github.ardoco.tlr:pipeline-tlr:2.1.0`. It brings LangChain4j transitively (through `model-provider`). Allow `dev.langchain4j` in the enforcer of `approach-ardoco` and `tlr-agent` only. Add an ArchUnit test in `tlr-agent`: no class outside `..sandman.tlr.ardoco..` imports `dev.langchain4j..` (R-030).
7. **Approach `ardoco`**: id `ardoco`, version `2.1.0+a1` (raise the `+aN` suffix when the mapping changes), `supports` = {architecture-doc → architecture-model}, `scopeMode` = `whole-project`, `usesLlm` = false. One run per (doc version × model version) with model format `pcm-repository` or `uml`; skip other formats with a warning.
   - Text: sentence `TextUnit`s of the doc version, ordered by `sentenceIndex`, one per line (T1.1 `render_sentences`). Annotate with ArDoCo's CoreNLP properties plus `ssplit.eolonly=true` and inject as `PreprocessingData` (spike `presplit`). Assert per line: the hash of the normalized line equals the hash part of the sentence key; a mismatch fails the run.
   - Model: stage the original model file from the artifact store (`storageUri`) into a temp dir; `ArchitectureConfiguration` with PCM or UML.
   - Pipeline: the SWATTR steps from the public factories (`ModelProviderAgent`, `TextExtraction`, `RecommendationGenerator`, `ConnectionGenerator`), then `runWithoutSaving()`. Pass `params.additionalConfigs` (default `{}`) as ArDoCo additional configs; params enter `configHash` as in T0.6.
   - Output: `ArdocoResult.getArchitectureTraceLinks()` → one `CandidateLink` per distinct (sentence number, model id). Source = the sentence `TextUnit` at that line. Target = the `ModelElement` with `localKey` = model id. `linkType` = `documents`; `confidence` = 1.0, because ArDoCo's `TraceLink` has no confidence; no `rationale`. An unknown model id fails the run.
   - Serialize ArDoCo runs in the JVM with one lock (ArDoCo singletons, spike "Not verified"). Check `ctx.cancelled()` between runs. Delete temp dirs.
8. **Docker and config**: the image needs no ArDoCo source build. Set `LLM_CACHE_DIR` to a temp dir and keep the working dir free of `.env`. Enable `ardoco` in `config/tlr/approaches.yaml`. Add `ardoco` to the orchestrator pair `architecture-doc → architecture-model`.

Out: SAD↔code (TransArC/ArDoCode, follow-up task, open question 1); LLM variants (SWATTR-AI, Artemis, ExArch); `kindPairs` input and orchestrator changes for pairwise approaches; per-project doc/model pairing globs (R-025); benchmark export formats and metrics (T2.3); gold-standard vendoring; switching T3.1 to the release (T3.5).

## Acceptance criteria

- Contract PR validates; `GET /v1/approaches` validates and lists `ardoco` with `scopeMode: whole-project` and `stub-name-match` with `pairwise`.
- **Equivalence (M2 exit):** for MediaStore and TeaStore (PCM), and MediaStore (UML), the adapter's link set equals the standalone set as (1-based sentence, model id) pairs. The standalone set comes from `Swattr.setUp(rawBenchmarkText, ArchitectureConfiguration(model, PCM|UML), {}, outDir)` + `run()`, parsed from `sadSamTlr_<name>.csv`. TEAMMATES, BigBlueButton and JabRef run in the same test. If CoreNLP splits a raw text into more sentences than lines, the test reports that project as excluded with the counts; otherwise it must be equal.
- **Incremental equals batch** (Testcontainers Memgraph, MediaStore): sequence = doc v1 (first 30 sentences) + PCM model; doc v2 (all 37 sentences); add the UML model; PCM v2 without one component; a step with a merged (union) input. After the last step, the set of current `ardoco` link ids equals the set of a batch run on a fresh KG seeded with the final state only.
- After each step, no active `ardoco` link has an endpoint outside the current versions.
- Two runs on the same input give the same link ids and `configHash` (determinism).
- `stub-name-match` behavior and all T0.6 tests stay unchanged. The enforcer still fails if another module adds LangChain4j. The ArchUnit test fails on a LangChain4j import outside `..tlr.ardoco..`.
- TEAMMATES runs in a container with `mem_limit: 5g` without OOM; the log records peak heap and duration per run. `make e2e` and CI stay green; e2e < 15 min.

## Open questions

1. SAD↔code: the KG has no code model that ArDoCo can read. Code elements come only from the external code-extraction plugin (Q-19) or the file-level stub. ArDoCo reads a code directory or an ACM file. The benchmark code and `codeModel.acm` files are not vendored. [Defer to a follow-up task T2.1b: stage the current code versions by path, `CodeConfiguration.DIRECTORY`, and map links to file-level `CodeUnit`s by path. Decide after the plugin's element contract is known.]
2. ArDoCo source for TLR: release 2.1.0 or the pinned commit `0d1f22b`. [Release 2.1.0; SWATTR stage code is identical, and no source build is needed in Docker or CI. T3.1 keeps B1.]
3. Doc/model pairing (R-025): all combinations or configured globs. [All combinations of current architecture-doc × architecture-model versions with a supported format; globs when a project needs them.]
4. Module layout: nested modules under `services/tlr-agent/` or `libs/java/`. [Nested `approach-spi` and `approach-ardoco`; T2.2 adds `approach-lissa` there.]
5. Exclude LangChain4j from the ArDoCo dependency instead of an enforcer exception. [No; `model-provider` classes reference it, and R-030 already prescribes the module exception.]
6. Standalone runner in the same JVM or a forked JVM. [Same JVM, fresh `DataRepository` per run; fork only if shared singletons change results.]
7. Rendering versus raw text: benchmark renderings equal the raw files except the final newline (checked on all five). [Feed the raw file to the standalone runner and the KG rendering to the adapter, as in production.]
8. Link confidence and rationale. [1.0 and none; ArDoCo's instance-link probabilities stay internal until a consumer needs them.]
9. Both orchestrator steps for one pair (doc and model changed) recompute everything twice. [Accept; results are identical by determinism. Optimize only if the run time matters.]
