# T6.5 Console graph explorer (visual knowledge graph for users)

Milestone M6 · Effort L · Depends on: T0.9, T1.9 (done) · Risk: RK-9 (injection through node properties), cross-project reads

Status: done 2026-10-19.

Deviations:

- The open questions took the bracketed defaults: built-in layouts (force, hierarchical, concentric), filter hint above 500 nodes, `Run` and `Ingestion` hidden for every user without the global admin flag.
- `sandman_agent.graphview` does not import the query-service guard. The shared `GraphService` takes the guard and its error class as constructor arguments. The dashboard keeps a thin subclass in `sandman_dashboard.graph` with the guard set, so its imports and tests stay unchanged. `jsonable` moved from `sandman_query.reader` into `graphview`.
- The routes live in `sandman_query/graph_console.py`. `console.py` only calls `graph_console.mount`.
- Fixed statements hide the labels in Cypher. A user statement is refused if it names a hidden label or returns a node with one. A result that holds property maps of unlabeled matches (for example `RETURN n.text`) is not filtered by label.
- The artifact filter works through the version pattern `HAS_VERSION` and `HAS_ELEMENT`. The state filter works through `CURRENT_VERSION`.
- The e2e test `tests/e2e/test_console_graph.py` is part of `make e2e`. It was not run against a full stack in this task.
- The manual browser check (layouts, export, 500 nodes on the soak project) is still open.

## Context

Users can only read the knowledge graph through lists and the Ask page. The admin dashboard (T1.9) has a graph page with Cytoscape.js, but it is admin-only and not limited to one project. Users want a view like the Neo4j Browser: the whole graph, a filtered part, or the result of their own query.

Read first:
- `services/dashboard/src/sandman_dashboard/{graph.py,static/graph.js,templates/graph.html}` (reuse: element conversion, caps, path query, filters)
- `services/query-service/src/sandman_query/{guard.py,reader.py,console.py}` (scoped guard, read path, roles)
- `docs/notes/cypher-guard.md`, `contracts/kg/schema.yaml`, `contracts/openapi/query-service.yaml`

## Goal

A console page `/console/projects/{project}/graph`. A user with access to the project sees its graph, filters it, expands it and runs read-only Cypher on it. The user cannot see other projects.

## Scope

1. **Backend (query-service).** Session-authenticated JSON routes under `/console/projects/{project}/graph/`: `start`, `expand`, `path`, `query`. They return Cytoscape elements, `truncated` and counts. Every route uses the existing role check for the project.
2. **Reuse, no copy.** Move the element conversion, caps and path logic from `sandman_dashboard.graph` into `sandman-agent` (`sandman_agent.graphview`). Dashboard and query-service import it. Adjust the dashboard only as far as the move needs.
3. **Views.**
   - Whole project: a bounded start set (500 nodes, `truncated` flag, hint to filter).
   - Filtered: by label, relationship type, artifact, version state (current/historic), element name search. Values come from the schema enum or are bound as parameters.
   - Neighborhood: click a node to expand it. Hop depth 1 to 3.
   - Path between two nodes (max 6 hops).
4. **User queries.** A Cypher box. The statement passes `guard.check(..., scoped=True)`, so every node pattern is anchored to the project. It runs in a read transaction with 10 s timeout, memory limit and row cap. Graph results (nodes, relationships, paths) are drawn. Other results show as a table. Guard errors show the reason, never a 500.
5. **Browser view.** Cytoscape.js, layouts (force, hierarchical, concentric), color by label, property panel, node and edge legend, search in the visible graph, PNG and JSON export, shareable URL for filter and query. Inconsistent and rejected links are marked visibly (style by `status`).
6. **Safety.** Own JavaScript only, CSP unchanged (no inline script). Property values are escaped. Long texts are cut and marked. `Run`, `Ingestion` and token-like data stay hidden for non-admin roles (allowlist of labels per role). Audit log line per query (`event=graph_query`, user, project, duration, no text of results).
7. **Docs.** A short user guide section in `docs/user/`.

Out: editing the graph, saved queries, multi-project views for non-admins, LLM-written Cypher (strategy `cypher` of T4.1 stays on the Ask page; an "open in graph" button is a follow-up).

## Acceptance criteria

- **Scope:** with two projects in Memgraph, a user of project A gets no node of B from `start`, `expand`, `path` and `query`, also with hand-written `MATCH (n) RETURN n`, `UNION`, subqueries and `OPTIONAL MATCH` (guard rejects or anchors it). A user without a role gets 403.
- **Read-only:** `CREATE`, `MERGE`, `SET`, `DELETE`, `CALL`, `LOAD CSV`, `;` chains and a caller-written `QUERY MEMORY LIMIT` are rejected. A bypassed guard (test seam) still fails in the read transaction.
- **Limits:** 600 matching nodes return 500 and `truncated=true`. A cartesian product hits the memory limit and shows a message. A 10 s query times out with a message.
- **Filter:** each filter returns only the selected labels and types. Unknown label or type gives 422. Filter values never appear in Cypher text.
- **XSS:** a node property with `<script>` renders escaped. CSP header is present. Templates have no inline script.
- **Roles:** labels hidden for non-admin roles do not appear in any response.
- **Move:** `uv run pytest services/dashboard services/query-service libs/python` stays green after the shared code move.
- **E2E:** `tests/e2e/test_console_graph.py` logs in as a user, loads the graph of the e2e project, filters to one artifact, expands one node, runs a path query and gets a write rejected.
- `ruff check`, `ruff format --check` green.
