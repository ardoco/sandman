## Goal

The budget has numbers. One command measures them on a scratch stack. A failed item gets a fix or a recorded follow-up. ADR-0014 states whether Memgraph passed.

## Scope

1. The budget below.
2. The harness `scripts/perf.py` and `make perf`.
3. A measured run and its results in this file.
4. Fixes for failed items, if the fix is small and local.
5. `mem_limit` and heap changes in `deploy/docker-compose.yml`, only with measured evidence.
6. An ADR-0014 amendment.

Out: live LLM runs, LLM enrichment and LiSSA (no credentials, cost), multi-user load tests, Grafana dashboards, the 30-day soak test (T5.5).

## Host assumption

- Server with at least 8 cores and 32 GB RAM (A-7). Limits in `deploy/docker-compose.yml` assume this host.
- The measured run may use a smaller machine. The results section names the machine. A budget item that depends on memory is compared with the limits of the stack, not with the host.
- Time budgets assume that no other heavy process runs on the host.

## Budget

| Id | Measure | Limit |
|---|---|---|
| `ingest-upload` | Time of `sandman ingest` for 1 000 files (check, archive, upload, ingestion record) | 60 s |
| `ingest-e2e` | Time from the start of ingest 1 until the workflow has ended (extraction, TLR, detection; includes the 10 s debounce) | 900 s |
| `ingest-extraction` | Duration of the step `extract-artifact-versions` for ingest 1 | 300 s |
| `ingest-tlr` | Duration of the steps `recover-trace-links` for ingest 1 | 480 s |
| `detection` | Duration of the step `detect-inconsistencies` for ingest 1 (detection latency) | 120 s |
| `incremental-e2e` | End to end time of ingest 2 (100 changed files) | 300 s |
| `query-bolt-p50` | p50 of the benchmark queries on the seeded KG, over Bolt | 20 ms |
| `query-bolt-p95` | p95 of the same queries | 250 ms |
| `query-http-p95` | p95 of five generic queries through `/v1/query/cypher` | 1 000 ms |
| `memgraph-memory` | Memgraph resident memory with 200 000 nodes | 4 096 MiB (half of the engine limit of 8 GiB) |
| `memgraph-bytes-per-node` | Tracked memory per node, all nodes and edges included | 16 KiB |
| `snapshot-size` | Size of one snapshot with 200 000 nodes | 1 024 MiB |
| `snapshot-time` | Time of `CREATE SNAPSHOT` with 200 000 nodes | 60 s |
| `container-memory` | Highest peak of any container during the run, as share of its `mem_limit` | 85 % |

Also required: no container is killed by the out-of-memory killer, and no workflow fails or times out.

## Decisions taken

- Limits are recommended defaults. No earlier measurement exists. A later task may tighten them after the soak test (T5.5).
- The file count is one project of 1 000 files, because NFR-15 allows 5 000 files per project and the ingest cost is expected to grow linearly.
- Detection latency is the duration of the detection step, not the time to the first inconsistency, because the workflow runs detection after TLR in one pass.
- Query latency is measured over Bolt (engine, plan and transfer) and over HTTP (adds guard and authorization). The NL query path is dominated by the LLM call, which this task does not measure.
- The 200 000-node KG is built from copies of the benchmark data. The copies have the same shape and indexes as real data, but the properties of the nodes are synthetic (`seed_kg.py`).
- The 85 % limit leaves room for peaks that the 3 s sampling can miss.
- Memgraph passes if the six Memgraph items pass. The fallback (ArcadeDB, then Neo4j) is not started in that case.
- The harness uses the scratch project `sandman-perf`. It never touches `sandman` and its volumes.

## Harness

- `make perf` runs `scripts/perf.py`. Options: `PERF_ARGS="--files 1000 --delta 100 --kg-nodes 200000 --reps 3 --keep"`.
- The harness copies `config/`, switches enrichment and LiSSA off in the copy and mounts it in the five services that read it.
- It starts the services with `docker compose -p sandman-perf`, publishes Memgraph on `127.0.0.1:17687` and the query service on `127.0.0.1:18080`, and removes project and volumes at the end (unless `--keep`).
- It writes `.work/perf/result.json` (override with `--out`) and prints one table. The exit code is 1 if an item fails.
- Unit checks: `uv run pytest scripts/test_perf.py`.
