# T5.3 Backup and restore scripts with drill

Milestone M5 · Effort S · Depends on: T0.11 · Risk: RK-16 (single server)

Status: done (2026-10-18)

## Context

`make backup` exited with 1 and no restore procedure existed. Stage 1 §11.5 names the data to protect and asks for a restore drill. Read first:
- `docs/stage-1-analysis-architecture.md` §11.5; `docs/stage-3-implementation-plan.md` (M5, RK-16); `adr/0014-graph-database.md`
- `deploy/docker-compose.yml` (volumes), `docs/user/operations.md` ("Data, logs, backup").

## Goal

An operator creates one archive of the running stack and restores it into an empty stack. A drill proves that the restored stack holds the same data.

## Scope

1. `scripts/backup.sh` and `scripts/restore.sh` (POSIX sh), with the shared helpers in `scripts/backup-common.sh`.
2. `make backup`, `make restore ARCHIVE=...` and `make backup-drill`.
3. The drill test `tests/e2e/test_backup_restore.py`.
4. The ops guide section in `docs/user/operations.md`.

Out: scheduled backups, off-host copy, encryption of the archive, Point-in-time recovery, NATS and Grafana data.

## What the archive holds

| Item | Source | Method |
|---|---|---|
| Graph | volume `memgraph-data` | `CREATE SNAPSHOT;`, then copy of the newest file in `snapshots/` |
| Workflow history | `orchestrator.db` in `orchestrator-data` | SQLite online backup (Python `sqlite3` backup API inside the service container) |
| Users, sessions, tokens | `users.db` in `query-data` | SQLite online backup |
| Dashboard state | `dashboard.db` in `dashboard-data` | SQLite online backup, only if the dashboard runs |
| Uploaded file contents | volume `artifact-store` | `tar` stream from the running `query-service` (read-only mount) |
| `manifest.json` | script | see below |
| `secrets.tar` | `deploy/secrets` | only with `--include-secrets` |

The archive does not hold these volumes:

| Volume | Reason |
|---|---|
| `nats-data` | Events are transient. The orchestrator recovers by polling the agents. |
| `gateway-data` | The gateway configuration comes from `deploy/gateway/config.json` and `deploy/secrets/gateway.env`. |
| `memgraph-log`, `otel-data`, `ollama-models` | Logs, telemetry and downloadable models. |
| `data/logs`, `data/llm-records` | Host directories. Copy them with normal file tools. |

## Consistency

- Memgraph: `CREATE SNAPSHOT;` writes a consistent snapshot while the database runs. The script copies only the newest file.
- SQLite: the backup API copies a consistent state of a live database. The script never copies a live `.db` or journal file.
- The script copies the artifact store first, the SQLite databases second and the graph last. The graph never refers to a file that the archive lacks.
- The copies are not one atomic point in time. Start the backup when no workflow runs. An ingestion that runs during the backup can leave workflow rows without matching graph data.
- The script stops with an error if `memgraph`, `orchestrator` or `query-service` is not running.

## Secrets handling

- The archive excludes `deploy/secrets` by default. A restored stack needs the original secrets from the operator's own store.
- `--include-secrets` adds them. The script prints a warning, and the archive has mode 0600. Store such an archive encrypted.
- `restore.sh` ignores `secrets.tar` unless `--with-secrets` is set. It then also needs `--force` if `deploy/secrets` exists.
- The Memgraph user comes from `deploy/secrets/memgraph.env` at first start. The snapshot holds no credentials.

## Manifest and checksum

- `manifest.json` records: `formatVersion`, `createdAt`, `project`, `gitCommit`, `kgSchemaVersion`, `memgraphImage`, `secretsIncluded`, `sqliteUserVersion` per database and all image references.
- The checksum is the SHA-256 of the archive in `<archive>.sha256`.

## Backup retention

- Archives go to `backups/` (git-ignored) or to `--out DIR`.
- The script keeps the newest 7 archives of the project and deletes older ones with their checksum files. Set `--keep N` or `BACKUP_KEEP`. Value 0 turns pruning off.

## Restore procedure

1. Check that `<archive>.sha256` exists and matches. Stop if not.
2. Refuse if `formatVersion` differs, the Memgraph image differs, or a schema version in the archive is newer than the repository.
3. Refuse if any container runs or any data volume holds files. Override with `--force`.
4. With `--force`, run `docker compose down`. This keeps the volumes.
5. Empty each data volume and unpack the archive items with owners and modes preserved.
6. Restore `deploy/secrets` only with `--with-secrets`.
7. Start the stack with `make up`. Memgraph recovers the snapshot at start.

The compose project is `COMPOSE_PROJECT_NAME`, default `sandman`.

## Drill

`make backup-drill` runs `tests/e2e/test_backup_restore.py` in the scratch project `sandman-drill`. The test never uses the project `sandman`. It does these steps:

1. Start Memgraph, NATS, orchestrator and query-service. Apply `init.cypher`.
2. Seed a project in the graph, a workflow row, and an artifact file.
3. Record the canonical KG export (`scripts/kg_canonical_export.py`), the SQLite dumps and the artifact checksums.
4. Run `scripts/backup.sh`.
5. Check the refusals: running stack, damaged checksum, wrong format version.
6. Remove the project with its volumes. Run `scripts/restore.sh` on the empty stack.
7. Start the services. Compare all recorded values with the original values.
8. Remove the scratch project and its volumes.

## Acceptance criteria

- `make backup` creates an archive and a checksum. `make restore` restores it.
- The drill passes on Docker.
- The archive holds no secrets unless `--include-secrets` is set.
- Restore refuses a damaged archive, a wrong format version and a non-empty stack.

## Open questions

1. Include `nats-data`. [No. Events are transient; the orchestrator recovers.]
2. Pause ingestion during the backup. [No. Document it; add `--quiesce` if the soak test (T5.5) shows inconsistencies.]
3. Encrypt archives. [No. Use disk or off-host encryption; the script only warns.]
4. Run the drill in CI. [No. Run it by hand each milestone (Stage 1 §11.5); it builds three images.]

## Results

Run on 2026-10-18 with Docker Desktop (Docker 29.7, Compose 5.5): `make backup-drill`, `3 passed in 71.25s`.

| Check | Result |
|---|---|
| Archive holds `manifest.json`, checksum file and no `secrets` entry | passed |
| Restore refuses a running stack, a damaged archive and format version 99 | passed |
| After `down -v` and restore, the canonical KG export (Project, 2 Elements, 1 relationship) is byte-identical | passed |
| The `orchestrator.db` dump (workflow `wf-drill`) and the `users.db` dump are identical | passed |
| The artifact checksum list is identical | passed |

Not tested: `--force` on a populated stack, `--include-secrets` and `--with-secrets`, the dashboard database, and a large graph.

Findings:
- The orchestrator keeps a read transaction open on `orchestrator.db` (rollback journal mode, `autocommit=False`). An outside writer cannot commit while the service runs. The backup API only reads, so the backup works. The drill seeds the database while the orchestrator is stopped.
- Memgraph recovers the snapshot at start in an empty data volume. The user from `memgraph.env` is created at first start.
