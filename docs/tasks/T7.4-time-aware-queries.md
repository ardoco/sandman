# T7.4 Time-aware queries

Milestone M7 · Effort M · Depends on: M4, T5.2 · Risk: RK-11 (graph growth)

Status: in progress.

## Context

All query strategies (ADR-0018) read the current state: `Artifact -[:CURRENT_VERSION]-> ArtifactVersion`. A user cannot ask what the project looked like after an earlier ingestion.

Read first:
- `contracts/kg/schema.yaml` (`Ingestion`, `ArtifactVersion`, `ACTIVATED`, `DELETED`)
- `docs/tasks/T5.2-retention-prune.md` (what retention removes)
- `services/query-service/src/sandman_query/nl.py`, `query.py` (`Runner.run`), `strategies/`

## Time fields in the KG

| Node | Field | Meaning |
| --- | --- | --- |
| `Ingestion` | `seq` | Per-project order. |
| `Ingestion` | `createdAt` | Time of the ingestion. |
| `Ingestion` | `sourceRevision` | Optional source revision, for example a Git commit. |
| `ArtifactVersion` | `ingestedAt`, `sourceRevision` | Same values for the ingestion that created the version. |
| `TraceLink` | `createdAt` | Creation time. No end time exists. |

`ACTIVATED` (Ingestion to ArtifactVersion) and `DELETED` (Ingestion to Artifact) give the history of every artifact.

## Goal

An optional `asOf` on `POST /v1/query/nl` makes every strategy read the artifact versions that were current after one ingestion.

## Design

1. Input: `asOf` (date-time) or `asOfRevision` (string). Send at most one.
2. The service picks one cutoff ingestion:
   - `asOf`: the newest ingestion with `createdAt` not after `asOf`.
   - `asOfRevision`: the newest ingestion with that `sourceRevision`.
3. The service replays `ACTIVATED` and `DELETED` edges of all ingestions up to the cutoff `seq`. The result is one version id per artifact that existed at that point.
4. The version ids are bound as the parameter `$versionIds`. All reads run in one read transaction.
5. `Runner.run` rewrites the anonymous pattern `(:Artifact)-[:CURRENT_VERSION]->(:ArtifactVersion)` to `UNWIND $versionIds AS asOfVid ... (:ArtifactVersion {id: asOfVid, projectId: $projectId})`. The rewritten query passes the guard again.
6. The context variable `AS_OF` carries the version ids from `NlService.answer` to `Runner.run`. The strategy functions keep their signatures. This covers `cypher` (intents and LLM queries), `graphrag`, `explore` and `auto`.
7. The response gets `asOf`: `{ingestionSeq, ingestedAt, sourceRevision?}`.

## Limits and errors

| Case | Result |
| --- | --- |
| Both `asOf` and `asOfRevision` | 422 |
| Time or revision is older than the oldest ingestion that retention (T5.2) kept | 422, message names retention and the oldest available ingestion time |
| Revision unknown or pruned | 422 |
| `asOf` before the first ingestion of a project that kept all ingestions | Empty state, no rows |
| Intent or generated query that does not read `CURRENT_VERSION` | 422, `asOf` cannot apply. A generated query gets the error as a repair hint. |

Trace links and inconsistencies keep no end time. Under `asOf` the strategies show links as active now, limited to the elements that existed at the cutoff. The response carries a warning for this.

## Out of scope

- `asOf` on `/v1/query/cypher`, exports and the console.
- Time filter on trace links and inconsistencies (needs new KG fields).

## Acceptance criteria

- Replay of partial ingestions, a changed version and a deleted artifact gives the right version ids.
- `asOf` older than the retained history gives a 422 that names retention.
- An intent query under `asOf` runs with `$versionIds` and without `CURRENT_VERSION`.
- The OpenAPI contract and `docs/user/querying.md` describe the new fields.
- `uv run pytest services/query-service`, ruff and mypy show no new problem.

## Test plan

- Unit tests of the replay and of the query rewrite (no KG).
- API tests with the fake reader: intent, retention error, conflicting inputs.
- Not run here: Traverse-backed check of the replay query and the rewritten templates (Docker needed).
