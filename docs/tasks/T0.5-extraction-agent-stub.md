## Context

The extraction-agent (Python) owns `Project`, `Ingestion`, `Artifact`, `ArtifactVersion`, `Element` nodes and handles artifact intake. In M0 its intake, versioning and plugin routing are real, but extraction itself is trivial. Read first:
- `docs/stage-1-analysis-architecture.md` §4.1–4.2 (schema, versioning, continuous use), §5.2
- `docs/stage-2-contracts-repository.md` §1.6 (`config/extraction/plugins.yaml`), §4.2 (stub behavior), §5 (walking skeleton)
- `contracts/openapi/extraction-agent.yaml`, `contracts/agent-cards/extraction-agent.json`, `contracts/skills.schema.json` (`ExtractArtifactVersions*`, `PluginExtract*`), `contracts/events.schema.json`, `contracts/kg/schema.yaml`, `contracts/kg/init.cypher`, `contracts/openapi/plugin-http.yaml`

## Goal

`services/extraction-agent` (package `sandman_extraction`): a FastAPI app exposing the REST API and the A2A skill `extract-artifact-versions` (mounted under `/a2a`, Agent Card at `/.well-known/agent-card.json`), using `sandman_agent`.

## Scope

1. Startup: run `contracts/kg/init.cypher` idempotently; `ensure_stream()`; `/healthz`, `/readyz` (Memgraph, NATS reachable).
2. `PUT/GET /v1/projects/{projectId}`.
3. `POST /v1/projects/{projectId}/ingestions/check` and `POST /v1/projects/{projectId}/ingestions` exactly per OpenAPI:
   - validate the manifest (relative paths, no `..`, ≤ 20 000 files); extract the archive (tar.gz/zip) safely (reject absolute paths, symlinks, path traversal, total size > configurable limit); verify the sha256 of every stored file;
   - `kind` by first matching `kindRules` glob, else `other`; ids via `stable_id` (`art`, `ver`, `ing` = stable_id(projectId, seq) with `seq` = `Project.ingestionSeq` + 1);
   - one transaction (Stage 1 §4.4): increment `Project.ingestionSeq`, create the `Ingestion` node; per path whose content differs from the current version: create the version if it does not exist, otherwise **re-activate** it; `ACTIVATED` edge, move `CURRENT_VERSION`, clear `deletedAt`; `mode=full` → set `deletedAt`, remove `CURRENT_VERSION` and add a `DELETED` edge for missing paths. No `PREVIOUS` edges;
   - idempotency is state-based: if nothing changed, the `Ingestion` is stored with empty lists and **no event** is published;
   - set `Ingestion.eventPublished = true` after the publish ack; at startup and before every intake, re-publish events of unpublished ingestions with a deterministic event id (uuid5 of the ingestion id), so a request retried after a failed publish never loses the event;
   - otherwise publish `sandman.ingestion.completed` (await ack); respond `201` with the `Ingestion` (incl. `seq`, `reactivatedVersionIds`); the actor comes from `X-Sandman-Actor` (trusted forwarder `query-service`) or `service:<caller>`;
   - callers are authenticated against the hash file (`SANDMAN_SERVICE_VERIFY_FILE`).
4. Skill `extract-artifact-versions` (created and re-activated versions alike): `RunRecorder.cleanup_stale(inputKey)`, `start`; stub extraction per Stage 2 §4.2 (one Element per file with label by kind; Markdown requirements → one `Requirement` per `## <ID> <title>` heading); explicit-reference matcher with `config/extraction/plugins.yaml` `explicitReferences.patterns` (creates `TraceLink` with `approach=explicit-reference`, `confidence=1.0`, `status=candidate`, `linkType=relates`, `active=true`); route artifacts matching plugin `match` rules to plugins through `A2aPluginClient` (inbound token from `tokenFile`; input incl. the project's `llmPolicy`), validate and write their elements/relations/references (resolve `ElementLocator` against elements of this run and current versions); plugin failure → file-level fallback, run `partial`; **one transaction per artifact version** that replaces the version's element set (elements not produced again lose `HAS_ELEMENT`; element properties are overwritten with `SET`) (element `runId` set only on create, so `cleanup_stale` never deletes pre-existing elements) and deactivates and recreates the explicit-reference links found in this version (re-resolving references when the *referenced* artifact changes stays open, review R-014); return `SkillResult` with the output and the `sandman.extraction.completed` event (the library publishes it).
5. Config: `config/extraction/plugins.yaml` (create the default file used by the walking skeleton, Stage 2 §1.6).

Out: real extractors (M1), LLM enrichment (M1), retention/prune (M5).

## Acceptance criteria

- Schemathesis (or equivalent) run against `contracts/openapi/extraction-agent.yaml` passes for the implemented operations. Every published event and skill result validates against the contracts.
- Integration tests (Testcontainers Memgraph + NATS):
  - two full ingestions of a fixture where one file changes and one disappears → exactly one new version, one `deletedAt`, correct `CURRENT_VERSION`;
  - re-sending the same ingestion → no new version nodes, a new `Ingestion` with empty lists, no event;
  - publish failure after the KG commit, then the client retries → the event is published exactly once (deterministic id);
  - revert A→B→A and delete-then-re-add of a file → no constraint violation, the earlier version is current again, `deletedAt` cleared, listed in `reactivatedVersionIds`, event published;
  - re-extraction of a version with fewer elements → the dropped elements are no longer current;
  - archive path traversal is rejected with 400/422;
  - extraction of the `mini` fixture creates three `Requirement` nodes and an explicit link REQ-1 → `MediaCacheTest`;
  - plugin stub failure leads to fallback elements and status `partial`;
  - running the skill twice with the same input does not duplicate facts.
- Element/link ids are deterministic (the test computes them with `stable_id`).

## Constraints

Python 3.13, `sandman_agent` only (no direct SDK use outside the library except FastAPI). No LLM calls. All Cypher parameterized; labels from a fixed enum.
