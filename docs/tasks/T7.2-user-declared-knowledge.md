# T7.2 User-declared knowledge file

Milestone M7 · Effort M · Depends on: M1, M2 · Risk: RK-9 (injection in declared text), RK-10 (project scope), S-3, S-4 (below)

Status: open, spec ready (2026-10-20). Open questions have bracketed defaults, marked "decided: default". Implementation can start without the user.

## Context

Users can add knowledge only through explicit references in documents (`explicitReferences` patterns, R-014). They cannot declare an element that no artifact contains. They cannot give an element a second name. They cannot state a trace link that no approach finds.

The paper asks for manual augmentation of the knowledge base in a structured format (paper §3.1, p. 489). See `docs/notes/paper-review-3774748.3795871.md` §3.6 (gap #6).

Facts from the code:
- `scan` already includes `sandman-knowledge.yaml`. It is not a dot-file and not `sandman.yaml`.
- `ingest()` checks every archive entry against the manifest hash before it stores the blob. This is the place for the validation.
- A blob with a known hash is not in the archive. It was validated when it first arrived.
- `_re_resolve` computes the desired explicit links of the whole project, then deactivates stale links and activates missing links in one transaction.
- The tlr-agent never deactivates or prunes links of approach `explicit-reference`. The review route answers 409 for them.

## Goal

A project holds an optional file `sandman-knowledge.yaml` at the repository root. The file declares elements, aliases and trace links. Intake validates the file against a JSON schema and rejects an invalid file. The extraction-agent turns the file into elements and into links with approach `user-declared`. The links follow the current versions of their endpoints after every ingestion.

## Scope

In:
1. JSON schema `contracts/knowledge.schema.json` for the file.
2. Validation at intake. An invalid file rejects the ingestion.
3. Format `sandman-knowledge` in the built-in extractor: declared elements and alias elements.
4. Resolution of declared links after every extraction run, approach `user-declared`.
5. Ownership extension: the extraction-agent writes `user-declared` links. The tlr-agent treats them like `explicit-reference` links.
6. User doc `docs/user/knowledge-file.md` with one full example.

Out:
- A console editor for the file. Sandman never writes the file (PR-D8).
- Declared negative links (a user "rejects" a link in the file). Use the T6.1 review instead.
- Use of aliases in TLR approaches or detectors (backlog).
- Declared relations (`CONTAINS`, `DEPENDS_ON`) between elements.
- Knowledge files in other paths or more than one file per project.

## File format

```yaml
version: 1
elements:
  - id: payment-provider              # [a-z0-9][a-z0-9-]{0,63}, unique in the file
    label: ModelElement               # common.schema.json ElementLabel
    kind: component                   # [a-z][a-z0-9-]{0,31}
    name: External Payment Provider   # 1..200 characters
    text: Third-party service ...     # optional, at most 4000 characters
aliases:
  - element: model/mediastore.repository#_qxAiILg7EeSNPorBlo7x9g
    names: [Media Store, MS]          # 1..20 names, each 1..200 characters
links:
  - source: docs/architecture.md#sec:overview
    target: src/main/java/org/example/Facade.java#org.example.Facade
    type: documents                   # common.schema.json LinkType
    rationale: Reviewed in design meeting 2026-10-01.   # optional, at most 2000 characters
```

Element references (`element`, `source`, `target`) have one of two forms:
- `<artifact path>#<localKey>`: an element of the current version of the artifact with this path in the same project.
- `decl:<id>`: an element of `elements` in this file.

Limits: file at most 1 MiB, at most 5000 elements, 5000 aliases and 20000 links. No YAML anchors and no YAML aliases.

## Behavior

### Intake validation (`ingest.py`)

1. Constant `KNOWLEDGE_PATH = "sandman-knowledge.yaml"`.
2. In `ingest()`, after the hash checks and before `store.put`: if the archive holds `KNOWLEDGE_PATH`, validate it.
3. Validation steps, in this order:
   - size at most 1 MiB, else 400
   - UTF-8, else 400
   - `yaml.scan` tokens: an anchor or alias token gives 400
   - `yaml.safe_load`
   - JSON schema `knowledge.schema.json` with `jsonschema` (already a dependency of `sandman-agent`)
   - semantic checks: unique `id`; every `decl:<id>` reference names an element of the file
4. On error, answer 400 `INVALID_INPUT: sandman-knowledge.yaml: <JSON pointer>: <message>`. Store no blob. Create no ingestion.
5. In the transaction, `kind_of` is not used for `KNOWLEDGE_PATH`. The artifact gets kind `other` and format `sandman-knowledge`.

### Extraction (`services/extraction-agent/src/sandman_extraction/knowledge.py`)

`builtin.extract` dispatches format `sandman-knowledge` to `knowledge.extract(path, content)`. It returns:
1. The file element (label `TextUnit`, kind `file`, as `stub_elements` does).
2. One element per declared element: `localKey = decl:<id>`, label, kind, name, text from the entry. `contentHash` = sha256(JCS(entry)). Parent: file element.
3. One alias element per alias entry: label `TextUnit`, kind `alias`, `localKey = alias:` + the first 12 hex characters of sha256(element reference), name = first name, `aliases` = JSON array of all names. `contentHash` = sha256(JCS(entry)).

The extractor parses the file again. Intake already validated it. If parsing fails anyway, the run fails for this artifact with a warning.

### Link resolution (`extract.py`)

Add `_resolve_declared(pid, rid)` next to `_re_resolve`. Call it at the end of every extraction run of a project that has a current `sandman-knowledge` artifact. Element ids change with every new artifact version, so every run can move link endpoints.

1. Read the current knowledge artifact version and its blob from the store.
2. Build the links: every `links` entry, and one `relates` link from each alias element to its `element`.
3. Resolve each reference:
   - `decl:<id>`: the element `<knowledge artifact id>#decl:<id>`.
   - `<path>#<localKey>`: the element with key `stable_id("art", pid, path) + "#" + localKey` in a current version.
4. An unresolved reference gives a run warning `knowledge: unresolved <reference>`. The link is skipped.
5. Link id: `tl_ = stableId("user-declared", "1", configHash, sourceId, targetId)`. Confidence 1.0. Status `confirmed`. Rationale from the entry.
6. Compare with the active `user-declared` links of the project. Deactivate stale links and activate missing links in one transaction, as `_re_resolve` does.
7. If the knowledge artifact is deleted, the desired set is empty. All `user-declared` links become inactive.

### tlr-agent changes

1. Replace the single constant `EXPLICIT_REFERENCE` with a set `EXTRACTION_OWNED = {explicit-reference, user-declared}` in `LinkStore`. Use the set at all four places and in `PruneTraceLinks`.
2. `ApproachesRoute` answers 409 for a review of a `user-declared` link. The message says: change `sandman-knowledge.yaml`.

### Effect on detectors

`ardoco-id` and `stub-untraced` read active, non-rejected links of all approaches. A declared link removes a finding when it adds the missing link. Declared elements live in an artifact of kind `other`. Detectors with `modelKinds: [architecture-model]` do not see declared model elements.

## Decisions taken

| Id | Question | Decision |
|---|---|---|
| D-1 | Where is the file? | Repository root, fixed name `sandman-knowledge.yaml`. One file per project. |
| D-2 | Is the file an artifact? | Yes, kind `other`, format `sandman-knowledge`. It gets versions, provenance and deletion like other artifacts. |
| D-3 | Who writes `user-declared` links? | The extraction-agent. It owns the file content, and it already resolves explicit references (R-014). This extends the `TraceLink` co-owner rule. |
| D-4 | Reference form | Artifact path plus `localKey`. Users know paths, not artifact ids. The artifact id is `stable_id("art", projectId, path)`. |
| D-5 | Where do aliases live? | On alias elements in the knowledge artifact, with a `relates` link to the target. The extraction-agent writes one artifact version per transaction, so it does not change elements of other artifacts. |
| D-6 | Review of `user-declared` links | Not allowed (409), as for `explicit-reference`. The file is the source of truth. |
| D-7 | LLM | None in this task. |

## Acceptance criteria

1. Contract commit first. Conformance vectors and both libraries are green.
2. Intake answers 400 and stores nothing for each case: file larger than 1 MiB, invalid UTF-8, YAML anchor, YAML syntax error, schema error, duplicate `id`, unknown `decl:` reference. The message holds the JSON pointer for schema errors.
3. A valid file gives one artifact of kind `other` and format `sandman-knowledge`. Kind rules of the manifest do not change this.
4. Unit tests of `knowledge.py`: declared element keys `decl:<id>`, alias elements with `aliases`, content hashes stable across key order in the YAML.
5. Memgraph integration test:
   - a declared link between a document section and a code type is active with status `confirmed` and confidence 1.0
   - after a new version of the code artifact, the link points to the new element id; the old link is inactive
   - an unresolved reference gives one run warning and no link
   - after deletion of the knowledge file in a full snapshot, no `user-declared` link is active
6. tlr-agent tests: a TLR run does not deactivate `user-declared` links; prune keeps them; a review answers 409.
7. End-to-end test on the mini snapshot: a declared `documents` link from a sentence to an undocumented model element removes the `undocumented-model-element` finding of `ardoco-id` in the next detection.
8. Security test (T4.4 pattern): a reference to a path of another project resolves to nothing.
9. The replay determinism test (T1.6) stays green.

## Risks

- RK-9: declared `text` and `rationale` enter LLM prompts of other features. Apply the same escaping and prompt fences as for other text.
- RK-10: a reference resolves only inside the project. Every query has `projectId`.
- S-3 (new): YAML parsing of user input. Mitigation: size cap before parsing, no anchors or aliases, `safe_load`, schema with bounded strings and arrays.
- S-4 (new): users declare wrong links, and the links hide real findings. Mitigation: the console shows the approach `user-declared` on each link. The export keeps the approach column.

## Constraints

Shared constraints of plan §5 apply. Do not add a dependency; `pyyaml` and `jsonschema` come from `sandman-agent`. Sandman never writes `sandman-knowledge.yaml` (PR-D8).

2. Invalid file: reject the ingestion or skip the file? [Reject the whole ingestion with 400. Skipping would hide the error from the user, and the GitHub Action fails visibly on 400.] decided: default
3. Validate in the CLI before upload? [No. The server answers fast with the same message. A local check would duplicate the schema logic.] decided: default
4. Allowed labels for declared elements? [All labels of `ElementLabel`, including `Decision` once T7.1 is done.] decided: default
