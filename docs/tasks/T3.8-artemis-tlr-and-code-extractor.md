## Context

ArDoCo PR #186 ("make inconsistency great again", merge `21ef682`, 2026-11-12, `2.2.0-SNAPSHOT`) adds the module `tlr/stages-tlr/artemis`. It also changes the code extractor. SANDMAN uses neither today. This task brings both into SANDMAN. T3.9 makes the result the default.

## Findings (2026-11-12, source of `21ef682`)

Verified in the upstream source (not run):

1. ArTEMiS TLR works in two stages: `ArtemisNer` (LLM named-entity recognition on the text) and `ArtemisConnectionGenerator`. A strategy list selects the target: `ComponentArtemisNerStrategy` (SAD to SAM), `ClassArtemisNerStrategy` and `DatafileArtemisNerStrategy` (SAD to code). The old `connection-generator-ner` is gone.
2. Three runners exist in `pipeline-tlr`:
   * `Artemis`: strategies on an architecture model and/or a code model.
   * `ArtemisInTransArC`: ArTEMiS replaces SWATTR for SAD to SAM. ArCoTL (SAM to code) and the transitive SAD to code recovery stay.
   * `ArtemisInExArch`: ExArch (LLM) builds the SAM. ArTEMiS links SAD to SAM. ArCoTL and the transitive recovery stay.
3. `TraceLinkCombiner` reads `ArtemisConnectionStates` with `ArtemisTarget(ARCHITECTURE_WITH_COMPONENTS, COMPONENT)`. If SWATTR connection states are also present, SWATTR wins. The ArTEMiS SAD-SAM-code runners must therefore not run SWATTR.
4. `LargeLanguageModel` is an enum. `ArtemisNer.get`, `ArtemisNerAgent` and `ArtemisNerInformant` take it. There is no `ChatModel` injection point. `ArtemisRunner` of the inconsistency agent bridges this with `GatewayStage` and `ArtemisChatModel`. The TLR side needs the same bridge.
5. `code-traceability` now depends on the module `artemis`. The `tlr-agent` classpath grows. `ModuleRulesTest` and `THIRD-PARTY.md` must be checked.
6. Code extractor changes:
   * `AllLanguagesExtractor` registers `Python3Extractor` and `CppExtractor` next to `JavaExtractor` and `ShellExtractor`.
   * `CodeExtractor.extractCodeFiles` builds `CodeFile` entries. One entry per compilation unit, plus one entry per other file that Magika finds under the root (`predictFileTypesFromFolderRecursively`).
   * `CodeModelDto` has the new component `codeFiles`. The ACM JSON gets a `codeFiles` array.
   * `ProgrammingLanguage.PYTHON3` is now `PYTHON`. The enum has about 60 values, each with file extensions.
   * `CodeModel.getClasses()` and `CodeItemRepository.getAllClassUnits()` are new.
   * `CodeConfiguration.metamodel` is `@Nullable`.
7. SANDMAN impact of finding 6:
   * `code-extractor-ardoco` (`CodeService`, `ElementMapping`, `Limits`) must handle Python and C++ units, `codeFiles`, and Magika over more files (time, memory, `tmp_magika*.tmp` purge).
   * `ElementMapping` line 84 maps only `ProgrammingLanguage.JAVA` units today.
   * The classifier rules decide which files reach the extractor. Non-source files appear in `codeFiles` only if SANDMAN stages them.
   * `ardoco-shadow` and `ArdocodeApproach.decode` read the ACM. The shadow must match the new DTO (T3.7 step 2).

Unknown:

* U1: Whether `Artemis` class and datafile strategies give usable results on a SANDMAN-staged tree (it contains only the files that the classifier staged).
* U2: Whether `ArtemisInExArch` can use the gateway for both LLM roles (`llmForExArch` and `llmForNer`). `ArdocodeApproach` already bridges ExArch.
* U3: Whether the Python and C++ extractors are deterministic across runs (`IdentifierProvider.reset`).
* U4: Whether the ACM size grows enough to break the F-1 shared code model budget (T5.4).

## Goal

SANDMAN offers these TLR approaches: `artemis` (SAD to SAM), `artemis-class` and `artemis-datafile` (SAD to code), `artemis-transarc` and `artemis-exarch` (SAD to SAM to code). The code extractor supports Python, C++ and `codeFiles`. All run through the LLM gateway.

## Decisions (defaults taken 2026-11-12)

| # | Question | Decision |
|---|----------|----------|
| 1 | LLM injection | Bridge with the gateway `ChatModel` (as `ArtemisRunner`). Ask upstream for `ChatModel` injection. Drop the bridge when it lands. |
| 2 | Approach ids | `artemis`, `artemis-class`, `artemis-datafile`, `artemis-transarc`, `artemis-exarch`. Version `<ardoco.version>+<sha>.a1`. |
| 3 | Approach with no LLM route | `ApproachUnavailableException`, as `lissa` does. T3.9 adds the fallback to `transarc`. |
| 4 | Non-source files | Stage files of `kind: code` and `kind: build` (new, see step 3) so that `codeFiles` and datafile linking work. Limits stay in `Limits`. |
| 5 | Link type for class and datafile links | Reuse the existing SAD-to-code link type. Add `target` (`component`, `class`, `datafile`) to the link evidence. |
