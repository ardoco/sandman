# T0.2 Python agent library `sandman_agent`

Milestone M0 · Effort L · Depends on: T0.1 · Blocks: T0.5, T0.8, T0.9, T0.10

## Context

All Python SANDMAN services (orchestrator, extraction-agent, query-service, plugin stubs) use one small library (`llm-replay`, T0.13, is standalone) instead of an agent framework. Read first:
- `docs/stage-1-analysis-architecture.md` §9 (API sketch), §3.3 (A2A convention), §3.2 (events)
- `docs/stage-2-contracts-repository.md` §1.2–1.4, §1.7 (environment variables)
- `adr/0010-minimal-agent-library.md`, `adr/0002-use-a2a-for-agent-commands.md`, `adr/0012-pluggable-approaches-and-detectors.md`
- `contracts/common.schema.json`, `contracts/events.schema.json`, `contracts/skills.schema.json`, `contracts/conformance/vectors.json`

## Goal

Implement `libs/python/sandman-agent` with the public API from Stage 1 §9.2, so that services can be written as plain async Python.

## Scope

Modules and required behavior:

| Module | Behavior |
|---|---|
| `config` | `Settings` from the `SANDMAN_*` environment variables (Stage 2 §1.7); `*_FILE` variables are read from files; missing required values fail at startup with a clear message. |
| `ids` | `stable_id(prefix, *parts)`, `section_local_key(headings, occurrences)`, `sentence_local_key(section_key, text, occurrence)`, `fingerprint(type, detector_id, involved_keys)` (detector id without version; keys sorted byte-wise by UTF-8), `new_run_id()`, `new_workflow_id()` exactly as in the vectors. |
| `contracts` | Loads schemas from `SANDMAN_CONTRACTS_DIR` (default: repository `contracts/`) with a `referencing` registry; `validate(def_ref, instance)` raises `ContractError` with all messages. |
| `llm` | Data classes per §9.2; `LlmClient` protocol; `OpenAiLlmClient` (official `openai` SDK, `base_url` = `SANDMAN_LLM_BASE_URL` (the `llm-replay` proxy) + key from settings, maps `response_schema` to `response_format` json_schema, sets `user=run_id`, forwards `traceparent`); `ModelSelector` reading `models.yaml` and enforcing `local-only` (only `*-local` routes and the `SANDMAN_LLM_LOCAL_KEY_FILE` key). No record/replay and no tool loop in the library (D-3, D-7). |
| `events` | `Event`, `EventPublisher` (validates against `events.schema.json`, sets `Nats-Msg-Id`, awaits the JetStream ack, retries 3× with backoff, then raises; used by the `a2a` module for completion events and by services for other events), `EventConsumer` (durable pull, ack on success, nak with delay on exception), `ensure_stream()` with the stream config from Stage 2 §1.4. |
| `kg` | `KgClient` (`neo4j` async driver; `read` uses `execute_read`, `write` uses `execute_write`); `RunRecorder` (`start`, `complete`, `fail`, `cleanup_stale(input_key)` which deletes facts with `runId` of non-completed runs for the same `inputKey` and marks those runs `failed`). |
| `artifacts` | `ArtifactStore.put(project_id, bytes) -> (sha256, storage_uri)`, `path_for(uri)`, `open(uri)`. |
| `a2a` | `Skill` protocol (`run` returns `SkillResult(output, event_type, event_data)`; the event is `None` for plugin skills, which publish nothing), `SkillContext`, `serve(agent_card_path, skills, settings) -> ASGI app` using `a2a-sdk` (pin the version; JSON-RPC binding, Starlette); implements the SANDMAN invocation convention (`sandman.skill` metadata, one `data` part, result artifact `result`, `SkillError` in status metadata `sandman.error`, REJECTED on invalid input or unknown skill, FAILED on output schema violation without publishing); on valid output publishes the single completion event with `causationid` = `messageId` of the A2A request and `correlationid` = workflow id, awaits the ack, then completes the task; bearer-token check against the hash file `SANDMAN_SERVICE_VERIFY_FILE` (agents) or against `SANDMAN_PLUGIN_INBOUND_TOKEN_FILE` (plugin mode, no NATS needed); `sandman.actor` accepted only from the `orchestrator` caller; the completion event's `causationid` is the request's `messageId`; `A2aClient.submit/get/cancel/card` with `returnImmediately`, sending the service's own token. |
| `plugins` | `A2aPluginClient` (extraction plugins; HTTP variant cut until needed, D-7), presenting the plugin's inbound token from the plugin configuration, returning validated `PluginExtractOutput`. |
| `auth` | Token verification against `SANDMAN_SERVICE_VERIFY_FILE` (sha256 of the presented token → caller name) for FastAPI (`require_service`, which rejects `plugin:<id>` callers unless the route explicitly allows them — only the query-service's read routes do), `trusted_actor` that accepts `X-Sandman-Actor` only from the `query-service` caller; own token from `SANDMAN_SERVICE_TOKEN_FILE`. |
| `telemetry` | JSON logging with the fields from Stage 2 §1.7, optional file sink (`SANDMAN_LOG_FILE`), contextvars for `workflowId/taskId/runId/projectId/actor`; OTel tracer setup when `OTEL_SDK_DISABLED=false`. |
| `testing` | `ScriptedLlmClient`, `InMemoryEventBus`, `run_conformance(vectors_path)`. |

The `llm-replay` proxy (T0.13) is a separate service; the library contains no cassette code.

Out: any service-specific logic; prompt templating; LLM retries (gateway's job); record/replay (T0.13); tools and tool loop (M6).

## Interfaces

Public names exactly as in Stage 1 §9.2. Export them from `sandman_agent/__init__.py`.

## Acceptance criteria

- `tests/conformance/test_python_conformance.py` runs the `stableId`, `sectionKey`, `sentenceKey`, `fingerprint`, `eventEnvelope` and four `skillInvocation` cases (served by an in-process test skill) in `contracts/conformance/vectors.json` and passes.
- Unit tests cover: config file secrets, model selector policy (route and key), token verification and forwarder rules (a token of another service is mapped to that service, `sandman.actor` from a non-orchestrator is ignored), completion event published only after valid output and before `COMPLETED`, publisher retry and raise, consumer nak on exception.
- Integration tests (Testcontainers, Memgraph `memgraph/memgraph:3.13.1` and `nats:2.15.0-alpine`): `KgClient.write` then `read`; writing in a read transaction fails; `RunRecorder.cleanup_stale`; publish → consume round trip with deduplication of a re-published event id.
- A2A round trip test: `serve()` app + `A2aClient` in the same test (httpx ASGI transport), states `SUBMITTED → COMPLETED` and `REJECTED`.
- `mypy --strict` and ruff pass; public API documented with docstrings (one line each).
- Record any deviations from the A2A JSON shapes assumed in the Agent Cards (V-19) in `docs/notes/a2a-python.md`; do not edit `contracts/`.

## Constraints

No agent frameworks. Dependencies: `a2a-sdk[http-server]`, `openai`, `neo4j`, `nats-py`, `jsonschema`, `referencing`, `pyyaml`, `httpx`, `opentelemetry-sdk` (+ OTLP exporter). Nothing else without justification in the PR description.
