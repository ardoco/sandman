# T1.12 Explicit-link re-resolution

Milestone M1 (follow-up) · Effort S · Depends on: T1.3 (done) · Blocks: – (M2 evaluation exports read explicit links) · Resolves review item R-014

Status: done (2026-10-10)

## Context

Explicit links run from a referenced `Requirement` to the referring element (R-013, T1.3). Both endpoints are per-version element ids, so a link stops being current when the requirements file gets a new version (`contracts/kg/schema.yaml` `conventions.current`). Nothing re-creates it: the matcher runs only over the versions of the current extraction run. Read first:
- `docs/stage-4-review.md` R-014 (accepted 2026-10-09), R-013, R-028 (`tl_` derivation), R-015 (active facts)
- `docs/stage-1-analysis-architecture.md` §4.2 (versions, current state), §5.2 (explicit references), §6 (rules)
- `docs/tasks/T1.3-requirements-extractor.md` (matcher rules, open question 5)
- `contracts/kg/schema.yaml` (`Element`, `TraceLink` co-owner rule, `conventions.current`, `PRODUCED`), `contracts/skills.schema.json` (`ExtractArtifactVersionsOutput`)
- Code: `services/extraction-agent/src/sandman_extraction/extract.py` (`match_references`, the target lookup and `_write_links` in `_extract`, link id `stable_id("tl", APPROACH, APPROACH_VERSION, config_hash, referenced, referrer)`); `tests/e2e/test_walking_skeleton.py` (REQ-1 → `MediaCacheTest`, revert step).

## Goal

After every ingestion, each current element that mentions a requirement id has a current explicit link to the current `Requirement` with that id, whichever artifact changed.

## Scope

1. **Stored references.** The extractor stores the unresolved reference texts of an element on the element: additive property `Element.references` (list of `{text, linkType}`), written with the element in the same transaction. Contract PR first (additive, `contracts/kg/schema.yaml`, new contract version).
2. **Re-resolution step.** In `extract-artifact-versions`, after the element and link writes: when the run created, reactivated or deleted any version that holds `Requirement` elements, resolve `references` of all current elements of the project against the current requirements (same rules as T1.3: `Requirement` targets only, match by `localKey`, no self-link, same link id and `PRODUCED` activation as in `_extract`). Cost: one read of elements with `references`, one batched write per 5 000 links.
3. **Output.** `explicitLinkCount` counts all links written in the run, including re-resolved ones. No new event or skill.
4. **Walking skeleton.** Add a step to `tests/e2e/test_walking_skeleton.py`: change only the requirements file; the link REQ-1 → `MediaCacheTest` is current again afterwards.

Out: LLM-based reference detection, per-project patterns (T1.3 open question 6), re-resolution for plugin-produced elements beyond what `explicitReferences` already gives them (they store `references` the same way), pruning of old non-current links (T5.2).

## Acceptance criteria

- Ingest requirements v1 and a doc that mentions REQ-1; ingest requirements v2 only (REQ-1 text changed): the doc sentence has a current link from the v2 `REQ-1`; the v1 link is not current.
- Delete REQ-1 in v3: no current link remains for it, and no error. Revert to v2 content: the link is current again.
- Running the skill twice creates no duplicate links (same `tl_` ids).
- An element without `references` and an ingestion without requirement changes cost no extra write (no re-resolution query writes anything).
- `explicit-reference` links stay owned by the extraction-agent (co-owner rule); tlr-agent cleanup is untouched.
- `uv run pytest services/extraction-agent`, `make lint` and the e2e job are green; contract validation passes.

## Test plan

Unit: reference storage per element, resolution against current requirements, deletion and revert, idempotency. Integration (Testcontainers Memgraph): the three ingestion sequences above on a small graph. E2E: the new walking-skeleton step.

## Constraints

Python 3.13, uv only, all Cypher parameterized, no new dependencies. Contract change only as an additive PR (`Element.references`), merged before the extractor change. Keep a handoff note `.work/T1.12.md` (CLAUDE.local.md).

## Implementation notes and deviations

- Re-resolution is gated on the ingested artifacts holding `Requirement` versions. Deletions trigger no extraction, so it is not gated on them.
- The `ing` and `tl_` derivations stay positional (additive rule, R-028).
