# T1.4 PDF/DOCX extraction via Docling, offline prefetch

Milestone M1 · Effort M · Depends on: T0.5 (done); T1.1 (`builtin.py`, Markdown extractor, golden harness) · Blocks: none

## Context

Documentation may arrive as PDF or DOCX (Stage 1 A-2). Docling converts both to a structured document; the extraction-agent runs without egress, so Docling's models are downloaded at image build time (Stage 1 A-8, V-13). Docling is untrusted-input parsing with heavy native code and must run with limits (R-029). Read first:
- `docs/stage-1-analysis-architecture.md` §5.2 (built-in extractors, failure modes), A-2, A-8, V-13; `docs/stage-2-contracts-repository.md` §2.2 (key libraries: `docling`), §3.1 (Dockerfile sketch with `python -m sandman_extraction.prefetch` and `/home/sandman/.cache/sandman-models`), §4.2
- `docs/stage-4-review.md` R-029 (Docling in a subprocess with limits), R-025 (which rendering ArDoCo sees)
- Code: `services/extraction-agent/src/sandman_extraction/extract.py` (`ExtractSkill._extract` inner `stub()` is synchronous and reads the blob via `svc.store.open`; `svc.store.path_for(uri)` gives the file path), `builtin.py` and `text.py` (T1.1), `services/extraction-agent/Dockerfile` (current: no prefetch step), `services/extraction-agent/pyproject.toml`.

## Goal

PDF (`pdf`, `*.pdf`) and DOCX (`docx`, `*.docx`) artifacts produce the same element structure as Markdown (file, sections, sentences with content-based keys and `sentenceIndex`), converted by Docling in a resource-limited subprocess that works fully offline.

## Scope

1. `services/extraction-agent/src/sandman_extraction/documents.py`:
   - `python -m sandman_extraction.documents <input-path>` converts with Docling and writes Markdown to stdout; Docling gets an explicit `artifacts_path` (models dir from `SANDMAN_MODELS_DIR`, default `~/.cache/sandman-models`), `HF_HUB_OFFLINE=1`, OCR per open question 2;
   - `async def to_markdown(path) -> str` starts it via `asyncio.create_subprocess_exec` with a timeout, `RLIMIT_AS`/`RLIMIT_CPU` (`resource.setrlimit` in `preexec_fn`) and a page/size limit (open question 4); non-zero exit, timeout or limit → exception → file-level fallback + warning (T1.1 §1);
   - the Markdown is fed to T1.1's `text.extract` with the original path; `startLine`/`endLine` refer to the rendering and are dropped before writing (open question 3) after `match_references` has used them.
2. Make the built-in path async where Docling is used: `stub()` in `_extract` becomes `async` (awaited per version), so a long conversion does not block the event loop.
3. `services/extraction-agent/src/sandman_extraction/prefetch.py`: downloads the models used by the configured pipeline into `SANDMAN_MODELS_DIR` with Docling's own downloader (pinned Docling version), then converts a tiny bundled PDF offline as a self-check.
4. Dockerfile: `RUN .venv/bin/python -m sandman_extraction.prefetch` in the build stage; copy the models dir to the runtime stage owned by `sandman`; set `SANDMAN_MODELS_DIR`, `HF_HUB_OFFLINE=1`.
5. Dependency `docling` (pinned) in `services/extraction-agent/pyproject.toml`; CPU-only `torch` per open question 1.
6. Fixtures and golden files: `tests/fixtures/documents/mediastore.pdf` and `mediastore.docx` generated once from the vendored MediaStore text (T1.1 open question 5), plus one DOCX with headings, a list and a table.

Out: OCR of scanned documents (unless decided otherwise), images/figures, page numbers in the KG (no schema field), Docling for other formats (HTML, PPTX), caching conversions, changes under `contracts/`.

## Acceptance criteria

- Golden files for the document fixtures committed and green (pinned Docling version; regenerating them is part of every Docling upgrade).
- For `mediastore.pdf` and `mediastore.docx` the sentence `localKey` set matches the one from the MediaStore text; the alignment rate is printed (target 37/37, deviations listed in the test).
- DOCX headings become sections with the same `sec:` keys as the equivalent Markdown.
- A converter crash, timeout, memory-limit hit or oversized PDF → file-level fallback, warning in the skill output, other artifacts of the run extracted normally.
- Offline: `docker run --network none` of the built image converts the fixture PDF (CI job step or e2e check), and the image build log shows the prefetch self-check.
- Integration (Testcontainers): a PDF version extracted through the skill writes sentences with `sentenceIndex`; T0.5 tests and the walking-skeleton e2e test stay green.
- `make lint` and `uv run pytest services/extraction-agent` green; Docling tests carry a pytest marker so a fast local run can skip them.

## Test plan

Unit: subprocess wrapper with a fake converter command (success, non-zero exit, timeout, garbage output). Golden: document fixtures. Integration: one PDF and one DOCX through the skill. Build: offline conversion in the image.

## Open questions (decided 2026-10-08: recommended defaults accepted)

1. Image size: Docling pulls `torch`. [CPU-only wheels via a uv index pinned for `torch` only; record the image size before/after in the PR.]
2. OCR (needs extra models, slow). [Off (`do_ocr=False`); born-digital PDFs only. Enable per deployment later.]
3. Line numbers for PDF/DOCX elements refer to the Markdown rendering, not the source. [Omit `startLine`/`endLine`; page numbers would need an additive schema field.]
4. Limits. [Timeout 120 s per file, 2 GiB address space, 300 pages, 50 MiB file size; configurable under `builtin.docling` in `config/extraction/plugins.yaml`.]
5. Markdown export vs. walking the `DoclingDocument` items. [Markdown export into T1.1 (no second structure mapper); switch only if golden files show escape artifacts.]
6. Model licenses (V-13). [Verify the licenses of the Docling layout and table models before merging; note them in the Dockerfile.]
7. R-025 "one canonical rendering per doc version". [Same default as T1.1 open question 1: no stored rendering; ArDoCo uses sentences from the KG.]

## Constraints

Python 3.13, uv only, `sandman_agent`; Docling only in the subprocess (never imported in the agent process); no network at runtime; all Cypher parameterized. Do not change `contracts/`. Ask before adding dependencies beyond `docling`. Keep a handoff note `.work/T1.4.md`.
