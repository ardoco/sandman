# Files

- [Extraction Agent](extraction-agent.md)
- [Inconsistency Agent](inconsistency-agent.md) - The Java/Quarkus inconsistency-agent: the InconsistencyDetector SPI with in-process and plain-HTTP plugin detectors, the one-transaction detect-inconsistencies run with fingerprint matching and re-detection transitions, and the triage REST API reached through the query-service.
- [llm-replay — LLM Record/Replay Proxy](llm-replay.md) - The standalone Starlette proxy in front of the Bifrost LLM gateway that every SANDMAN LLM caller targets — live pass-through, strict record/replay keyed by RFC 8785 canonicalization of the request body, per-experiment JSONL cassettes, and a service-token-protected /v1/status.
- [Orchestrator](orchestrator.md) - The rule-based workflow engine of SANDMAN — SQLite state (inbox, workflows, steps, messages, dead_events), the event-to-step rule table with debounce and actionKey dedup, the executor loop with per-project pipeline lock, retries and completion-event step closing, and the workflows/dead-events REST API.
- [Query Service](query-service.md) - SANDMAN's only user entry point — the bearer-token REST API with per-operation minimum roles from the OpenAPI contract, the server-rendered console on session cookie sandman_session with CSRF and forced password change, the SQLite user store (Argon2id, tokens, sessions), trusted forwarding of owner operations with X-Sandman-Actor/X-Sandman-Roles, and the CSV exports.
- [TLR Agent (Trace-Link Recovery)](tlr-agent.md) - The Java/Quarkus tlr-agent — the TraceLinkApproach SPI for in-process recovery approaches, config/tlr/approaches.yaml, the recover-trace-links skill with one Run per approach and one tracelinks.updated event, batched link writing with activation in the run's final transaction, and the GET /v1/approaches catalog.
