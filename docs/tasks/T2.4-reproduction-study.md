## Goal

A user can check that the ArDoCo adapter reproduces the standalone runner exactly. A user can compare a live LiSSA re-run with the published value. A user can derive the run count from a variance pilot. A user can test a configuration for memorization with a perturbed benchmark.

## Scope

1. **Exact equality**: `sandman eval equal --format F --expected FILE --actual FILE`. Exit code 0 if the link sets are equal, 1 if not. The report lists links that only one side has. No tolerance.
2. **LiSSA delta**: `sandman eval compare --published F1` (T2.3) reports live F1 minus published F1 with a 95 % bootstrap CI.
3. **Variance pilot**: `sandman eval pilot --f1 X [--f1 Y ...]` reads the F1 of at least 2 pilot runs. It prints mean, standard deviation, the run count n of protocol section 5, and a flag if n exceeds the cap.
4. **Contamination probe**: two commands.
   - `sandman eval perturb --names FILE --out DIR PATH...` renames identifiers consistently in text files. The mapping is deterministic (seeded) and written to `DIR/mapping.json`. Ids and gold standards stay unchanged.
   - `sandman eval contamination --original F1... --perturbed F1...` applies the verdict rule of protocol section 6.
5. **Paraphrase**: needs an LLM and a human check. The harness does not include it. The protocol keeps it as a manual step.

## Acceptance criteria

- Equal sets give exit code 0. A single missing or extra link gives exit code 1 and names the link.
- `perturb` replaces whole identifiers only, applies one mapping to all files, and gives the same output for the same seed.
- `pilot` and `contamination` give the values of `sandman_cli.evaluation.stats` (`runs_needed`, `contamination_verdict`).
- Unit tests run offline in `tools/cli/tests/test_evaluation_repro.py`.

## Procedure on a prepared machine

Run the guided script. It writes the results into the table above.

```sh
uv run python scripts/t24_guided.py
```

1. The script leads you through seven numbered steps (0 to 6). Each step says what you do by hand.
2. Press Enter to run the automatic part of a step. Each step prints `PASS`, `FAIL` or `SKIP`.
3. Skip any step. Steps 4 to 6 need an LLM endpoint.
4. Use `--resume [RUN_ID]` to continue a run. Use `--only STEP...` to run chosen steps. Use `--dry-run` to see the commands.
5. Raw outputs and logs go to `experiments/live/<run-id>/`. The state is in `state.json`.

The manual steps are in [docs/user/evaluation.md](../user/evaluation.md). They cover:

1. Prerequisites and the Memgraph integration tests.
2. Stack start, project creation, ingestion with kind rules, and `sandman export tracelinks --format ardoco-sad-sam --approach ardoco` (the approach id is `ardoco`).
3. Exact equality: `BenchmarkEquivalenceTest` with `SANDMAN_BENCHMARK_CSV_DIR`, then `sandman eval equal`. Expect exit code 0 for each project and format.
4. `sandman eval compare --published`, `pilot`, `perturb` and `contamination`.
