# T5.1 GitHub Action `sandman-ingest`

Milestone M5 · Effort S · Depends on: T0.10 · Used by: T5.5

Status: done (2026-10-18)

## Context

Users ingest with `sandman ingest` or the REST API ([ingesting-artifacts.md](../user/ingesting-artifacts.md)). Stage 1 (Q-14) confirms GitHub Actions as the CI platform. Project teams need a ready step for their own workflows. T5.5 (nightly ingest) uses it.

Facts that shape the design:
- The CLI is a member of the uv workspace and depends on `sandman-agent` (workspace). It has no standalone package.
- The CLI already builds the manifest, applies `sandman.yaml`, uploads only missing blobs and waits for a workflow (`sandman workflows --wait`).
- The ingestion response has no workflow id. The workflow list gives it.

## Goal

A user adds one step to a workflow. The step uploads the project directory to their SANDMAN instance, optionally waits for the workflow, and returns ids and status.

## Design

- Composite action `actions/sandman-ingest/action.yml` and script `actions/sandman-ingest/run.sh` (bash, `jq`, `git`; all present on `ubuntu-latest`).
- The action installs `uv` (`astral-sh/setup-uv`, pinned by commit SHA). The script then runs the CLI from the action's own checkout: `uv run --locked --no-dev --package sandman-cli --project <action root> sandman ...`.
- Reuse of the CLI: the action needs no second implementation of kind rules, hashing or multipart upload. A curl-only version would need glob matching with `**` in shell. The CLI is the smaller delta.
- Pinning the action to a commit SHA pins the CLI and its lock file.

Flow:
1. Check inputs. Mask the token. Fail if the token is empty.
2. `partial` mode: copy the files from `git diff --name-only --diff-filter=d <base> HEAD` and `sandman.yaml` to a temp directory.
3. `sandman ingest --project P --mode M --revision R DIR`. Read `ingestionId` and the counts from the JSON.
4. If the ingestion created, reactivated or deleted nothing, no workflow starts. Status is `none`.
5. Otherwise poll `sandman workflows --project P` (up to 60 s) for the newest workflow with `createdAt` not earlier than the ingestion `createdAt` (seconds resolution).
6. If `wait` is `true`, run `sandman workflows --wait ID --timeout T`. The step fails unless the status is `SUCCEEDED`.
7. Write the outputs, also on failure.

## Inputs and outputs

| Input | Default | Meaning |
|---|---|---|
| `url`, `token`, `project` | required | instance, personal API token (maintainer), project id |
| `path` | `.` | directory to ingest |
| `mode` | `full` | `full` or `partial` |
| `base` | empty | partial mode: base commit |
| `revision` | `github.sha` | source revision |
| `wait` | `true` | wait for the workflow |
| `timeout` | `600` | seconds to wait |

| Output | Meaning |
|---|---|
| `ingestion-id` | id of the ingestion |
| `workflow-id` | id of the workflow, empty if none started |
| `status` | `SUCCEEDED`, `FAILED`, `CANCELED`, `BLOCKED`, `STARTED` (not waited), `none` |

## Security

- The token comes only from an input. The user passes `secrets.*`. The script passes it to the CLI through the environment, never on a command line.
- The script runs `::add-mask::` for the token. It never prints the token. The CLI errors print method, path, status and response body only.
- Inputs reach the script as environment variables. The action never interpolates `${{ }}` into shell code (no script injection).
- Pins: `setup-uv` by commit SHA. The docs tell users to pin the action by commit SHA.
- Least privilege: the example sets `permissions: contents: read`. The action needs no GitHub token scope.
- Untrusted pull requests: secrets are not available to fork PRs, so the step fails with a clear error. The docs forbid `pull_request_target`. The example triggers are `push` to the default branch and `workflow_dispatch`.
- The runner must reach the instance. The default stack listens on `127.0.0.1`. Operators publish it behind TLS.

## Limits

- Partial mode does not delete artifacts. Use a scheduled `full` ingestion for deletions.
- Partial mode needs the base commit in the checkout (`fetch-depth: 0`).
- Workflow matching uses the creation time. Two ingestions in the same second can match the same workflow.
- Dot-files and symbolic links are skipped, like in the CLI.
- Limits of the ingestion API apply (20 000 files, 1 GiB).
- Each run installs `uv` and the CLI dependencies. This costs about a minute.

## Tests

`tests/actions/test_sandman_ingest.py` runs `run.sh` against a local mock HTTP server (no instance). It runs in the `python` CI job.

| Test | Proves |
|---|---|
| waits and sets outputs | request shape (check, upload, revision, mode), bearer header on all requests, mask line, token not in logs, outputs |
| no wait | status `STARTED`, no workflow poll |
| unchanged ingestion | status `none`, no workflow id |
| failed workflow | exit 1, status `FAILED` |
| HTTP 403 | step fails, status code in the message, token not in logs |
| empty token | error before any request |
| partial | only changed files in the manifest |

`actionlint` was not available on the build host. Run it once on the example workflow before release.

## Decisions taken

| Question | Default taken |
|---|---|
| CLI or curl | CLI via `uv run` from the action checkout |
| Where | composite action in this repository (`actions/sandman-ingest`) |
| Default mode | `full` |
| Default wait | `true`, timeout 600 s |
| Revision | `github.sha` |
| Deletions in partial mode | not supported |
| Release tag, Marketplace listing | none; users pin a commit SHA |

## Open questions

| Question | Recommended default |
|---|---|
| Publish the CLI as a package to skip the workspace install? | Yes, when the repository is public and releases exist. Then drop `uv run --project`. |
| Split the action into its own repository for the Marketplace? | No, until users ask. |
| Post a PR comment with the result? | No. It needs a write token and runs on untrusted code. |
| Add a `delete` step for partial mode (needs an API for single deletions)? | Not now. Use a nightly `full` run. |
