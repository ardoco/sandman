# T0.9 Query-service stub (users, roles, scope guard, console)

Milestone M0 · Effort L + S · Depends on: T0.2 (done) · Blocks: T0.11, M4 · Resolves review item R-026

## Context

The query-service (Python) is the only user entry point and the policy decision point: it authenticates users and services, checks roles, confines every read to one project, forwards owner operations with the actor identity, and hosts the console. It owns no KG nodes; its own state is a SQLite user store. In M0 everything is real except NL-to-Cypher, which maps a few regex intents to fixed queries (M4 replaces it). Read first:
- `docs/stage-1-analysis-architecture.md` §5.5, §7 (authorization, scope guard, validation, execution), §10 (console pages, notifications), §11.2 (users, sessions, tokens, forwarders)
- `docs/stage-2-contracts-repository.md` §1.2, §1.5 (authorization matrix), §1.7, §4.5
- `adr/0009-nl-to-cypher.md`, `adr/0018-query-strategies.md`, `adr/0011-inconsistency-console.md`, `adr/0013-users-and-roles.md` — including their **Amendments**
- `contracts/openapi/query-service.yaml` (normative; `x-sandman-min-role` per operation), `contracts/openapi/shared.yaml`, the owner APIs it forwards to (`extraction-agent.yaml`, `inconsistency-agent.yaml`, `orchestrator.yaml`), `contracts/kg/schema.yaml`
- Library: `libs/python/sandman-agent` (`Settings`, `KgClient`, `auth`, `status`, `telemetry`); existing services `services/extraction-agent` and `services/orchestrator` show the app structure (one ASGI app, REST under `/v1`, `/healthz`, `/readyz`, `/v1/status`).

## Goal

`services/query-service` (package `sandman_query`): FastAPI app with the REST API of `contracts/openapi/query-service.yaml`, the Cypher scope guard, the stub NL endpoint, exports and a server-rendered console (Jinja2 + vendored htmx, no own JavaScript, no build chain).

## Scope

1. **User store** (SQLite at `SANDMAN_USER_DB`, schema version via `PRAGMA user_version`, plain SQL migrations): users (username, Argon2id hash, global roles ⊆ {admin}, disabled, must_change_password, created_at), memberships (project, user, role ∈ viewer < triager < maintainer), personal tokens (id, user, name, sha256 of the secret, optional project, optional max_role, expires_at, last_used_at), sessions (sha256 of the session id, user, CSRF token, created/expires/last_seen), last visit per (user, project). First admin from `SANDMAN_ADMIN_PASSWORD_FILE` with `must_change_password = true`.
2. **Authentication.**
   - `/v1/*` accepts **bearer tokens only** (personal tokens via hash lookup; service tokens via `sandman_agent.auth.TokenVerifier` and `SANDMAN_SERVICE_VERIFY_FILE`). No cookies on `/v1/*` except `/v1/auth/login` (sets the console cookie) and `/v1/auth/logout` (`security: session`).
   - Console (`/console/*`): server-side session; cookie `HttpOnly`, `SameSite=Strict`, `Secure` when `SANDMAN_COOKIE_SECURE=true`; CSRF token on every form POST (403 without); logout and password change revoke the session; login rate limit (5 failed attempts per username and per client address per 15 min → 429); forced password change before anything else when `must_change_password`.
3. **Authorization** per the `x-sandman-min-role` of each operation and Stage 2 §1.5. Effective project role = min(membership role, token `maxRole`); a token with `projectId` works only for that project. Global `admin` passes every check. Service callers: reads allowed; plugin callers (`plugin:<id>`) only `POST /v1/query/cypher` and `GET /v1/schema`, and only for projects granted in `config/query/plugins.yaml` (`{plugin-id: [project, …] | "*"}`); every other route rejects them with 403. Requests for a project the caller cannot read return **404** (no existence leak).
4. **Forwarding** of owner operations (ingestion check/upload, project put, inconsistency list/detail/transition, workflow list/get/create) with the query-service's own token plus `X-Sandman-Actor: user:<name>` and `X-Sandman-Roles`; owner status codes and problem bodies are passed through. `GET /v1/inconsistencies/{id}`: fetch from the owner, then authorize against the returned `projectId` (404 if not readable). Transitions: same, before forwarding. Uploads are streamed, not buffered in memory.
5. **Cypher scope guard** (ADR-0009 amendment, D-2), used by the raw Cypher endpoint and the NL stub:
   - Parser (V-28): time-box 1 day for an openCypher grammar (ANTLR-generated Python parser, generated code vendored, runtime `antlr4-python3-runtime`); if that does not cover the allowlisted subset cleanly, write a small recursive-descent parser for exactly the allowlisted subset and reject everything else (RK-19 fallback). Record the choice in `docs/notes/cypher-guard.md`.
   - Allowlisted clauses: `MATCH`, `OPTIONAL MATCH`, `WHERE`, `WITH`, `UNWIND`, `RETURN`, `ORDER BY`, `SKIP`, `LIMIT`, `UNION [ALL]`, pattern comprehensions and `EXISTS { … }`. Rejected: `CALL`, write clauses, Memgraph-specific clauses (`SHOW …`, `DUMP DATABASE`, `TERMINATE TRANSACTIONS`, streams, settings, `LOAD CSV`, index/constraint statements), `QUERY MEMORY LIMIT` written by the caller.
   - Anchoring: every connected pattern component in every `MATCH`, comprehension and subquery contains a node anchored by `{projectId: $projectId}` or `(:Project {id: $projectId})`, or a variable bound by an earlier anchored pattern. `$projectId` is bound by the service, never taken from user `params`.
   - Global admin without `projectId`: anchoring is skipped, the clause allowlist still applies.
   - Execution: `KgClient.read` (read transaction) with a driver timeout (users ≤ 10 s, services ≤ 30 s) and `QUERY MEMORY LIMIT 100 MB` appended; `LIMIT` enforced (append if missing, fetch `limit + 1`, set `truncated`). You may add an optional `timeout` parameter to `sandman_agent.KgClient.read` (with a test); `MemoryLimitError` → 422 problem.
   - Result post-check: every returned node/relationship map with a `projectId` must equal the requested project, else 422 (and log `event=scope_violation`).
   - Rows are JSON values; nodes/relationships as property maps plus `_labels`/`_type`; no internal ids.
6. **NL stub** (`POST /v1/query/nl`): regex intents from `config/query/intents.yaml` (`untraced requirements`, `links of <name>`, `open inconsistencies`, `components without documentation`, `what changed since <revision>`) mapped to fixed, anchored Cypher templates that also pass the guard; other questions → 422 with an explanation. `mode=cypher-only` returns the Cypher with empty `columns`/`rows`. `strategy` (`auto` default, `cypher`, `graphrag`, `explore`; ADR-0018) is accepted and validated: `auto` and `cypher` use the intents and return `strategy: cypher`; `graphrag` and `explore` answer 501 (NotImplemented problem). No LLM call in M0.
7. **Schema and exports:** `GET /v1/schema` (kg/schema.yaml as JSON); `GET …/export/tracelinks` (active links with both endpoints current; CSV columns per the contract) and `…/export/inconsistencies` (read from the KG, with history), both via the same read path.
8. **Status and health:** `/healthz`, `/readyz` (Memgraph and user store reachable), `/v1/status` (`StatusTracker`, in-flight requests).
9. **Console** (`/console`, Stage 1 §10 pages): login and forced password change; projects (counts by status, "new/reopened since last visit" via `changedSince`, last workflow status); inconsistency list (filters) and detail (evidence, involved elements and links, history, transition form with allowed transitions only, reason required for ACCEPTED/REJECTED/DEFERRED); upload (archive + kind rules); ask (NL stub); workflows (list, manual trigger for maintainers); administration (users, memberships, tokens). Jinja2 autoescape on, never `|safe` on data, no Markdown→HTML; response header `Content-Security-Policy: default-src 'self'`; htmx vendored under `static/` (pin the version; htmx 2.x is 0BSD). Update last visit when a project page is viewed.
10. Default config files `config/query/intents.yaml` and `config/query/plugins.yaml` (stub plugin granted `"*"` for the walking skeleton).

Out: LLM NL-to-Cypher, `graphrag`, `explore`, classifier for `auto` (M4), dashboard (T1.9), OIDC.

## Acceptance criteria

- **Authorization matrix:** one parametrized test per operation × caller kind (anonymous, viewer, triager, maintainer, admin, service, plugin with/without grant, personal token with project restriction and `maxRole`) asserting allow/deny per `x-sandman-min-role`; unreadable project → 404.
- **Forwarders:** owners receive `X-Sandman-Actor` only from the query-service; a test with a fake owner asserts headers and that a client-supplied `X-Sandman-Actor` is never forwarded.
- **Scope guard bypass corpus** (run with validation on, and with validation off against a real Memgraph to show the read transaction still blocks writes): unanchored `MATCH`, `WITH $projectId AS p MATCH (n) …`, anchoring only in `WHERE`, second unanchored component, pattern comprehension and `EXISTS` subquery reaching other projects, `UNION` with an unanchored branch, `CALL`, `SHOW STORAGE INFO`, `DUMP DATABASE`, `LOAD CSV`, write clauses, comments/strings hiding keywords, a user-supplied `$projectId` param, caller-written `QUERY MEMORY LIMIT`, cartesian product hitting the memory limit; a result post-check test with a forged row.
- **Sessions:** cookie flags, CSRF missing/wrong → 403, logout revokes, rate limit → 429, bootstrap admin must change the password, `/v1/*` ignores cookies.
- **Console smoke tests:** every page renders for a member; element text containing `<script>` is escaped; CSP header present; transition form posts with CSRF and shows the 409 conflict message.
- NL intents return the expected Cypher for each pattern; unknown question → 422. `strategy` unknown value → 422; `graphrag`/`explore` → 501; response carries `strategy: cypher`.
- Responses of all `/v1` operations validate against `contracts/openapi/query-service.yaml` (jsonschema; Schemathesis optional).
- Integration tests with Testcontainers Memgraph 3.13.1 (skip without Docker).
- `uv run ruff check`, `ruff format --check`, `uv run pytest services/query-service` green.
