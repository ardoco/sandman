## Goal

The approach `lissa` writes LiSSA-style requirement↔code links. All LLM and embedding calls go through the Sandman Java LLM library to the gateway or `llm-replay`, without LangChain4j. On the WARC project, the adapted code gives the same link set and the same P/R/F1 as upstream LiSSA. Replayed runs give identical links and need no provider key.

## Decisions

1. **One module, vendored code.** New Maven module `services/tlr-agent/approach-lissa`, package `edu.kit.kastel.mcse.ardoco.sandman.tlr.lissa`. Copy the reused LiSSA classes from commit `18ed936` (see Reuse table). Keep the MIT header in each copied file. Record the commit in `approach-lissa/LISSA_COMMIT` and in `services/tlr-agent/THIRD-PARTY.md`. No Docker `ARG LISSA_COMMIT` is needed (closes the §11 remainder).
2. **No LangChain4j.** The module keeps the default enforcer ban (no override). The existing ArchUnit rule guards the package. No new rule.
3. **Java LLM library.** Add `LlmClient` to `libs/java/agent-lib` (revives the R-051 cut item). JDK `HttpClient` plus Jackson. No new dependency. Behavior:
   - Endpoints: `POST {baseUrl}/chat/completions` and `POST {baseUrl}/embeddings`. Non-streaming only (`stream` is never set).
   - Model and key: `LlmAccess.model(route)` and `LlmAccess.apiKey()`. These apply the project `llmPolicy` and the local-only rule.
   - Request fields: `model`, `messages`, `temperature`, `seed`, `user` = run id. Header `traceparent` from `Telemetry`.
   - Send one embedding request per input text, never a batch. A batch key depends on all its members. The next version would then miss replay and pay again. One text per request makes each cassette key depend on one element only.
   - Status 402: throw `BudgetExceededException`.
   - Status 429, 5xx and connect errors: retry 2 times with backoff. Then throw `LlmUnavailableException`.
   - Status 404 `replay_miss` and other 4xx: throw `LlmCallException` (not retryable). The message contains the response body, so a replay miss shows the cassette key.
   - agent-lib does not depend on `approach-spi`. `LissaApproach` maps `LlmUnavailableException` to `ApproachUnavailableException`. The skill then fails retryable after the other approaches.
   - Usage: sum `usage.prompt_tokens` and `usage.completion_tokens` in thread-safe counters. Collect the response `model` values.
4. **Routes follow the policy.** The approach always uses `LlmAccess.chatRoute()` and `LlmAccess.embedRoute()`. A cloud project gets `chat-default` and `embed-default`. A local-only project gets `chat-local` and `embed-local`. Remove `model` and `embed` from the `lissa` params in `approaches.yaml` (as Python T1.5). Model pins for experiments come from `config/llm/models.yaml`.
5. **Two model terms.** The **configured model** is `LlmAccess.model(route)`, known before any call. It enters `environment()` and thus `configHash`. The **response model** is the `model` field of a response. It goes to `Run.resolvedModel`. Rule: `resolvedModel` = the lexicographically smallest response model. `mixedModels` = true if more than one distinct response model occurs. The result does not depend on thread order.
6. **SPI change (additive).** `TlrContext` gets `LlmClient llmClient` (null if `usesLlm()` is false). The tlr-agent builds `LlmAccess` before it calls `environment()`. It passes `LlmAccess` in the environment `TlrContext`, so `environment()` can read the configured models. A `PolicyException` there records no Run. The skill then fails with `INVALID_INPUT`, `retryable=false`, after the other approaches. The tlr-agent creates the `LlmClient` after `recorder.start`, because `user` needs the run id. It creates one client per Run. After `recover`, the tlr-agent writes to the Run: `model` = route, `inputTokens`, `outputTokens`, `resolvedModel`, `mixedModels`, `promptIds`. It writes these on success and on failure. `RunRecorder` gets matching optional parameters (as Python `kg.py`). `TraceLinkApproach` gets `default List<String> promptIds()` (empty).
7. **Budget.** `BudgetExceededException` cancels the remaining calls of the Run. The Run fails with error `BUDGET_EXCEEDED`. The other approaches finish. Then the skill fails with `SkillException("BUDGET_EXCEEDED", …, false)`, so the orchestrator sets the workflow `BLOCKED`.
8. **Approach** `lissa`, version `1.1.0+s1` (LiSSA version plus Sandman adaptation number). The `ardoco.version` prefix rule (`VersionTest`) applies only to `approach-ardoco`. `usesLlm` = true. `supports` = {requirements → code}. `paramKeys` = `retrieval.k`, `classifier`, `concurrency`.
9. **Scope mode: `whole-project`.** LiSSA ranks all targets per source. A changed target can push an unchanged pair out of the top k. Pairwise input would keep that stale link (R-022). Whole-project runs recompute over all current versions of the pair and replace the active links. Under replay, unchanged calls hit the cassette. In live mode, every run pays all calls again (see open question 4).
10. **Element mapping.** The input `KindPair` selects the source and target elements. Type string and content depend on the element label, not on the side:
    - `Requirement`: type string `requirement`; content = `text`.
    - `CodeUnit` with kind `file`: type string `source code`; content = file bytes from `ctx.artifacts().pathFor(version.storageUri())`, decoded as UTF-8, CRLF as LF.
    - Other labels and code kinds (`type`, `method`) are skipped.
    Thus the WARC test (requirement → requirement) uses the production path. Sandman kind names never enter the prompt. A pinned map gives LiSSA's exact type strings. Elements are sorted by `id` before embedding and retrieval.
11. **Mapping to links.** One `CandidateLink` per distinct (source id, target id) that the classifier accepts. `linkType` = `implements`. `confidence` = 1.0. No `rationale`. Output is sorted by (source id, target id).
12. **configHash.** `environment()` = JSON of: configured chat model, configured embedding model, classifier template id and sha256, temperature, seed, `k`, `LISSA_COMMIT`. A prompt change thus changes `configHash` and the link ids. `promptIds` = `["lissa-simple@<sha256-8>"]` (or `lissa-reasoning@…`).
13. **Determinism.** Temperature 0, fixed seed, sorted inputs, stable cosine sort, sorted output. Classifier calls run on a bounded pool (`concurrency` [8]). Results are collected per pair, so order does not matter.

## Acceptance criteria

- WARC: the adapted pipeline gives P = 0.38, R = 0.6985294117647058, F1 = 0.49222797927461137 and the same link set as upstream LiSSA `18ed936`.
- No class in `approach-lissa` or agent-lib imports `dev.langchain4j`. The module has no enforcer override. `mvn dependency:tree -pl services/tlr-agent/approach-lissa` shows no `dev.langchain4j`.

- Incremental and batch runs give equal active links (scripted `LlmClient`, R-022).

## Risks

- **Prompt byte drift.** Any change to template, type strings, content normalization or element order makes every equivalence lookup miss. Mitigation: Step 5 byte test against the upstream template.
- **Cost in live mode.** Whole-project scope pays all classifier calls again on each version. Mitigation: open question 4; budget errors block the workflow.
- **Large code files.** Without truncation, an embedding request over the model token limit gets a 4xx answer. Mitigation: open question 3.
- **Cassette size.** Embeddings are large (3072 floats per element for `-3-large`). Mitigation: the e2e fixture uses `embed-local`; WARC answers stay in the downloaded LiSSA caches.
- **Provider non-determinism.** Live outputs can change despite seed 0 and temperature 0. Mitigation: replay for CI; `mixedModels` and R-041 provider pins make drift visible.
- **Cassette re-recording.** `make record-cassettes` deletes and re-records the whole walking-skeleton cassette. Enrichment answers (T1.5) can change and alter the golden export beyond `lissa`. Mitigation: open question 8.
- **Remote Ollama models.** Recording needs `embed-local` (`nomic-embed-text:v1.5`) on the remote Ollama endpoint. Mitigation: check before Step 9; `make models` pulls it for the local profile.
- **Upstream drift.** LiSSA moves on. Mitigation: pinned commit; re-vendoring is a separate task.

## Implementation notes and deviations

- `TraceLinkApproach.promptIds` takes the run context: `promptIds(TlrContext)`. The classifier name comes from the params.
- `paramKeys()` returns `retrieval`, `classifier` and `concurrency`. `RecoverTraceLinks` checks top-level names. The value `k` is read as `retrieval.k`.
- Over-limit embedding input: the embedder detects an `LlmCallException` whose message contains `context_length_exceeded` or `maximum context length`. It skips the element and logs a warning.
- WARC equivalence test: `WarcEquivalenceTest` (tag `benchmark`, Maven profile `benchmark`). It reads the data set from `~/.cache/sandman/lissa-warc` and checks sha256 sums. The target files enter as code files. The test maps the prompt label "source code" back to "requirement" for the cache lookup.
- The test asserts P, R and F1 of upstream (0.38, 0.6985294117647058, 0.49222797927461137) to 1e-12. It does not compare the link set with an upstream dump. Equal metrics on this data set make a different link set unlikely.
- No WARC cassette is committed.
