# T7.1 Architectural decision extraction

Milestone M7 · Effort M · Depends on: M1, M2 · Risk: RK-9 (injection in decision text), RK-11 (graph growth), S-1, S-2 (below)

Status: open, spec ready (2026-10-20). Open questions have bracketed defaults, marked "decided: default". Implementation can start without the user.

## Context

Sandman has no element type for architectural decisions. Decision records (ADR, MADR) are ingested as plain documents today. Their sentences become `TextUnit` elements. Nothing marks the file as a decision. Nothing links the decision as a whole to the model or the code.

The paper names decisions and rationale as core knowledge (paper §1, p. 487; §3.3, p. 489). See `docs/notes/paper-review-3774748.3795871.md` §3.5. Contradictions between decisions stay in the backlog until this task has data.

Facts from the code:
- A kind rule returns `(kind, format)`. The format is a free string. A new format value needs no contract change.
- `builtin.extract` sends `markdown` and `text` formats to `text.extract`. Other unknown formats get file-level stub elements.
- `text.extract` returns one file element (`localKey = file`, label from `LABEL_BY_KIND`), then sections and sentences. Sections have `parent`, so `CONTAINS` edges go from the file element down.
- `extract.py` writes elements per label in `LABELS`. A new label needs a new entry there.
- T6.3 traverses `CONTAINS` upward. A change in a linked sentence of a decision reaches the decision element without extra work.

## Goal

Each ADR or MADR file becomes one `Decision` element with its status and date. The sections and sentences of the file stay `TextUnit` elements below the decision. A deterministic TLR approach links each decision to the model elements and code elements that it names.

## Behavior

### Detection of decision files

1. The CLI adds default kind rules after the rules of `sandman.yaml`:
   - `adr/*.md` = `architecture-doc`, format `adr`
   - `docs/adr/**/*.md` = `architecture-doc`, format `adr`
   - `docs/decisions/**/*.md` = `architecture-doc`, format `adr`
   - `**/adr/[0-9][0-9][0-9][0-9]-*.md` = `architecture-doc`, format `adr`
2. A rule in `sandman.yaml` wins over a default rule, because the first matching rule decides.
3. The files `README.md`, `index.md` and `template.md` in these folders get format `markdown`, not `adr`. Add these exclusions as rules before the defaults.
4. The extraction-agent does not guess. Only format `adr` creates a `Decision`.

### Parser (`services/extraction-agent/src/sandman_extraction/decisions.py`)

1. Call `text.extract(path, content, markdown=True)`. Keep all its elements.
2. Change the file element: `label = Decision`, `kind = decision`.
3. Set `name` to the first level-1 heading. Strip a leading number pattern such as `12. ` or `ADR-12: `. If no heading exists, use the file name without suffix.
4. Read the status:
   - MADR: front matter key `status` (YAML between the first two `---` lines).
   - Nygard: the first sentence of the section `Status`.
   - Map the first word, case-insensitive, to the enum. `superseded by ...` maps to `superseded`. Other values map to `unknown`.
5. Read the date from front matter key `date`, or from a line `Date: YYYY-MM-DD`. If the date is not a valid ISO date, omit it.
6. Set `text` of the decision to the title, the decision section and the consequences section, joined by blank lines and cut to 4000 characters. Decision section names: `Decision`, `Decision Outcome`. Consequences section names: `Consequences`, `### Consequences`.
7. Set `contentHash` = sha256 of this `text` (built-in rule: text, else name).
8. Remove the front matter from the text that `text.extract` reads, so front matter lines do not become sentences. Keep line numbers correct: replace the front matter lines with empty lines.
9. If the parser finds no decision section, keep the element. Add a run warning `adr: no decision section in <path>`.

Register the format in `builtin.extract`: `if fmt == "adr": return decisions.extract(path, content), []`. Add `Decision` to `LABELS` in `extract.py`.

### TLR approach `decision-mention` (tlr-agent)

1. Class `DecisionMention` in package `edu.kit.kastel.mcse.ardoco.sandman.tlr`. Register it in `META-INF/services/edu.kit.kastel.mcse.ardoco.sandman.tlr.TraceLinkApproach`.
2. Version `1`. `supports()`: `(architecture-doc, architecture-model)` and `(architecture-doc, code)`.
3. Sources: elements with label `Decision` only. Targets: `ModelElement` with kind `component` or `interface`, and `CodeUnit` with kind `file` or `type`.
4. Match rules, on the decision `name` and `text`:
   - A code file path (`localKey` of a file `CodeUnit`) occurs in the text: confidence 1.0.
   - A target name occurs as a whole word, case-sensitive, and the name has at least `minNameLength` (default 4) characters: confidence 0.8.
   - Otherwise no link.
5. Link type `relates`. Rationale: `mentions '<name>'` or `mentions path '<path>'`.
6. Add `decision-mention: { enabled: true, params: { minNameLength: 4 } }` to `config/tlr/approaches.yaml`.

The other approaches keep working on the sentences of the decision file, because these sentences stay `TextUnit` elements of an `architecture-doc` artifact.

## Decisions taken

| Id | Question | Decision |
|---|---|---|
| D-1 | New `ArtifactKind` `decision`? | No. Use `architecture-doc` with format `adr`. A new kind changes the enum in many places and the `KindPair` lists of all approaches. Kind `architecture-doc` gives the decision sentences the existing SAD↔SAM and SAD↔code links. |
| D-2 | One element per decision or a new node type? | One `Element` with label `Decision`. It reuses keys, versions, provenance, export and NL queries. |
| D-3 | Where does the decision element sit? | It is the file element of the decision file (`localKey = file`). Sections and sentences stay below it. No new key scheme is needed. |
| D-4 | Who writes the decision links? | The tlr-agent, as approach `decision-mention`. The tlr-agent owns `TraceLink`, so no co-owner change is needed. |
| D-5 | LLM in this task? | No. Parser and approach are deterministic. |

## Acceptance criteria

1. Contract commit first. Conformance vectors and both libraries are green.
2. Unit tests of the parser:
   - Nygard ADR: title, status `accepted`, decision text, no date
   - MADR v3 with front matter: status, date, decision outcome text, front matter not in sentences
   - status `Superseded by ADR-7`: `superseded`
   - unknown status word: `unknown`
   - no decision section: element kept, one warning
3. The 18 files `adr/0*.md` of this repository give 18 `Decision` elements: 17 with status `accepted`, 1 with status `proposed`. `adr/README.md` and `adr/template.md` give none.
4. The sentence keys of a decision file equal the keys that format `markdown` gives for the same file, except front matter lines.
5. Unit tests of `decision-mention`: path match 1.0, whole-word name match 0.8, no match inside a longer word, no match for names shorter than `minNameLength`.
6. Memgraph integration test: an ADR that names a model component and a Java file gives two active `decision-mention` links from the `Decision` element.
7. End-to-end test on the mini snapshot plus one ADR fixture: the Decision node exists, the links exist, and the T6.3 impact report for a change of the named Java file lists the decision.
8. The replay determinism test (T1.6) stays green.

## Risks

- RK-9: decision text enters LLM prompts of other features (NL queries, T7.5). Apply the same escaping and prompt fences as for other text.
- RK-11: each ADR adds one node. The growth is small.
- S-1 (new): name matching gives false links for common words that are also component names (for example `Cache`). Mitigation: case-sensitive whole-word match, minimum length, review in the console (T6.1).
- S-2 (new): `architecture-doc` ADRs enter the input of `ardoco-id` (`textKinds`). A decision that names a component that the model lacks gives a `missing-model-element` finding. This is a correct finding for the detector. Users can exclude ADRs with a `sandman.yaml` rule that sets kind `other`.

## Constraints

Shared constraints of plan §5 apply. Do not use an LLM in this task. Do not add a Python dependency; `pyyaml` comes from `sandman-agent`.
