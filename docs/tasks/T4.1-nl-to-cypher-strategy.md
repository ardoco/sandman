## Context

`POST /v1/query/nl` accepts `strategy` (ADR-0018) since T0.9, but answers only with fixed regex intents. This task adds LLM-based NL-to-Cypher as strategy `cypher` and the dispatch that all later strategies plug into. Read first:

- `docs/stage-1-analysis-architecture.md` §7; `docs/stage-2-contracts-repository.md` §4.5 (query-service, configuration)
- `docs/tasks/T0.9-query-service.md` (guard, `Runner`, intents stub)
- `contracts/openapi/query-service.yaml` (`queryNl`), `contracts/kg/schema.yaml`, `contracts/config/`
- Code: `services/query-service/src/sandman_query/` (`query.py`, `guard.py`, `service.py`, `app.py`); LLM client: `libs/python/sandman-agent/src/sandman_agent/llm.py` (`ModelSelector`, `LlmClient`, `ScriptedLlmClient` in `testing.py`).

## Goal

A question without a matching intent is turned into one guarded, executed Cypher query by the LLM (through the gateway, so record/replay works), with bounded repair. Strategies are enabled in `config/query/strategies.yaml`; a disabled or unimplemented strategy answers 501.

## Scope

1. **Config.** `config/query/strategies.yaml` with schema `contracts/config/query-strategies.schema.json`: per strategy `enabled`; for `cypher` also `intentsFirst` (default true), `maxRepairs` (default 2), `maxExamples` (default 8). Missing file = only `cypher` enabled. Defaults: `cypher` on, `graphrag` and `explore` off. The schema also allows `classifierThreshold` (used by T4.7).
2. **Dispatch.** One async function per strategy in a registry; `POST /v1/query/nl` (and the console Ask page) resolve the strategy: `auto` resolves to `cypher` until T4.7 (the classifier) exists; a strategy that is disabled or has no function answers 501 with the NotImplemented problem. The role check stays first.
3. **Strategy `cypher`.**
   - If `intentsFirst` and an intent matches, use its fixed template (unchanged T0.9 behavior, no LLM call).
   - Otherwise, if no LLM is configured: 422 with the existing "question not understood" message (T0.9 behavior).
   - Otherwise one chat call on the project's route (`ModelSelector.chat_model(llmPolicy)`), temperature 0, structured output `{cypher, explanation}`. System prompt: schema text generated from `contracts/kg/schema.yaml` (labels, properties, relationships), the rules (read-only, `$projectId` anchoring, no other parameters, no `CALL`), and the examples of `config/query/examples.yaml` (non-`test` split, first `maxExamples`). The question goes into the user message only.
   - Validation: the parse-tree scope guard (`guard.check`, scoped). Rejected, or failing in the database (guard-passed query answered 422 by `Runner.run`), the error text is fed back and the model is asked again, at most `maxRepairs` times. A scope violation in the result is not repaired. After the last failure: 422 "no valid query after repairs" with the attempts in the log, not in the problem.
   - `mode=cypher-only` and `execute=false` validate with the guard only and run nothing.
   - Response fields: `strategy: cypher`, `cypher`, `params` (`projectId` only), `attempts` (`cypher`, `error`), `warnings`, `model`, `resolvedModel` (LLM path only). No `answer` (T4.3).
   - LLM errors (`PolicyError`, budget exhausted, gateway error) answer 503.
4. **Wiring.** `Service` builds the `ModelSelector` from `Settings` (`llm_models_file`, `llm_base_url`, `llm_key`) like the extraction-agent; `llm_factory` is the test injection point. The project's `llmPolicy` is read from the KG.

Out: answer synthesis (T4.3), classifier (T4.7), `graphrag` (T4.5), `explore` (T4.6), embedding-based example selection (T4.2), `EXPLAIN` validation, LLM-supplied parameters.

## Acceptance criteria

- Replay/scripted-LLM tests: valid first answer; guard rejection then repaired answer; database error then repaired answer; repairs exhausted → 422; scope violation not repaired; unanchored/`CALL`/write Cypher from the model never reaches the reader; `cypher-only` runs nothing; prompt contains schema text and examples; question only in the user message; local-only project uses `chat-local`; LLM failure → 503; no LLM configured → the T0.9 422.
- Dispatch tests: `graphrag`/`explore` 501 (not implemented), `cypher` disabled in config → 501 (also for `auto`), unknown strategy 400, intents still work without an LLM.
- `strategies.yaml` default file validates against its schema (`scripts/validate_contracts.py`).
- Responses validate against `contracts/openapi/query-service.yaml`.
- `uv run ruff check`, `ruff format --check`, `uv run pytest services/query-service` green.
