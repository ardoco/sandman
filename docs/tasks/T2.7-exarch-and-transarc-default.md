## Context

Most projects have documentation and code but no architecture model (SAM). TransArC (SAD→SAM→code) needs a SAM. ExArch (ICSA 2025) gives one: an LLM reads the documentation and returns component names, and the names form a components-only SAM. T2.1b runs ArDoCode (SAD→code, no SAM) and excludes TransArC because of an assumed in-process CoreNLP need (T2.5 open question 7). Read first:

### Findings (checked offline on 2026-10-18 against the `io.github.ardoco.tlr:*:2.1.0` and `io.github.ardoco.core:common:2.1.0` jars in the local Maven repository and their sources)

Verified:
1. **Location.** `ExArch` and `Transarc` are runners in package `edu.kit.kastel.mcse.ardoco.tlr.execution` of the released `pipeline-tlr:2.1.0` (Maven Central, used by T2.1 since 2026-10-10). The LLM classes are in `model-provider:2.1.0`, package `edu.kit.kastel.mcse.ardoco.tlr.models.informants`. Source headers say "Licensed under MIT".
2. **ExArch API.** `ExArch.setUp(File inputText, CodeConfiguration, ImmutableSortedMap<String,String> additionalConfigs, File outputDir, LargeLanguageModel, LlmArchitecturePrompt documentationExtractionPrompt, LlmArchitecturePrompt codeExtractionPrompt, LlmArchitecturePrompt.Features codeFeatures, LlmArchitecturePrompt aggregationPrompt)`. The `CodeConfiguration` is mandatory, also for the documentation-only variant. Pipeline: text preprocessing, code model provider, `LlmArchitectureProviderAgent`, then the TransArC stages (`TextExtraction`, `RecommendationGenerator`, `ConnectionGenerator`, `SamCodeTraceabilityLinkRecovery`, `SadSamCodeTraceabilityLinkRecovery`). ExArch is TransArC with an LLM-made SAM.
3. **Transarc API.** `Transarc.setUp(File inputText, ArchitectureConfiguration, CodeConfiguration, additionalConfigs, File outputDir)`; the runner sets the metamodels (`ARCHITECTURE_WITH_COMPONENTS`, `CODE_WITH_COMPILATION_UNITS`). `ArdocoResult` has `getArchitectureTraceLinks()` (SAD↔SAM), `getSamCodeTraceLinks()` and `getSadCodeTraceLinks()`.
4. **ExArch output.** `LlmArchitectureProviderInformant` builds an `ArchitectureComponentModel` of `ArchitectureComponent(name, id = name, empty sets, "Component")`. Components only: no interfaces, no connectors, no confidence.
5. **ExArch documentation prompt.** `LlmArchitecturePrompt.EXTRACT_FROM_ARCHITECTURE` has two user turns: (a) identify the high-level components of the documentation (`%s` = whole text); (b) "provide a list that only covers the component names … Output format: - Name1". Other prompts: `EXTRACT_FROM_CODE` (packages, or packages and their classes), `AGGREGATION`.
6. **Post-processing.** Keep lines that start with `-`; strip the dash; remove `Components`, then `Component`; trim; `toCamelCase` (only if the name contains a space: split at `" "`, first char upper, rest lower, default locale); drop blanks; `distinct`; `sorted` (Java `String` order). Two prompts without aggregation merge by Levenshtein similarity.
7. **LLM access.** The enum `LargeLanguageModel` (`GPT_4_O`, `GPT_4_1`, `GPT_5`, `OPENAI_GENERIC`, `OLLAMA_GENERIC`) creates the LangChain4j `ChatModel` from process environment variables only (`OPENAI_API_KEY`, `OPENAI_ORGANIZATION_ID`, `OLLAMA_HOST`, `OLLAMA_TOKEN`, `SEED`, …), temperature 0. `create()` wraps it in `CachedChatLanguageModel`, which writes a JSON cache to `LLM_CACHE_DIR` (default `.cache-llm/`). The informant constructor calls `create()`; there is no `ChatModel` injection point. This is the V-29 situation of ADR-0015.
8. **Component listing format.** `ModelFormat` has `PCM`, `UML`, `COMPONENT_LISTING`, `ACM`. `ArchitectureConfiguration.extractor()` maps `COMPONENT_LISTING` to `ComponentListingArchitectureExtractor`. That extractor reads lines, splits each at `::` (limit 2), and makes `ArchitectureComponent(… , "component")`; a line without `::` gets a random UUID-based id.
9. **TransArC and CoreNLP.** `NameComparisonUtils.areEqualLemmatized` starts an in-process CoreNLP pipeline (`tokenize,pos,lemma`). In the 2.1.0 bytecode, no class reads `PreprocessingMethod.LEMMATIZATION`: `TraceLinkGenerator` passes only `NONE` and `STEMMING` (OpenNLP `PorterStemmer`), and the fields of `ComponentNameResemblance` and `PackageResemblance` get their value from there. TransArC therefore probably needs no CoreNLP models. This contradicts the assumption of T2.5 open question 7. The tlr-agent keeps the CoreNLP code jar without models (T2.5), so the classes still link.
10. **Sandman side.** `Artifact.kind` already has `architecture-model`; `format` is a free string. No `inferred`, `origin` or `derivedFrom` property exists (schema 0.5.0). The extraction-agent already calls the LLM gateway with routes `chat-default` / `chat-local` per `Project.llmPolicy`, records `promptIds` and `replayMode` on the `Run`, and reuses earlier results (T1.5). `tlr.kindPairs` has no approach lists; every enabled approach that supports a pair runs. `sandman.yaml` holds only `kindRules` and is not ingested.

Unknown (T2.7a checks them):
- U1. TransArC runs end to end on the tlr-agent classpath without the CoreNLP models jar (finding 9 is static analysis only). Result: pass (T2.7a).
- U2. `COMPONENT_LISTING` with metamodel `ARCHITECTURE_WITH_COMPONENTS` is accepted, and the field order of `Name::Id` is name first. Result: pass; ids equal the second field, type `component`.
- U3. A model from a listing file gives the same TransArC links as the in-memory ExArch model (type `component` versus `Component`, order of components). Result: pass for same names; a PCM gives other links than a names-only listing.
- U4. Key format of `CachedChatLanguageModel` (needed to replay recorded answers into standalone ExArch). Result: key is `messages.toString()` (fragile); tests use an HTTP stub on `OLLAMA_GENERIC` (decision for open question 1).
- U5. Which ExArch variant (documentation only, code only, both with aggregation) and which LLM the ICSA 2025 paper reports as best; paper title, DOI and replication package location and licence. Result: SAD only is best (GPT-4o, weighted F1 0.86); DOI 10.5281/zenodo.14506935 (replication package, MIT). See `docs/notes/spike-T2.7a.md`.
- U6. Cost of one TransArC run per document compared with `ardocode` (F-1), and peak heap on TEAMMATES. Result: TeaStore 15.2 s against 6.5 s, TEAMMATES 115 s against 69 s; peak heap 419/848 MiB against 415/972 MiB.
- U7. ExArch's code variant asks for `CODE_WITH_COMPILATION_UNITS_AND_PACKAGES`, but the runner provides `CODE_WITH_COMPILATION_UNITS`; the code prompt may never run (possible upstream defect, relevant only for open question 2). Result: the informant reads the `CodeModel` and uses `getAllPackages()` for both code features; the code variant was not run and stays out of T2.7.

## Goal

A project without a user architecture model gets a derived, components-only model from its architecture documentation. The derived model is a separate, clearly marked KG artifact with full provenance. TransArC is the default SAD↔code approach and runs on the user model, or on the derived model when no user model exists. A user model that arrives later supersedes the derived model.

## Decisions

1. **ExArch runs as a port in the extraction-agent** (tool `exarch`, version `2.1.0+x1`; raise `+xN` when prompts or parsing change). Port the two documentation prompts verbatim (MIT, with attribution) and the post-processing of finding 6 exactly. Use the existing `LlmClient`, routes and reuse logic of T1.5. Reasons: the extraction-agent owns `Artifact`, `ArtifactVersion` and `Element` (single writer); it already has policy routing, budgets and cassettes; ArDoCo's LLM path is env-only (finding 7, T3.2 decision 2). Rejected: ArDoCo's `ExArch` runner in a Java agent (env-only LLM, a cross-service handoff of the result to the extraction-agent); a Java `ChatModel` adapter as in T3.2 (the informant has no injection point, finding 7).
2. **The derived model is a derived artifact.**
   - Path `.sandman/derived/exarch/<source doc path>.components`; `kind` `architecture-model`; `format` `component-listing`; new property `origin` = `derived` (absent = `user`).
   - Content: one line `Name::Name` per component, sorted, UTF-8, `\n` line ends. ArDoCo reads it with `COMPONENT_LISTING`.
   - The extraction-agent stores the content in the artifact store and writes the version through its own ingestion code. It creates an `Ingestion` with `mode` `partial` and `actor` `system:model-derivation`. Versioning, reactivation (same names = same version id), events, retention and extraction then work unchanged.
   - New `ArtifactVersion` properties: `derivedFrom` (source doc version id) and `derivationRunId`. The derivation `Run` has `USED` → source doc version, plus `model`, `resolvedModel`, `promptIds`, `replayMode` and `configHash`.
3. **Derived `ModelElement`s.** The builtin extractor gets the format `component-listing`: one `ModelElement` per line, `kind` `component`, `name` = name, `localKey` = id (= name, as ExArch), `contentHash` = sha256(name). It sets the new optional property `inferred` = true when the version has `derivedFrom`. No confidence: ExArch gives none, and a made-up value is false precision.
4. **Never confusable.** Intake rejects every manifest path under `.sandman/` (`INVALID_INPUT`), so users cannot write or spoof derived artifacts. A full snapshot never deletes a derived artifact. Console, query service and exports show `inferred` and `origin`. Element keys of derived models never equal user keys (different artifact id).
5. **Trigger.** New skill `derive-architecture-model` of the extraction-agent; input `{projectId}`. The skill is idempotent and decides itself:
   - A current `origin: user` architecture-model exists: mark all current derived artifacts deleted (supersede).
   - No user model: for every current `architecture-doc` version without a current derived artifact `derivedFrom` that version, derive one. Delete derived artifacts whose source doc artifact is deleted.
   - The orchestrator starts the skill on `extraction.completed` when the changed versions contain a `user` doc or model version, and on `ingestion.completed` with `deletedArtifactIds`. Derived versions never start the skill, so no loop exists.
   - Switch: `modelDerivation: { enabled: true, projects: {} }` in `config/orchestrator/rules.yaml` (per-project `{ enabled }` like `retention.projects`). `enabled: false` stops new derivations; existing derived artifacts stay until a user model or a manual run of the skill removes them.
6. **Reuse and reproducibility.** One derivation `Run` per source doc version. `inputKey` = sha256(JCS({input: {projectId, versionId}, tool, configHash, promptIds})). A completed Run with the same `inputKey` and the same route model is reused without an LLM call (T1.5 rule). Thus a reactivated doc version gives the same derived version, also with a live LLM. Record/replay goes through `llm-replay` with a cassette per scenario; CI replays strictly.
7. **Text.** The prompt gets the S3 rendering (`TextUnit` sentences one per line, ADR-0015 R-025 amendment), the same text that TransArC sees. A text longer than `maxInputChars` [120 000] is skipped with a warning; no truncation, because a cut text silently changes the model.
8. **LLM policy.** `cloud-allowed` uses `chat-default`; `local-only` uses `chat-local`. No route or no key for the policy: skip with warning "model derivation skipped: no LLM route for policy"; never fall back to a cloud route. Budget errors fail the Run.
9. **Approach `transarc`** in module `approach-ardoco` (version `2.1.0+a1`, `scopeMode` `whole-project`, `usesLlm` false, no params). `supports` = {architecture-doc → code, architecture-model → code}. One `Transarc` run per (doc version × model version) under `ArdocoRuns.LOCK`. Text as `ardoco` (S3 rendering, `PreprocessingData`, hash check); ACM through `CodeModelClient` as `ardocode`; model file staged from `storageUri` with `PCM`, `UML` or `COMPONENT_LISTING`. Output: `getSadCodeTraceLinks()` as `ardocode` decision 4 maps them (pair doc → code) and `getSamCodeTraceLinks()` (pair model → code, target = file `CodeUnit`). A derived model pairs only with its source doc. Reason for the second pair: a model change must start TransArC again, and the orchestrator only plans steps for configured pairs.
10. **Defaults after T2.7.** `config/tlr/approaches.yaml`: `transarc: { enabled: true }`, `ardocode: { enabled: false }` (opt-in), `ardoco`, `lissa` and `stub-name-match` unchanged. `rules.yaml` gets the pair `{ source: architecture-model, target: code }`. Keep `ardocode` enabled until the T2.7 acceptance criteria pass; switch both in one commit.
11. **SAD↔SAM.** `ardoco` (SWATTR) also reads `COMPONENT_LISTING` and links docs to derived models (only to the model of the same doc). `transarc` does not write SAD↔SAM links, so no duplicate links exist. SWATTR then runs twice per doc (in `ardoco` and inside `transarc`); open question 5 covers that cost.
12. **Inconsistency detection.** `ardoco-id` (T3.1) and `artemis-id` (T3.2) accept `COMPONENT_LISTING` and include derived models (user decision 2). A finding that involves an `inferred` element gets severity `info` at most and `evidence.inferredModel: true`. Reason: a model derived from the same text makes "undocumented model element" mean "LLM hallucination" and "missing model element" mean "LLM miss". When a user model supersedes the derived one, the derived artifact is deleted, and the existing deleted-artifact rule resolves its findings.

## Acceptance criteria

- **Port equivalence (unit vectors).** For a fixed set of LLM answers (dash lines, `Component` suffixes, spaces, blank lines, duplicates, non-dash lines, non-ASCII, names with `::`), the port gives the same sorted name list as `LlmArchitectureProviderInformant` post-processing. The Java side runs in a test of `approach-ardoco` with the recorded answers (mechanism from T2.7a check 4). Names with `::` or a line break are dropped with a warning; the vector set documents this as the only deviation.
- **TransArC equivalence (benchmark profile).** For MediaStore and TeaStore with the PCM model and the T2.6 ACM, `transarc` links equal the standalone `Transarc` runner as (1-based sentence, decoded path) and (model id, decoded path). TEAMMATES, BigBlueButton and JabRef run in the same test (T2.1 exclusion rule for sentence-count mismatches).
- **ExArch end to end.** For MediaStore and TeaStore with the same recorded LLM answers, the derived listing has the same names as standalone `ExArch`, and the `transarc` SAD↔code links on the derived model equal standalone `ExArch`'s SAD↔code links.
- **Lifecycle** (Testcontainers Memgraph, MediaStore doc and ACM, replay cassette): (a) doc only: one derived artifact, `origin: derived`, `inferred` elements, `derivedFrom` and `derivationRunId` set, `transarc` and `ardoco` links present; (b) doc v2: new derived version, old one not current; (c) doc v1 again: the first derived version is reactivated without an LLM call; (d) user PCM model: derived artifact deleted, links via the derived model retired after the `transarc` run, its findings resolved; (e) user model deleted: derived artifact current again, no LLM call. After each step no active link has an endpoint outside the current versions.
- `local-only` project without `chat-local`: no derivation, one warning, no cloud request (stub gateway counts requests). Intake of a `.sandman/…` path fails with `INVALID_INPUT`. A full snapshot keeps the derived artifact.
- **Metrics report** (T2.3 harness, all benchmark projects): SAD↔code precision, recall and F1 for `ardocode`, `transarc` with the gold SAM, and `transarc` with the derived SAM (replay). The report flags it for the user if `transarc` with the derived SAM is more than 0.05 macro F1 below `ardocode`; the default switch (decision 10) stays the user's decision.
- **Cost:** `make perf` reports `transarc` seconds per doc next to F-1. The ingest-tlr budget result is recorded; T2.7 does not need to meet it (F-1 owns that).
- `make e2e`, `replay-twice` and CI green. The golden diff lists only the new Runs, links and the derived artifact of the new no-model scenario, plus `stub-name-match` links of the new pair model → code.

## Security

- **Untrusted documentation.** The SAD enters the prompt as data. Prompt injection can only change the returned names. Parse only `- name` lines. Drop names longer than `maxNameLength` [80], names with control characters, `::` or line breaks, and all names after `maxComponents` [100]; log each drop. Names go to Cypher only as parameters and to later prompts only as quoted data (T4.4 rules apply).
- **Spoofing.** The reserved prefix `.sandman/` is rejected at intake (decision 4). Only the extraction-agent sets `origin` and `derivedFrom`.
- **Data protection.** `local-only` projects never reach a cloud route (decision 8). No `.env`, `LLM_CACHE_DIR` or provider key in any agent (T3.2 constraint).
- **Cost.** `maxInputChars`, the LLM budget of T1.5 and Run reuse limit spending; one derivation per doc version.

## Risks

- R1. LLM output varies between models and runs; derived models differ between deployments. Mitigation: Run reuse, replay in CI, `resolvedModel` on the Run.
- R2. Derived models are components only; ArDoCo detectors may report noise (decision 12 caps severity).
- R3. Finding 9 is static; if TransArC needs CoreNLP models after all, T2.7a stops and the user decides (provider lemmas upstream, or keep `ardocode` as default).
- R4. Cost: `transarc` adds SWATTR and ArCoTL per doc on top of `ardoco` (F-1). If the ingest-tlr budget gets worse, open question 5 applies.
- R5. Small local models (`chat-local` = qwen3:4b) may give poor component names; quality for `local-only` is not measured by the paper.

## Constraints

Contract changes in one additive PR first. Python port without new dependencies; Java side without new dependencies. Do not change ArDoCo. No LangChain4j outside `approach-ardoco` and `detector-ardoco` (R-030). Prompt text verbatim from `LlmArchitecturePrompt` 2.1.0 with MIT attribution. Keep a handoff note `.work/T2.7.md` (CLAUDE.local.md).
