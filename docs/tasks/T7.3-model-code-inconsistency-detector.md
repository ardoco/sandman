## Context

Sandman detects documentation–model inconsistencies (`ardoco-id`, `artemis-id`) and untraced requirements (`stub-untraced`). It does not detect a mismatch between the architecture model and the code. Stage 1 Q-6 puts "model element without code" in scope for rule-based detection. LLM documentation–code contradictions come later.

The paper names documented-versus-implemented mismatches as a consistency problem (paper §3.3, p. 489). See `docs/notes/paper-review-3774748.3795871.md` §3.7 (gaps #12, #16).

The data for the rule exists. The approach `transarc` (T2.7) writes SAM→code links: source `ModelElement`, target `CodeUnit` of kind `file`, link type `implements`, confidence 1.0 (`TransarcApproach.samToLinks`). Users can add more links with T7.2.

Facts from the code:
- `transarc` needs an architecture document and a model. A project without a document gets no SAM→code links.
- Code elements come from `code-extractor-ardoco`: `CodeUnit` kinds `file`, `type`, `method`. Each code file is one artifact. Its file element has `localKey` = the ACM path (T2.6 key table). Types have `CONTAINS` parents. No package elements exist.
- Detectors ignore rejected links. `ArdocoIdDetector` caps the severity at `info` for `inferred` model elements and puts `inferredModel` in the evidence.
- The ArDoCo benchmark has `goldstandard_sam_<y>-code_<y>.csv` per project. T2.3 left it out, because SAM↔code was not a Sandman link type then.

## Goal

A rule-based detector `model-code` reports architecture components without linked code and code files without a linked component. A removal-protocol evaluation on the ArDoCo benchmarks measures precision, recall and F1 per finding type before the detector is enabled by default.

## Scope

In:
1. Detector `model-code` in `services/inconsistency-agent` (in-process, Java SPI, no ArDoCo dependency).
2. Finding types `model-element-without-code` and `code-without-model-element`.
3. Config entry in `config/inconsistency/plugins.yaml`.
4. Removal-protocol evaluation with a CLI command and a results section in this spec.
5. Format `ardoco-sam-code` in `tools/cli/src/sandman_cli/evaluation/formats.py` to read the SAM↔code gold standard.
6. Doc update: `docs/plugins.md` and `docs/user/trace-links-and-findings.md`.

Out:
- LLM documentation–code contradictions (Q-6). Backlog item, separate task after M7 (open question 5).
- Model–code mismatch at type or method level.
- Interface and connector consistency (a model interface without a code interface).
- Dependency consistency (model connector against code `DEPENDS_ON`).
- New TLR approaches. The detector uses existing links.

## Contract changes

None. Finding types are free strings. The detector uses the existing SPI, KG labels and link types. The new CLI evaluation format is not a contract.

## Behavior

### Detector `model-code`

- Class `ModelCodeDetector` in package `edu.kit.kastel.mcse.ardoco.sandman.inconsistency`. Register it in `services/inconsistency-agent/src/main/resources/META-INF/services/edu.kit.kastel.mcse.ardoco.sandman.inconsistency.InconsistencyDetector`.
- `id` = `model-code`. `version` = `1`. `scopeMode` = `WHOLE_PROJECT`. `usesLlm` = false.
- `paramKeys`, with defaults:
  - `modelKinds`: `[architecture-model]` (artifact kinds)
  - `codeKinds`: `[code]` (artifact kinds; `test` is not in the default)
  - `modelElementKinds`: `[component]`
  - `codeElementKinds`: `[file]`
  - `excludeGlobs`: `["**/package-info.java", "**/module-info.java"]` (on the code file path)
  - `linkApproaches`: `all`, or a list of approach ids
  - `maxFindingsPerType`: `500`

A **model–code link** is an active `TraceLink` with `status <> 'rejected'`, in either direction, between a current `ModelElement` and a current `CodeUnit`, from an approach in `linkApproaches`. A link to a `type` or `method` counts for its file: follow `CONTAINS` up to the file.

Rules:
1. **Guard.** If the project has no model–code link at all, return no findings and the detector warning `model-code: no model-code links; enable transarc or declare links (T7.2)`. Without links, every component would be a finding.
2. **`model-element-without-code`.** A current `ModelElement` with a kind in `modelElementKinds`, in an artifact with a kind in `modelKinds`, without a model–code link. Involved: the model element, role `subject`. Severity `warning`; `info` when `inferred` is true. Evidence: `inferredModel` (boolean), `linkApproaches`.
3. **`code-without-model-element`.** A current `CodeUnit` with a kind in `codeElementKinds`, in an artifact with a kind in `codeKinds`, whose path matches no `excludeGlobs`, without a model–code link. Involved: the code unit, role `subject`. Severity `info`. Evidence: `path`.
4. **Cap.** Sort the findings of each type by key. Keep the first `maxFindingsPerType`. If findings were cut, add the warning `model-code: <type> capped at <n> of <total>`.
5. Titles: `Model element without code: <name>` and `Code without model element: <path>`, cut to 200 characters.

Run all reads in one read call per rule with `projectId` in every `MATCH` (RK-10). Follow the query style of `StubUntracedDetector`.

### Config

Add to `config/inconsistency/plugins.yaml`:

```yaml
model-code: { enabled: false, params: { modelKinds: [architecture-model], codeKinds: [code], linkApproaches: all } }   # T7.3
```

Set `enabled: true` only after the evaluation meets the gate (decision D-4).

### Removal-protocol evaluation

Benchmarks: MediaStore, TeaStore, TEAMMATES, BigBlueButton, JabRef. Use the pinned code commits of T2.6 and the gold standards of T2.3 (`ArDoCo/Benchmark` `e60ddb2`).

Gold mapping: `goldstandard_sam_<y>-code_<y>.csv` gives pairs (component id, code path). Let `F(c)` be the files of component `c`.

Runs per project:
1. **Baseline.** Ingest the unchanged project. Run TLR (`transarc`) and `model-code`. Record the findings.
2. **Code removal.** For each gold component `c`: remove all files `F(c)` from the snapshot. Expected finding: `model-element-without-code` for `c`.
3. **Model removal.** For each gold component `c`: remove `c` from the model file. Expected findings: `code-without-model-element` for each file of `F(c)` that no other gold component maps.

Counting per run, per type:
- true positive: an expected finding is reported
- false negative: an expected finding is missing
- false positive: a reported finding that is not expected and not in the baseline
- Report precision, recall and F1 per type, micro-averaged over all runs of a project, with bootstrap CIs from `stats.py`.
- Also report the baseline agreement: baseline `code-without-model-element` findings against files in no gold pair, and baseline `model-element-without-code` findings against components with no gold pair.

Execution modes:
- **Simulated (all removals).** Record the baseline `transarc` links once as CSV (format `ardoco-sam-code`, as T3.3 did for `ardoco`). For a removal, drop the removed files or component and their links from the recorded set. Run the detector rules on the result. This needs no new TLR run.
- **Full (sample).** For 3 removals per project and type (seeded choice), ingest the changed snapshot and run `transarc` again. Compare with the simulated result. Report the agreement. A difference shows that `transarc` relinks files to other components after a removal.

Tooling: `sandman eval removal --project <name> --mode simulated|full --seed 42 --out experiments/removal/<project>.json`. Put the logic in `tools/cli/src/sandman_cli/evaluation/removal.py`. Model removal deletes the component element with its id from the PCM repository or UML file (`defusedxml` parse, ElementTree write). Pre-register the protocol in `experiments/PROTOCOL.md` before the first run (plan §3.3).

## Decisions taken

| Id | Question | Decision |
|---|---|---|
| D-1 | Plugin, ArDoCo module or core? | Core module of the inconsistency-agent, like `stub-untraced`. The rule is pure Cypher and needs no ArDoCo class (R-030 stays untouched). |
| D-2 | Which links count? | All active non-rejected model–code links of the approaches in `linkApproaches`, in either direction. `transarc` is the main source; `user-declared` (T7.2) links count too. |
| D-3 | Severity | `model-element-without-code`: `warning`, `info` for inferred models (T3.1 rule). `code-without-model-element`: `info`, because models abstract and do not cover all code. |
| D-4 | Enable by default? | No, until the evaluation gate holds: micro F1 at least 0.7 for `model-element-without-code` on at least 3 of 5 projects (simulated mode), and simulated–full agreement at least 0.8. `code-without-model-element` stays `info` in every case. |
| D-5 | LLM | None. Q-6 LLM contradictions are a later task (PR-D9: LLM features are off by default). |

## Acceptance criteria

1. Unit tests on a fixed graph:
   - a component with an active `transarc` link to a file: no finding
   - a component whose only link is rejected: `model-element-without-code`
   - a link to a `type` inside the file counts for the file
   - an inferred component: severity `info`, evidence `inferredModel: true`
   - a file that matches `excludeGlobs`: no finding
   - a file in a `test` artifact with default params: no finding
   - no model–code link in the project: no finding, one warning
   - cap: 3 findings with `maxFindingsPerType: 2` give 2 findings and one warning
2. Two runs on the same graph give the same fingerprints.
3. A rejected link (T6.1 review) creates the finding in the next detection, and a new link auto-resolves it (T0.7 lifecycle).
4. `DetectorRegistry` loads `model-code` and validates its params.
5. The evaluation runs on all five benchmarks in simulated mode and on the sample in full mode. Results with CIs and the agreement are in this spec.
6. `enabled` in `config/inconsistency/plugins.yaml` follows the gate of D-4.
7. `make e2e` stays green. The replay determinism test (T1.6) stays green.

## Test plan

- Unit (Python, CLI): `ardoco-sam-code` reader; simulated removal on a fixture with expected counts.

## Risks

- RK-3: gold component ids and file paths must map to KG keys. Use the model id (`ModelElement.localKey`) and the file path relative to the code root, as T2.3 does. Report the mapping rate per project.
- RK-15: the gold standard comes from the same benchmarks that tuned ArDoCo. Report the results as reproduction, not as generalization. Pre-register the protocol.
- RK-11: `code-without-model-element` can produce one finding per file in large projects. Mitigation: severity `info`, `maxFindingsPerType`, detector disabled by default.
- S-5 (new): the detector depends on `transarc` link quality. A missed link gives a false `model-element-without-code`. Mitigation: links of all approaches count; users add links with T7.2 or confirm links with T6.1.
- S-6 (new): projects without an architecture document get no `transarc` links. The guard reports a warning instead of noise.

## Constraints

Shared constraints of plan §5 apply. No new dependency in the inconsistency-agent. Do not change the detector SPI. Keep a handoff note `.work/T7.3-impl.md`.

### Gate (D-4)

- F1 of `model-element-without-code` (simulated) is at least 0.7 on 4 of 5 projects. BigBlueButton fails with 0.62. Criterion met (needs 3).
- Pooled agreement is 1817 of 1919 expected findings, 0.947. Criterion met (needs 0.8).
- Per-project agreement is 0.78, 0.67, 1.00, 0.53 and 0.95. The pooled value is dominated by JabRef (1689 of 1919 findings). The mean over projects is 0.79.
- Decision: `enabled: true` in `config/inconsistency/plugins.yaml`, by the literal pooled reading of the protocol.
- User decision 2026-10-20: keep `enabled: true`, with the per-project agreement and the BigBlueButton F1 of 0.62 known.
- Caution: full mode loses recall because `transarc` relinks or misses links after a removal. Treat `model-element-without-code` findings in BigBlueButton as low recall.
- Limit: gold standard and `transarc` come from the same benchmarks (RK-15). The numbers are reproduction.
